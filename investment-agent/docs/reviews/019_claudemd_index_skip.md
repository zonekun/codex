## 事象

**CLAUDE.mdの「タスク別の必読ファイル」索引を最初に参照しなかった。**

CLAUDE.md索引には以下のエントリが明記されている:
> | EDINET遅延報告TOBスクリーニング | `docs/knowledges/analysis/008_edinet_delay_tob_screening.md` |

## 既存のフィードバック

`feedback_claudemd_index_first.md` に同種のルールが既に記録済み:
> ツール系タスク実行前にCLAUDE.md索引→該当knowledge MDを必ず読む。パス規約を推測しない

今回は「タスク実行」ではなく「情報探索」の場面だったが、同じ原則が適用される。

## 再発防止

既存フィードバックの適用範囲を拡大認識する:
- タスク実行時だけでなく、**ユーザーが既存機能・ツールについて言及した場合**もCLAUDE.md索引を最初に確認する
- memory/glob/grepによる探索はCLAUDE.md索引で見つからなかった場合のフォールバック

## 【パターン 2 のみ: 誤読・ミス原因分析】

### 事象
ユーザーが「tob関連 もう一つツール開発中あったはず」と質問。AIは CLAUDE.md 索引を参照せず、memory 確認 -> glob -> ユーザーへの候補提示 -> 再質問 -> 知見MD読み込みという多段探索を行い、特定に不要な往復が発生した。CLAUDE.md 索引で「TOB」を検索すれば、L350（EDINET遅延報告TOBスクリーニング）と L406（TOB ML予測モデル）が即座にヒットし、1往復で完了した。

### 読み手がどう解釈した可能性があるか
1. 「タスク別の必読ファイル」テーブルは**タスクを実行する前に読むべきファイルの一覧**であり、ユーザーの質問に答えるための索引ではない、と解釈した可能性がある
2. feedback memory の「ツール系タスク実行前に」が適用条件として読まれ、今回のような「質問への回答」は適用外と判断された可能性がある
3. L322「新しいタスクを受けたら `docs/knowledges/` 内を優先スキャンして」の「優先スキャン」を glob/grep による探索と解釈し、索引テーブルのルックアップではなくファイルシステムの探索を選択した可能性がある

### 直接原因
- CLAUDE.md 索引テーブルの**用途が「タスク実行前の必読指定」に限定的に記述**されており、「ユーザーの質問・探索依頼に対する索引引き」という用途が明記されていない
- feedback memory の適用条件が「ツール系タスク実行前」に限定されている

### 根本原因
- CLAUDE.md 索引テーブルは本来「このプロジェクトで扱うツール・機能・分析の正式な索引」であり、タスク実行前だけでなく、あらゆる場面でプロジェクト内の知見を特定する最初のルックアップ先であるべき。しかし、見出し・導入文・feedback memory のいずれもこの汎用的用途を表現していない
- feedback memory `feedback_claudemd_index_first.md` が 2026-04-15 の特定事故（Dropbox保存先パス推測）を元に書かれたため、「実行前の規約確認」という限定的なスコープになっている。事故からの教訓が特殊化されすぎて、汎用原則に昇華されていない

### 誤読を許した MD 上の原因
1. **CLAUDE.md L322**: 「新しいタスクを受けたら」-- 「タスク」が質問・探索を含むかが不明確
2. **CLAUDE.md L324**: 見出し「タスク別の必読ファイル」-- 「必読」が「実行前に読む」に限定的に読める。索引・ルックアップ用途が見出しに表れていない
3. **feedback_claudemd_index_first.md L7**: 「ツール系タスク（Dropbox/GCS/BQ/外部API/スクリプト呼び出し等）を実行する前に」-- 適用条件が「実行する前」に限定
4. **CLAUDE.md テーブルの「タスク」列**: 全エントリが動作動詞形式（「〜を取得」「〜を改修」「〜を確認」）。「〜について聞かれた」「〜に関連する情報を探す」形式のエントリが不在

### 再発防止の方向性
1. **CLAUDE.md L322 の文言拡張**: 「新しいタスクを受けたら」を「新しいタスクを受けたら、またはユーザーが既存機能・ツール・分析について言及・質問したら」に拡張
2. **feedback memory の適用範囲拡張**: 「ツール系タスク実行前」を「ツール系タスク実行前、およびユーザーがプロジェクト内の既存機能・ツールについて質問・言及した場合」に拡張
3. **MD構造の改善は不要**: 索引テーブル自体の構造は問題ない。導入文の1箇所と feedback の1箇所を修正すれば十分
