## 【パターン 2 誤読・ミス原因分析】

### 事象

テストスクリプト `test_yutai_nav.py` を `C:\tmp\` に配置した。ユーザーが即座に指摘し修正された。

### 読み手（AI）の解釈

「テスト」→「一時的」→「テンポラリディレクトリ」という意味的連想が作用。CLAUDE.md の「ローカルDL保存先: `C:\tmp\`」が「ローカル作業全般の場所」と拡大解釈された可能性。

### 直接原因

004_coding_conventions.md を参照せずに Write を実行した（CLAUDE.md L290 違反）。

### 根本原因

CLAUDE.md L290 のトリガー条件が **「`scripts/` 配下に新規 .py ファイルを作成する場合」** に限定されている。AIが `scripts/` 以外にスクリプトを書こうとした場合、このルールは発火しない。本事故はまさにその盲点を突いたケース。

### MD上の原因

- `CLAUDE.md:290` — トリガー条件の範囲が狭い。「新規 .py スクリプトを作成する場合」とすべきところ「`scripts/` 配下に」と限定している
- `CLAUDE.md:78` — `C:\tmp\` の用途が「ローカルDL保存先」と書かれているが、「スクリプト配置禁止」とは明記されていない。DL先とスクリプト配置先の区別がAIにとって自明でない可能性がある
- `docs/knowledges/tools/004_coding_conventions.md` — テストスクリプト（`test_*.py`）の配置先ルールが明文化されていない。一時スクリプトは `tmp_*.py` で `scripts/` 配下と明記されているが、テストスクリプトの配置先は既存ファイルからの推論に依存

### MD構成原因

- CLAUDE.md L290 のルールが「`scripts/` 配下に書くと決まった後」のチェックリスト参照を強制する設計であり、「どこに書くか」の判断を制御する上位ルールが不在
- 004_coding_conventions.md の命名規則セクション（§一時スクリプト、§共通ライブラリ）にはテストスクリプトの項がない

### 対策スコープ

個別MD固有のfixではなく、CLAUDE.md レベルでのトリガー条件拡張が必要。
