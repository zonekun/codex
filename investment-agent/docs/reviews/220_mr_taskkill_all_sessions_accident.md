**どのルールを参照/未参照だったか**:

### 2. 直接原因

| 不備 | 場所 | 内容 |
|------|------|------|
| A. 破壊的操作定義にプロセス操作が含まれない | `004_coding_conventions.md §破壊的操作` | 定義リストに `taskkill /IM`（全プロセスkill）が含まれない。AI は破壊的操作チェックをスキップした |
| B. 他セッション影響確認のトリガーが存在しない | CLAUDE.md §4.4 | §4.4 の「他者影響がある操作」が「他セッション」まで拡張されていない。確認義務の発火条件として認識されなかった |
| C. 「このプロセスだけ」という確認なしに /IM を使った | 行動側 | `/F /IM` がスコープ全体kill であることの説明なし。PIDによる特定プロセスkillという代替を検討しなかった |

### 3. 根本原因

- 破壊的操作ルール（004/CLAUDE.md §4.4）は「ファイル操作・DB・Git・GCPリソース・外部送信」を列挙しているが、**ローカルプロセス操作（taskkill等）が対象外**のまま放置されていた
- 理由: これまでプロセス操作が問題になる事故が発生しておらず、ルールに追加する契機がなかった
- 結果: AIはプロセス操作を「安全な補助操作」と分類し、破壊的操作チェックを適用しなかった

### 4-1. MD上の原因

**004_coding_conventions.md §破壊的操作**（L208-218）

```
- 上書き・削除: 既存 blob/ファイルへの書き込み、blob.delete(), rm -rf ...
- DB 破壊系 DML: DROP, TRUNCATE, 広範囲 DELETE ...
- Git 破壊系: push --force, reset --hard ...
- 他者に見える変更: PR/Issue/Slack/email/LINE 送信、Cloud Run/Workflows 実行
- bucket/quota 系: gsutil rsync -d, jobs delete, secrets 削除
- 副作用のあるスクリプトを | head 等のパイプで部分確認しない
```

→ **`taskkill /IM`（同名プロセス全体kill）が列挙に存在しない**。AIはこのリストを参照して「プロセスkillは破壊的操作に該当しない」と判断した可能性が高い。

**CLAUDE.md §4.4（L79-80）**

```
dry-run → 小範囲10件確認 → 全件展開。全件一発実行禁止。承認された範囲のみ。
```

→ 「承認された範囲のみ」という記述はあるが、ユーザーが「A」と答えた時点でClaudeが「承認された範囲 = 現セッションのみ」と勝手に解釈した。**ユーザーは `/IM` の全プロセスkillを知らない状態で「A」を選んだ**。インフォームドコンセント（操作スコープの明示）がなかった。

### 4-2. MD構成原因

- CLAUDE.md §4.4 の破壊的操作定義と 004_coding_conventions.md §破壊的操作の記述が分離しており、004側に詳細が移譲されているが、プロセス操作の追記がどちらにも行われていなかった
- 「他者影響」の概念が §4.4 では外部サービス（LINE/Cloud Run等）に限定されており、ローカルプロセスの「他セッション影響」に射程が及んでいなかった

### 5. 再発防止

**推奨①（最優先）: 004_coding_conventions.md §破壊的操作 にプロセス操作を追加**

```markdown
- **プロセス操作**: `taskkill /IM`（全同名プロセスkill）、`Stop-Process -Name`。
  必ず `/PID <pid>` で対象を特定してから実行。`/IM` `/Name` による全プロセスkillは
  他セッション影響確認なしに提案・実行禁止
```

**推奨②: CLAUDE.md §4.4 に「プロセス操作の確認義務」ポインタを追加**

既存原則「他者に見える変更」の例示に追記:
```markdown
- **プロセス操作**: `taskkill /IM` 等の全プロセスkill → 004_coding_conventions.md §破壊的操作参照
```

**推奨③: 選択肢提示時の「影響スコープ明示」を行動ルール化**

選択肢に操作コマンドを含む場合、以下を必ず付記:
- そのコマンドが影響するスコープ（PIDのみ or 全同名プロセス等）
- 他セッションが存在する場合の影響

永続化先: `004_coding_conventions.md §破壊的操作`（1行で追記）

### 6. 新規リスク

推奨①を実施した場合の副作用シミュレーション:
- `/IM` `/Name` 指定を一律禁止にすると、意図的に全プロセスkillしたい正当ユースケース（例: 暴走した全ソルジャーの一括kill）が阻害される
- 対策: 「確認なしに」という条件付きにする（ユーザーがスコープを明示的に承認した場合は許可）
