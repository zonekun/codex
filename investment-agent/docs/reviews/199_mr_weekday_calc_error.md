## 【パターン 2/4: 原因分析】

### 事象

バックフィル完了ログの `2026-05-16: 0件取得` を説明する際、「金曜だが確報なし」と出力した。実際には2026-05-16は土曜日であり、ユーザーが即座に訂正した。

### AIの思考回路（推定）

1. バックフィルジョブの完了ログを確認し、説明文を生成する文脈にあった
2. `0件取得` という結果に対して「なぜ0件か」を説明しようとした（ユーザーへの配慮行動）
3. 説明候補: 「土曜/日曜（市場休場）」「J-Quants未公開」「祝日」の中から曜日情報が必要と判断
4. **CLAUDE.md §4.1「日付属性はpython/dateで確認」を参照せずに**、内部の「2026-05-17が何曜か」という文脈知識から逆算しようとした
5. 逆算誤り（または知識誤り）により「金曜」と断定してテキスト出力した

**なぜ確認しなかったか**: 「曜日を添える」という動作は「説明の付加」であり、「報告」の一部として認識されにくい。CLAUDE.md §4.1 の「確認優先」は「データ属性・BQ値・日付時刻」を明示しているが、「説明文中に添えるカレンダー情報」がそのスコープと明示されていないため、ルールが発火しなかった可能性が高い。

### 直接原因

1. **行動上の直接原因**: 「曜日」という日付属性を `python/date` で確認せず、暗算・推論で断定して出力した。CLAUDE.md §4.1 違反
2. **ルール発火の直接原因**: 「曜日」が「日付属性」の具体例として列挙されていない。「日付属性」の定義が抽象的なため、「カレンダー知識で答えられる」と判断されルールが未発火のまま通過した

### 根本原因

`CLAUDE.md §4.1` の「日付属性はpython/dateで確認」という規定が:
- 「日付属性」の定義を具体例で示していない（曜日・営業日判定・祝日該当が含まれるかが不明確）
- 「データ値の確認」文脈では発火するが「説明文付加」文脈では発火しにくい（トリガー範囲が狭い）
- 詳細は `004_coding_conventions.md §日付時刻ルール` に委譲されているが、同セクション（L252-260）はコード上の実装規約であり「説明文中の曜日記述」への適用が明示されていない

### MD上の原因

`CLAUDE.md §4.1`（L47）:
```

```

この1行の問題点:
- 「日付属性」の具体例（曜日・営業日・祝日・経過日数等）が列挙されていない
- 「データから読む」場合と「説明文として付加する」場合の両方にルールが適用されることが明示されていない
- ポインタ先の `004_coding_conventions.md §日付時刻ルール` はJST/UTC変換に特化しており、「曜日計算の禁止」は記載されていない

### 再発防止（推奨）

## 【重大な指摘】

### [重大-1] 「日付属性」の定義に曜日・営業日が含まれることが不明確

- **箇所**: `docs/knowledges/tools/004_coding_conventions.md` §日付時刻ルール L258
- **問題**: 「MD記述時」の確認義務が「プランMD・知見MD・レビューMD等への記載時」に限定されている。「会話出力に曜日を添える」場面が射程外に読める
- **誤読パターン**: 「会話内の説明文は報告であってMDではない → §日付時刻ルールは適用外 → 知識から回答してよい」
- **トリガー条件**: ジョブ完了報告・ログ説明・データ解釈など、曜日情報を「補足説明」として付加する場面
- **影響**: ユーザーへの誤情報提供。特に「0件=休場」の判断根拠として曜日が使われる場合、誤った休場判定を引き起こす可能性
- **根拠**: `004_coding_conventions.md` L258「MD記述時」の限定文言、および今回事故の再現手順4
- **推奨対応**: `004_coding_conventions.md §日付時刻ルール` に「曜日・営業日・祝日判定も日付属性に含まれ、会話出力含む全ての文脈で python/date 確認必須」の1行を追記
- **MD修正で足りるか**: Yes。コード側の変更不要

### [重大-2] 再発防止策が意志依存型のみ

- **箇所**: 提出MD「再現手順3」「補足情報」
- **問題**: 「コマンドを実行せず」という行動事実の記述はあるが、「次回はコマンドを実行する」という意志依存型の記述にとどまる。強制発火機構がない
- **誤読パターン**: 「記録した → 次回から気をつける → 対策完了」という短絡的完了判断
- **トリガー条件**: 同種の「説明文中に曜日を添えようとする」場面で、再度同じ省略が起きる
- **影響**: 再発。同種エラーが別日付・別銘柄で繰り返される
- **根拠**: `md-reviewer.md` §Step 8c(iv)「意志依存型か判定。意志依存型なら強制発火の代替案を併記」
- **推奨対応**: 004への追記（重大-1と統合）によりルール文書として記録することが現実的な強制手段。hookによる自動検知は曜日発言の文脈検知が困難なため、ルール明文化を優先する
- **MD修正で足りるか**: Yes（hook不要、004追記で対応）
