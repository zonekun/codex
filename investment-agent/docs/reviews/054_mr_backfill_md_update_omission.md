# MR-054: バックフィル完了時のプランMD更新漏れ

**日時**: 2026-05-01 22:08 JST
**重大度**: 中（ユーザー指摘で発覚）
**カテゴリ**: 知見ファイル整合義務違反
**先行事故**: MR-041（コンセMD更新漏れ、2026-04-30）と構造的に同一パターン

## 事象

2019-H1バックフィル全完了時、087メトリクスファイルは更新・コミットしたが、バックフィル計画MD（`docs/plans/20260427_140000_tdnet_2017_2022_backfill.md`）のステータス・BQテーブルを更新しなかった。ユーザーに「MDファイル更新したか」と指摘されて初めて対応。

## 原因

### 直接原因
- 087メトリクス記録は memory のフィードバック（`feedback_backfill_metrics_auto.md`）で自動化されていたが、プランMDの進捗更新は同feedbackの射程外だった
- プランMD自体の「後片付け」チェックリスト（L419-425）に `[ ] 本プランのステータスを ✅ 完了 に更新` が記載済みだったが、完了時にこのセクションを確認するフローが確立されていなかった

### 根本原因
- MR-041（コンセMD更新漏れ）と構造的に同一パターンの再発事故。041の再発防止として追加された CLAUDE.md §知見ファイル整合義務の発火条件が「既存スクリプトの動作変更」に限定されており、「プランに紐づく作業の進捗変化」をカバーしていなかった
- バックフィル完了時の更新義務が「087メトリクス」（memory feedback）と「プランMDステータス」（プランMD末尾チェックリスト）に分散しており、一方だけ実行して他方を忘れる構造

## 再発防止

### 永続化先
1. **CLAUDE.md §知見ファイル整合義務**: 発火条件を「スクリプト変更」→「スクリプト変更 or マイルストーン完了」に拡張
2. **memory `feedback_backfill_metrics_auto.md`**: プランMD更新義務を追記
3. **memory `feedback_proactive_plan_md_update.md`**: 新規作成済み（4点セットチェックリスト）

### チェックリスト（バックフィル各H完了時）
1. 087メトリクスファイルに実測値記録
2. **対応するプランMDのステータス・進捗テーブルを更新**
3. **プランMDの後片付けチェックリストを確認**
4. memory の関連エントリを更新
5. コミット

「指示を受けないと更新しない」は知見ファイル整合義務違反。
