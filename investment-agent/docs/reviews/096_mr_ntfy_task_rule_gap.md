## 【パターン 2: 誤読・ミス原因分析】

### 1. 事象

セッション 2ff782ef で全ntfy送信に `--task` が省略され、通知タイトルが「ATP」のみ。ユーザーのスマホ通知一覧で作業名が判別不能に。

### 2. 読み手の解釈

AIは CLAUDE.md L341（修正前）の `--sender ATP` 必須ルールに従い `--sender ATP` は付けた。`--task` の記載がなかったため、省略可能と判断。068 L200 も「省略時はsenderのみ表示」と補強し、省略の正当性を裏付けた。

### 3. 直接原因

**CLAUDE.md §用語・解釈ルール の修正前 L341 に `--task` の必須記載がなかった**。AIが ntfy 送信コマンドを組み立てる際、CLAUDE.md の該当行をトリガーとして `--sender` のみ付与。`--task` の存在自体は068に記載されていたが、「省略時は〜」の記述から任意パラメータと解釈。

### 4. 根本原因

`--task` パラメータは `--sender` と同時に notify.py に追加されたが（コード上は L427-430 で同列）、CLAUDE.md への必須ルール反映が `--sender` のみに留まった。068 知見ファイルでも `--sender` は見出しレベルの必須ルール（L194）だが、`--task` は箇条書き内の補足（L200）に留まり、非対称な扱いが残った。

### 4-1. MD 上の原因

- **CLAUDE.md（修正前）L341**: `--sender ATP` のみ明記。`--task` 未記載
- **068 L194**: 見出し「必須ルール: `--sender` は毎回付ける」が `--task` を含まない
- **068 L200**: 「省略時はsenderのみ表示」が省略を許容する表現

### 4-2. MD 構成原因

- CLAUDE.md → 068 のリファレンスは適切に張られている（CLAUDE.md L340「詳細は `docs/knowledges/tools/068_line_ntfy_push.md`」）
- しかし CLAUDE.md が正本として `--task` 必須を宣言しても、068 側で省略可と読める記述が残っていれば、068 を読んだAIは省略可と判断し得る。正本と詳細リファレンスの間で必須性の一貫性が欠けていた

### 5. 再発防止の方向性

1. **068 L194 見出し修正**: `--sender` と `--task` の両方を必須として見出しに含める
2. **068 L200 表現修正**: 「省略時は〜」の省略許容表現を削除し、「必須」と明記
3. **コード側バリデーション**: notify.py で `--sender` 指定時に `--task` が未指定ならwarning or errorを出す（構造的強制）

### 6. 対策スコープ

- 068 の修正は対象MD固有の fix
- CLAUDE.md L341 は既に修正済み（汎用ルール層での対策完了）
- コード側バリデーションは汎用的な再発防止策
