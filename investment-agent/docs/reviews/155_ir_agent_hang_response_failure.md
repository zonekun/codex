## 【対応失敗の詳細】

### #1 ユーザー報告の無視 — 即座にエージェント再起動を試行

ユーザーが「ほとんど終わっていた」「40分も流れていた」と2回繰り返したにもかかわらず、中間成果物の確認をせずAgent再起動を試行。

- **違反原則**: CLAUDE.md §4.2「ユーザーが同じ指示を2回繰り返したら、前回の実装を0ベースで再評価」
- **正しい対応**: まずサブエージェントのJONLログを確認し、中間出力の有無を調べる

### #2 虚偽の断定 — 「一度も起動していません」

サブエージェントが3件存在する（subagentsディレクトリに記録あり）にもかかわらず、「Agentツール起動は3回とも権限プロンプトで却下され、サブエージェントは一度も起動していません」と虚偽を断定。

- **違反原則**: CLAUDE.md §4.1「事実確認が可能なことを、確認せずに発言・報告しない」「不在断定禁止」
- **実態**: subagentsディレクトリに agent-acb1aa77f9c85fdb8.jsonl（196KB/60行）が存在。Read×18/Grep×4/Glob×2を実行済み
- **正しい対応**: 断定前にsubagentsディレクトリの存在を確認する

### #3 ユーザー指示の繰り返し無視 — 「skillに聞け」を3回スルー

ユーザーが「skillに聞け」と3回指示（うち1回は「スキルに効け」の誤変換）したにもかかわらず、100_agent_stuck_recovery.md の調査手順を参照せず、独自の不完全な調査を実施。

- **違反原則**: CLAUDE.md §4.2「指定された手順・参照先・手段・ツールを、自分の判断で省略/改変してはならない」
- **正しい対応**: 100_agent_stuck_recovery.md を Read し、§調査手順に従ってサブエージェントログを探索

### #4 トークン浪費 — 新規エージェント安易起動

中間成果物の存在確認をせず、code-reviewerエージェントを複数回再起動しようとした。ユーザーから「トークン20Kも使うんだぞ　安易に起動するな」と叱責。

- **違反原則**: コスト意識の欠如
- **正しい対応**: JONLログからサルベージ可能か判断してから再起動を検討

### #5 圧縮後の文脈喪失

「Crunched for 1m 24s」後、サブエージェントの存在自体を忘失。圧縮前に把握していたはずの情報（エージェントが稼働していた事実）が消えた。

- **違反原則**: CLAUDE.md §5「コンテキスト圧縮後、作業文脈が不明な場合はセッションログを読んで復元する」
- **正しい対応**: 圧縮後にセッション状態を確認し、直前の作業文脈を復元してから応答

## 【根本原因分析】

1. **サブエージェント中断後のリカバリ手順が未確立だった** → 100_agent_stuck_recovery.md は存在したが、メインエージェントが参照しなかった
2. **コンテキスト圧縮がサブエージェント稼働情報を消失させた** → 圧縮後の復元義務が機能しなかった
3. **ユーザー報告より自身の推測を優先した** → 「却下された」という自身の記憶を裏取りせず断定
