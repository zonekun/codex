## 【パターン 4: 誤読・ミス原因分析】

### 1. 事象

LINE双方向会話モード（`active: true`）で、コンテキスト圧縮後にntfyコマンドを再構成する際、`--wait` フラグを付けずに3回連続送信した。ユーザーが3回指摘しても自分のコマンドミスと認識できず、外部要因と帰責した。

### 2. 読み手の解釈

圧縮後のAIは以下のように解釈したと推定される:
- CLAUDE.md L39の「send_ntfy_and_waitで自発送信」→ 関数名は認識したがCLIフラグへの変換で`--wait`を脱落
- `--timeout 10800`を指定しているので「待機モードに入る」と確信 → 実際には`--wait`なしでは`--timeout`は無視される
- 送信結果「200 OK」→「正常に送信できた=自分のコマンドは正しい」と確証バイアス発生

### 3. 直接原因

**068知見MDを参照せずに記憶ベースでCLIコマンドを構成した。** CLAUDE.md L37-46には`send_ntfy_and_wait()`という関数名は書かれているが、CLI実行時の`--wait`フラグとの対応はなく、068知見MDの参照が必要だった。

### 4-1. MD上の原因

| ファイル:行 | 問題 |
|------------|------|
| CLAUDE.md:39 | 復旧義務の記述が `send_ntfy_and_wait()` （Python関数名）のみ。CLI実行テンプレートの提供または068への参照導線なし |
| 068知見MD:14-31 | §最重要セクションの使い分け表は明確だが、「コンテキスト圧縮後に必ず本セクションを再読する」という発火条件が記載されていない |
| 068知見MD:82-87 | CLIの `--wait` と `--timeout` の共依存関係（`--wait` なしでは `--timeout` は無視される）が暗黙。コマンド例からは読み取れるが明示的に書かれていない |

### 4-2. MD構成原因

- CLAUDE.md §ライン会話モードから068知見MDへの**コンテキスト圧縮後の参照導線**が欠落。CLAUDE.md L39は「memoryのline_conversation_mode.mdを必ずチェック」とmemory参照は明記しているが、068知見MD参照は暗黙
- CLAUDE.md §知見管理の高頻度参照テーブルには「LINE通知」→068のマッピングが存在する（L244「ライン」「LINE」= ntfy通知）が、これは**用語解釈ルール**であり、コンテキスト圧縮後の復旧フロー中に自動的に発火するトリガーではない

### 5. 根本原因

**2層構造の問題**:

**(a) 行動層: AIの判断がドキュメントを上書きするパターンの4件目**

MR-071/131/134と同根。今回の変種は「知見MD参照の省略」。知見MDを読めば即座に判明する問題を、「自分のコマンドは正しい」という前提のもと知見MD参照を省略した。MR-134で追加された§ステップ完了検証義務（CLAUDE.md L208）は**プランのステップ実行**に対する検証義務であり、**コンテキスト圧縮後のコマンド再構成**という異なるトリガーには発火しない。つまり制度的対策のスコープが不足している。

**(b) 行動層: ユーザーフィードバック無視の深刻化**

MR-134は1回の指摘で気付いたが、MR-136は3回の指摘を要した。「200 OK」という表面的成功が確証バイアスを強化し、ユーザー指摘を「外部要因の報告」と誤解釈した。CLAUDE.md §指示の字義優先（L339）に「ユーザーが同じ方向の指示を2回以上繰り返した場合、自分の前回の実装が指示に沿っていたか0ベースで再評価する」と明記されているにもかかわらず、このルールが発火しなかった。

### 6. 再発防止の方向性

1. **CLAUDE.md §コンテキスト圧縮後復旧義務にCLIテンプレート参照導線を追加**: L39に「068知見MDのCLIテンプレートを参照してコマンドを構成する」旨を追記
2. **068知見MDに`--wait`/`--timeout`共依存の明示的注記を追加**: 「`--timeout`は`--wait`併用時のみ有効。`--wait`なしでは無視される」
3. **CLAUDE.md §注意事項にユーザーフィードバック優先ルールを強化**: 「ユーザーが『動いていない』と指摘した場合、外部要因を疑う前に自分のコマンド/コードを知見MDと照合する」
4. **068知見MDの落とし穴セクションにMR-136事故事例を追記**

### 7. 対策スコープ

提出MDの再発防止策は4点全て意志依存型（「必ずReadする」「即座に再送」「先に検討する」）であり、スコープが本事故固有に閉じている。汎用ルール化が必要な箇所:

- **コンテキスト圧縮後のコマンド再構成時の知見MD参照義務**: ntfyに限らず、圧縮後にCLIコマンドを再構成する全てのケースに適用すべき。ただしCLAUDE.md L39に圧縮後復旧義務は既に存在するため、既存ルールの拡張（CLI具体例の追加）が妥当
- **ユーザーフィードバック無視への構造的対策**: CLAUDE.md §指示の字義優先（L339）は「2回以上繰り返し→0ベース再評価」と既に書かれている。しかし本事故では発火しなかった。「動いていない」系のフィードバックへの具体的な対応手順（まず自分のコマンドを知見MDと照合する）をCLAUDE.mdに追加すべき
