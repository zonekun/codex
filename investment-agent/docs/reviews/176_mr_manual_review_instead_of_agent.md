# MR-176 /code-reviewer 未起動・手動レビュー実施

- **日時**: 2026-05-15 JST
- **パターン**: 2（誤読・ミス報告）
- **違反規約**: CLAUDE.md §4.2（ユーザー指示優先）、§8（スキル・エージェント）

---

## 事象

ユーザーが「ソースコードレビューに」と指示。これは `/code-reviewer` エージェントの起動指示だったが、Claude Code が自分で直接レビューを実施してしまった。

## ユーザー指示の原文

> ソースコートとskill両方

## 実際の動作

1. `scrape_jpx_delisted.py` と `skills/classify_tob.md` を Read
2. Claude Code 自身が5件の指摘を列挙
3. ユーザーが「レビューワ起動という意味だったが レビュー済みなのでもうよい」と訂正

## 原因分析

- 「レビューに」を「レビューして」と解釈した。「レビューに（出して）」→ `/code-reviewer` エージェント起動、という意図を読み取れなかった
- §8 にエージェント一覧（`/code-reviewer` = 独立実行→結果返却）が明記されており、レビュー業務は `/code-reviewer` の管轄
- 手動レビューと `/code-reviewer` の使い分け判断基準が不明確だったため、デフォルトで手動実行に流れた

## 構造的原因

- 「レビュー」という語がユーザー発話に含まれた時点で `/code-reviewer` 起動を第一候補とすべきだが、その発火条件が内部的に確立されていなかった
- MR-110（code-reviewer routing miss）で同種の事故が過去にも発生している

## 再発防止

- 「レビュー」「レビューに」「レビューして」等のキーワードが含まれる指示は、まず `/code-reviewer` 起動が適切かを判断する
- ユーザーが明示的に「自分で見て」「直接確認して」と言った場合のみ手動レビュー

## 影響

- レビュー結果自体は有効（5件指摘→全件修正済み）で実害なし
- ただしエージェントが発見する可能性のあった追加指摘を見逃したリスクあり
