# 118 事故報告: テストスクリプトを C:\tmp\ に配置（scripts/ 規約違反）

- 日時: 2026-05-08 JST
- 対象: `scripts/test_yutai_nav.py`（修正後の正しいパス）
- パターン: 2（誤読・ミス原因レビュー）
- レビュアー: md-reviewer
- 出力先: `docs/reviews/118_mr_test_script_placement_violation.md`

---

## 事象

松井証券 ResearchNet の株主優待ナビゲーションのテストスクリプトを新規作成した際、初版を `C:\tmp\test_yutai_nav.py` に配置した。ユーザーが即座に指摘し、`scripts/test_yutai_nav.py` に再作成された。

## なぜ誤りか

- **`C:\tmp\` はテンポラリダウンロードデータ専用**: CLAUDE.md §実行環境に「ローカルDL保存先: `C:\tmp\`（Google Drive・Dropbox 禁止）。検証後は削除する」と明記。スクリプトの配置先ではない
- **テストスクリプトは `scripts/` 配下に `test_` プレフィックスで配置**: 既存の `scripts/test_conse_quick.py` がこの命名規則に従っている。`docs/knowledges/tools/004_coding_conventions.md` §命名規則で定義
- **`C:\tmp\` のスクリプトは git 管理外**: プロジェクトリポジトリの外にあるため、バージョン管理・コードレビュー・他端末での再利用が不可能

## 影響

**低**: ユーザーが即座に指摘し、ファイルは削除・再作成された。本番影響なし。

## 根本原因

1. **コーディング規約を参照せずに Write した**: CLAUDE.md §コーディング規約に「`scripts/` 配下に新規 .py ファイルを作成する場合、Write 実行前に `docs/knowledges/tools/004_coding_conventions.md` を Read」と明記されているが、参照しなかった
2. **「テスト」「一時的」という意味的連想**: テストスクリプトを「一時的なもの」と解釈し、テンポラリディレクトリに配置する判断をした。しかしテストスクリプトも正規のプロジェクト成果物であり、`scripts/` に配置すべき
3. **既存の同種スクリプトを確認しなかった**: `scripts/test_conse_quick.py` という先例が存在するにもかかわらず、既存の命名・配置パターンを確認しなかった

## MD上の原因（4-1）

- **`CLAUDE.md:290`（修正前）** — トリガー条件「`scripts/` 配下に新規 .py ファイルを作成する場合」は、`scripts/` 以外にスクリプトを書こうとした場合にトリガーが発火しない。「新規 .py スクリプトを作成する場合（配置先を問わず）」とすべきところ、配置先を限定していた
- **`CLAUDE.md:78`** — `C:\tmp\` の用途が「ローカルDL保存先」と書かれているが、「スクリプト配置禁止」とは明記されていない。DL先とスクリプト配置先の区別がAIにとって自明でない
- **`docs/knowledges/tools/004_coding_conventions.md`** — テストスクリプト（`test_*.py`）の配置先ルールが明文化されていなかった。`tmp_*.py`（一時スクリプト）と `lib_*.py`（共通ライブラリ）の配置・命名規則は明文化されているが、`test_*.py` のセクションがなく、既存ファイル（`scripts/test_conse_quick.py`）からの推論に依存していた

## MD構成原因（4-2）

- CLAUDE.md L290 のルールが「`scripts/` 配下に書くと決まった後」のチェックリスト参照を強制する設計であり、「どこに書くか」の判断フェーズをカバーする上位ルールが不在だった
- 004_coding_conventions.md の命名規則セクション（§一時スクリプト、§共通ライブラリ）にはテストスクリプトの項がなく、AIが配置先を探しても明文ルールを見つけられない構造だった

## 再発防止

本事故は、既存ルールのトリガー条件に盲点があることを証明した。以下の対策を実施:

1. **CLAUDE.md L290 トリガー条件拡張**: 「`scripts/` 配下に新規 .py ファイルを作成する場合」→「新規 .py スクリプトを作成する場合（配置先を問わず）」に変更。配置先が `scripts/` であることも明記（事故: review 118 で追加）
2. **004_coding_conventions.md にテストスクリプト配置ルール追記**: `test_*.py` のセクションを新設し、配置先は `scripts/` 配下、`C:\tmp\` やプロジェクト外は禁止と明文化

## 新規リスク（6）

- CLAUDE.md の修正後トリガー文言「新規 .py スクリプトを作成する場合（配置先を問わず）」が `src/` 配下のモジュール（スクリプトではないPythonファイル）にも過剰に発火するリスク。文言上「スクリプト」に限定しているため低リスクだが、AIの解釈次第では不要な 004 参照が発生し得る
- `C:\tmp\` 以外にも不適切な配置先（プロジェクトルート直下、`data/` 配下等）が存在する。今回の修正でトリガー自体は拡張されたが、「どこに書くか」の具体的な判断材料は 004 に依存する

## レビュー対象ファイルパス

- `docs/knowledges/tools/004_coding_conventions.md` — 命名規則・配置ルールの正本。§テストスクリプト（test_*.py）を追記
- `CLAUDE.md` §実行環境 — `C:\tmp\` の用途定義
- `CLAUDE.md` §コーディング規約 — 新規スクリプト作成時の必読ルール（トリガー条件を拡張）
