# 042: 新規運用規約の導入時にルール明文化を同時実行しなかった

**日時**: 2026-04-30 JST
**重大度**: Medium（ユーザー指摘1回で修正完了。ただし構造的に再発しやすいパターン）
**カテゴリ**: 運用ミス（暗黙の規約導入 + ルール文書化の後回し）

## 事象

`docs/knowledges/tools/059_earnings_model_eda.md` の反省会ログにおいて、ユーザー検証済みエントリと自動生成エントリを区別するために「✓」マークを導入した。具体的には:

- ✓ 付き = ユーザーが検証した確定エントリ
- マークなし = AI自動生成の未検証エントリ

この区別は反省会ログの信頼性管理として有効な規約だが、**ログエントリへの適用のみ行い、手順セクションへのルール明文化を行わなかった**。ユーザーから「これルールとして書いた？」と問われて初めて、「銘柄別ログの検証ルール」セクションを反省会の運用手順に追記した。

### 会話ログ（該当部分）

```
AI: （反省会ログに ✓ マーク付きエントリと未マークエントリを混在記録）

ユーザー: これルールとして書いた？

AI: （「銘柄別ログの検証ルール」セクションを059 MDの運用手順に追記）

ユーザー: 言われないとできないのはしんどい
```

## 根本原因

### 1. 「適用」と「文書化」を別工程として扱う思考パターン

AIは新規パターンを「その場で使う」ことと「将来のために明文化する」ことを分離して捉えている。結果として、適用は即座に行うが文書化は「次のステップ」として後回しになり、指摘されるまで実行されない。

### 2. 暗黙知の生成に対する自覚の欠如

新しい記法規約（✓マーク）を導入した時点で、それは暗黙知を生み出している。次回セッションのAIがこのファイルを読んだとき、✓の意味を知らなければ正しく運用できない。この「将来の自分（別セッション）が困る」という視点が欠落していた。

### 3. CLAUDE.mdの知見管理義務の射程外

CLAUDE.md §知見管理の義務は「ファイル追加・移動・リネーム時」や「既存スクリプトの動作変更時」の知見MD更新をカバーするが、「**同一ファイル内で新規規約を導入した場合、同ファイルの手順セクションにもルールを書く**」という粒度の義務は明文化されていなかった。

## 正しい動作

新しいパターン・規約・記法をファイルに導入する際は、以下を**アトミック（不可分）操作として同時に実行する**:

1. **パターンの適用**: 実データにパターンを反映する（今回: ✓マーク付与）
2. **ルールの明文化**: 同一ファイルまたは対応する手順セクションに、パターンの定義・適用条件・判定基準を記載する

Step 1 だけ実行して Step 2 を省略・後回しにしてはならない。

### 判定基準

以下のいずれかに該当する変更を行った場合、ルール明文化が必須:

- 新しい記法・マーク・プレフィックスの導入（例: ✓、~~取消線~~、[VERIFIED] 等）
- 既存フォーマットへの新しいフィールド・列の追加
- エントリの分類基準・優先順位の変更
- 暗黙の命名規則・配置規則の適用

## 再発防止

**ルール（即時適用）**: ファイルに新しい運用規約・記法・分類基準を導入する場合、**同じコミット（同じ編集アクション）内で手順セクションにルールを明文化する**。「適用」と「文書化」は常にアトミック操作とし、片方だけの実行を禁止する。

**セルフチェック**: 「この記法/規約を、このファイルを初めて読む別セッションのAIが正しく運用できるか？」— No なら手順セクションへの記載が足りていない。

## レビュー自体の不備

本レビューは「新規規約の適用とルール明文化は常にアトミック操作」という再発防止ルールを提示したが、**そのルール自体をどこに永続的に記載するかを明記していなかった**。「ルール（即時適用）」と書いただけで、記載先ファイル・セクションが不明のまま閉じており、本レビューが報告した問題（ルール文書化の欠落）を本レビュー自身が再現していた。
