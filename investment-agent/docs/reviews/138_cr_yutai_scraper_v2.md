### #1 会社名フィールドの取得源が未定義

- 箇所: `docs/plans/tools-098_yutai_scraper_20260509_165014.md:27` (列構成: 会社名)、`scripts/test_yutai_nav.py:132-148` (`extract_yutai_data`)
- 事象: Excel 出力仕様の「会社名」列に対応するデータ取得ロジックが v1 コードに存在しない。`extract_yutai_data()` は `ticker`, `kenri_kakutei`, `yutai_text` のみ返す
- トリガー: Phase 2 で `update_yutai.py` を実装する際、会社名の取得方法が不明で実装者（Codex含む）が判断を迫られる
- 影響: 実装者が独自判断で BQ 問い合わせを追加するか、リサーチネットページから別途スクレイピングするか、空欄のまま進む可能性
- 根拠: `test_yutai_nav.py:132-148` の `extract_yutai_data()` の返却 dict に `"name"` キーが存在しない。一方 `098_yutai_scraper.md:101-103` の中間JSONL仕様には `"name": "王将フード"` が含まれている
- 推奨対応: **[方向性]** 計画 Phase 2 Step 5 に「会社名は BQ `STOCK_CODE_LIST` から事前取得して JSONL に付与」等の方針を明記する。リサーチネットのページ上にも会社名は表示されるため、スクレイピングで取得する方法もあるが、BQ から事前に ticker→会社名マップを作る方が安定的

### #2 全銘柄走査の所要時間見積もりと中断耐性の設計不足

- 箇所: `docs/plans/tools-098_yutai_scraper_20260509_165014.md:57-59` (全銘柄走査・リスタート機能)
- 事象: 計画の見積もり（4-5時間 + テスト1時間）は実装時間のみ。全銘柄走査の実行時間（推定 4-5 時間）が記載されていない。またリスタート機能は「既存JSONL読み込み→処理済みスキップ」のみで、セッションタイムアウト（松井証券が長時間操作で自動ログアウト）への対応が未検討
- トリガー: 全銘柄走査を開始し、2-3 時間経過後に松井証券セッションが切れる
- 影響: セッション切れ後の全リクエストが失敗し、空回りする。リスタート機能があっても再ログインが必要。`update_conse_quick.py` にはセッション切れ検知ロジックが存在するか不明
- 根拠: `test_yutai_nav.py:230` のメインループに `time.sleep(1)` × 3,768社 ≒ 4-5時間の直列処理。証券会社のWebセッションには通常 30-60 分のアイドルタイムアウトがある
- 推奨対応: **[方向性]** (1) セッション切れ検知（`NoSuchElementException` や特定のエラーページ検出）→ 自動再ログイン → リスタートのフローを設計に追加。(2) 計画の見積もりに実行時間を明記。`update_conse_quick.py` の同種実装があれば参考にする

### #3 中間JSONL→Excelシート振り分けの月パース仕様が未定義

- 箇所: `docs/plans/tools-098_yutai_scraper_20260509_165014.md:35-36` (権利月の表記ルール)、`docs/plans/tools-098_yutai_scraper_20260509_165014.md:70` (シート `01`〜`12` に月別振り分け)
- 事象: `kenri_kakutei` テキスト（例: `"3月末、9月末"`, `"4月末"`, `"5月15日"`）から月番号を抽出するパースロジックの仕様が Phase 3 に含まれていない
- トリガー: Phase 3 で Excel 生成を実装する際、多様な表記パターンの月パースで実装者が判断を迫られる
- 影響: `"毎年4月末(期末)時点"` や `"随時"` のような変則パターンで月の判定に失敗し、シートへの振り分けが漏れる
- 根拠: `098_yutai_scraper.md:71-73` のパターン例で `"3月末、9月末"` 等が列挙されているが、正規表現や判定フローは未記載。`"随時"` の場合にどのシートに配置するかも未定義
- 推奨対応: **[方向性]** Phase 1 の 098知見MD更新時に、`kenri_kakutei` テキストの全パターン（月末/月中/複数月/随時）と対応する月番号抽出ルールを定義する。随時優待は全月に複写するか、専用シート（`00` 等）を用意するかの方針を決定
