## 【重大な指摘】（即修正）

### #1 `_bc_ignore_reason` フィールド名がスキーマ定義と不一致

- 箇所: `docs/plans/20260508_125300_monthly_autofix_bc_ignore_knowhow.md:77`
- 事象: P0-1のStep 3C修正方針内で `_bc_ignore_reason` を使用しているが、042_monthly_disclosure_master.md L157のextract_adapter.json正式スキーマ定義では `bc_ignore_reason`（アンダースコアなし）
- トリガー: 計画通りにスキルMDを修正した場合、エージェントが `_bc_ignore_reason` を設定するが、突合ロジック（compare_monthly_buffett.py）が `bc_ignore_reason` を参照する可能性
- 影響: bc_ignore理由が記録されない、または突合ロジックで無視される
- 根拠: `042_monthly_disclosure_master.md:157` — `| bc_ignore_reason | string | — | bc_ignore の理由。BC値の逆引き結果を含めて記載する |`
- 推奨対応: 計画内の `_bc_ignore_reason` を `bc_ignore_reason` に統一。スキーマ定義が正本

### #2 E6一致キーが既存E1/E3パターンと広範に重複

- 箇所: `docs/plans/20260508_125300_monthly_autofix_bc_ignore_knowhow.md:137,153,165,179,194`
- 事象: E6-1〜E6-4の一致キーに `抽出結果.*0件|一致なし` が含まれるが、これはE1-1（L43）`一致なし|抽出結果.*0件|regex.*fail`、E3-1（L74）`一致なし|抽出結果.*0件` とほぼ同一
- トリガー: パターンDB照合時に `抽出結果.*0件` でgrepすると、E1/E3/E6の全てがヒットし、どのパターンを適用すべきか判定不能
- 影響: エージェントがE6（bc_ignore判定）でなくE1/E3（regex修正・Gemini変換）に誤誘導される可能性
- 根拠: 042-1パターンDB L13-14 使い方: 「エラーログから「一致キー」でgrepして該当パターンを特定」
- 推奨対応: E6パターンの一致キーにE6固有の識別子を追加する。例: `bc_ignore|GCS.*0件|文書.*なし|文書種別` など、GCS文書レベルの問題を示すキーワードを含める。または、確認条件の段階で明確に区別できることを042-1の使い方セクションに補記する（「一致キー重複時は確認条件で絞り込む」）
