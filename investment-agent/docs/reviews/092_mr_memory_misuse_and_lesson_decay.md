# MR-092: メモリ用途誤判定 + 教訓の形骸化

**作成日**: 2026-05-07
**種別**: 運用レビュー（自己申告）
**重大度**: 中（ルール違反だが即座に是正された）

---

## 事象

2022年バックフィル監視中、ScheduleWakeup チェーンが API 529 で途切れ 05:00 JST 開始に失敗（2h45m 遅延）。その後の対応で2つの問題が発生。

### 問題1: メモリへの不適切な記録宣言

**やりとり**:
```
ユーザー: 教訓は生かされるのか
Claude: 教訓を生かします。今回の件をメモリに記録し、次回から長時間待機は CronCreate を使います。
ユーザー: メモリは不適切
```

**違反ルール**: CLAUDE.md §記録・保存の制約
> 「調査結果・再発防止策のメモリ保存は厳禁」
> 「プロジェクト全体の取り決めもメモリNG: 端末横断で共有すべき前提は CLAUDE.md / skills/*.md / docs/knowledges/ に書く」

ツール使い分けルールはプロジェクト全体の運用規約であり、知見ファイル（093_monitoring_obligation.md）に記載すべきもの。メモリに記録すると宣言したのはルール違反。

### 問題2: 「教訓は生かされるのか」の本質

ユーザーの問いは修辞的ではない。以下の構造的問題を指摘している:

1. **ルールの存在と適用のギャップ**: 093_monitoring_obligation.md に ScheduleWakeup の限界は暗黙的に記載済み（CronCreate が選択肢に挙がっている）。にもかかわらず長時間待機で ScheduleWakeup チェーンを選択した
2. **是正の保存先を再び誤る**: 教訓を知見ファイルに書くべきところ、反射的に「メモリに記録」と回答。CLAUDE.md §記録・保存の制約を参照していない
3. **形式的な「教訓を生かします」**: 具体的な記録先・記録内容を示さず、口約束だけで済ませようとした

## 再発防止

- **記録先の判定フロー**: 教訓・ルール → 知見ファイル or CLAUDE.md。個人の行動傾向 → memory。この判定を「記録します」と発言する前に行う
- **「生かします」は動詞で示す**: 口頭宣言ではなく、具体的なファイルパスと記載内容を提示してから書く
