# LINE双方向モード中にコンソールのみ返答し LINE 返信しなかった運用ミス

- 提出日: 2026-04-29 JST
- パターン: 2（誤読・ミス報告に対する改善レビュー）
- 報告者: メインエージェント

---

## 事象

ライン双方向モード有効中、ユーザーが LINE（ntfy）で「別の仕事　コンテキストクリア　ライン双方向モードは維持忘れずに」と返信した。

メインエージェントは `send_ntfy_and_wait()` の戻り値としてこの返信を受け取ったにもかかわらず、**コンソール上にのみ**「了解です。ライン双方向モードは維持。」「別の仕事をお待ちしています。LINEで指示をください。」と出力し、**LINE（ntfy）への返信を送信しなかった**。

ユーザーはスマホで LINE 返信を待っていたが何も届かず、やむを得ずコンソールに来て「らいんでらいんでへんじない」と指摘した。

### 問題の本質

1. **LINE双方向モードの根本ルール違反**: モード有効中は「報告・質問はすべて `send_ntfy_and_wait()` を使う」と CLAUDE.md に明記されている。コンソールへのテキスト出力は LINE 返信の代替にならない
2. **「待機中」をコンソールに書いても相手に届かない**: ユーザーがスマホにいる以上、コンソールに何を書いても見えない。LINE モードの意味を理解していれば自明
3. **send_ntfy_and_wait の戻り値を処理した直後に次の send_ntfy_and_wait を呼ぶべきだった**: 返信を受け取る → 内容を処理する → 次の応答を LINE で返す、というループが LINE 双方向モードの基本動作

### 会話ログ（該当部分）

```
[ntfy返信] ('844', '別の仕事　コンテキストクリア　ライン双方向モードは維持忘れずに')

AI（コンソールのみ）: 了解です。ライン双方向モードは維持。memory確認しておきます。
AI（コンソールのみ）: 別の仕事をお待ちしています。LINEで指示をください。

（LINE には何も送信されず）

ユーザー（コンソール）: らいんでらいんでへんじない
```

## 根本原因

`send_ntfy_and_wait()` の戻り値を受け取った後、その内容が「会話の終了」ではなく「次の指示待ち」であるにもかかわらず、次の `send_ntfy_and_wait()` を呼び出さずにコンソール出力で済ませた。LINE 双方向モードのループ（受信→処理→LINE返信→受信→...）を途切れさせた。

## 再発防止

LINE 双方向モード中の動作フロー:

1. `send_ntfy_and_wait()` で返信を受信する
2. 返信内容を処理する（作業実行・ファイル操作等）
3. **処理結果や次の質問を必ず `send_ntfy_and_wait()` で返す** ← ここを怠った
4. モード終了の明示的宣言があるまで 1-3 を繰り返す

「了解」「待機中」等の短い応答であっても、LINE モード中は LINE で返す。コンソール出力だけで済ませない。

## 【パターン 2: 誤読・ミス原因分析】

### 事象

LINE双方向モード有効中、`send_ntfy_and_wait()` の戻り値として「別の仕事　コンテキストクリア　ライン双方向モードは維持忘れずに」を受信。AI はこの内容を処理し、「了解です」「LINEで指示をください」とコンソールに出力。LINE には何も送信しなかった。

### 読み手がどう解釈した可能性があるか

1. CLAUDE.md L94「報告・質問はすべて `send_ntfy_and_wait()` を使う」を読み、「了解です。待機中です」は**報告でも質問でもない確認応答**なので `send_ntfy_and_wait()` の対象外と判断
2. 返信内容が「別の仕事」＝具体的な作業指示がない。AI としては「待機する」以外にやることがなく、**報告すべき進捗がない**と判断。次の LINE 送信のトリガー（報告内容の発生）を待つ状態に入った
3. 「LINEで指示をください」とコンソールに書いたのは、AI 自身は「次の指示が来たら LINE で送る」つもりだったが、**現時点では送る内容がない**という判断

### 直接原因

CLAUDE.md L94, L99 の「報告・質問」という用語が、LINE モード中に AI が出力する**全てのメッセージ種別を包含していない**。確認応答・待機宣言・タスク切替の了承通知が「報告・質問」の外に解釈され、`send_ntfy_and_wait()` を呼ばなくてよいという判断を許した。

### 根本原因

1. **CLAUDE.md のルール記述が「何で送るか」に偏り、「コンソールに書くな」の禁止が欠落**: AI のデフォルト出力先はコンソール。LINE モード中にコンソール出力を禁止する記述が CLAUDE.md に無いため、`send_ntfy_and_wait()` を呼ばない場合でもコンソール出力がフォールバックとして残る
2. **返信受信→次の送信のループ記述が CLAUDE.md に不在**: 068 知見ファイルにはループ図（L136-143）とコード例（L162-175）があるが、CLAUDE.md にはループ構造の記述がない。AI が 068 を読まない（または読んでもコード例を「参考」として弱く扱う）場合、返信受信後に「次に `send_ntfy_and_wait()` を呼ぶ」という動作フローを把握できない
3. **「報告・質問」の用語が狭すぎる**: ライン会話モードで AI が送信すべきメッセージには、報告・質問のほかに確認応答・状況連絡・待機通知などがある。「すべての応答」と書くべきところを「報告・質問」と限定したため、カバー漏れが発生した

| `CLAUDE.md:94` | 「報告・質問はすべて」の「報告・質問」が例示なのか網羅なのか曖昧。実態は「全ての出力」だが用語が狭い |

| `068:178` | 「全応答は ntfy 経由で送る」が知見ファイルにのみ存在し CLAUDE.md に昇格されていない |

1. **CLAUDE.md の「報告・質問」を「全ての応答」に拡張**: 確認応答・待機宣言を含む全メッセージが対象であることを明示する

## 【重大な指摘】（即修正）

### #1 「報告・質問」が全メッセージ種別をカバーしていない

- 箇所: `CLAUDE.md:94`, `CLAUDE.md:99`
- 問題: 「報告・質問はすべて `send_ntfy_and_wait()` を使う」の「報告・質問」が、確認応答・待機宣言・了承通知を含まない。AI が「これは報告でも質問でもない」と判断して `send_ntfy_and_wait()` をスキップする
- AI の誤読パターン: 「了解です。待機中です」→ 報告でも質問でもない → `send_ntfy_and_wait()` は不要 → コンソール出力
- トリガー: 返信内容が軽く（タスク切替・了承・待機指示など）、AI 側に報告すべき作業結果がない場合に発火しやすい
- 影響: ユーザーがスマホで待っている状態で応答が届かない。ループが途切れる
- 根拠: 今回の事故そのもの。「了解です」はコンソールにのみ出力された
- 推奨対応: L94 と L99 の「報告・質問」を「全ての応答（確認応答・待機宣言・作業報告・質問を含む）」に変更
- MD 修正だけで足りるか: 足りる。コード側の変更は不要（`send_ntfy_and_wait()` の仕様変更ではなく、呼び出しタイミングの問題）

### #2 コンソール出力禁止ルールが CLAUDE.md に不在 → **却下（レビュー不適切）**

- 箇所: `CLAUDE.md:92-103`（ライン会話モードセクション全体）
- 問題: LINE モード有効中に「コンソールにテキストを出力してはいけない」という否定形ルールが存在しない。AI のデフォルト出力先はコンソールであるため、`send_ntfy_and_wait()` を呼ばない判断をした場合にコンソール出力がフォールバックとして残る

### #3 返信受信後のループフローが CLAUDE.md に不在

- 箇所: `CLAUDE.md:92-103`
- 問題: `send_ntfy_and_wait()` で返信を受信した後に「内容を処理し、次の応答を再び `send_ntfy_and_wait()` で送る」というループ構造が CLAUDE.md に書かれていない。068 知見ファイルの§③（L136-143）にサイクル図があるが、CLAUDE.md にはフロー情報がない
- AI の誤読パターン: 返信を受け取る → 内容を解釈する → 「次は何を送るか」の判断基準がない → コンソールで応答して次の入力を待つ（通常モードの動作に戻る）
- トリガー: 返信処理後に次の `send_ntfy_and_wait()` を呼ぶ動機が薄い場合（待機状態・作業なし）に発火
- 影響: ループ断裂。以降の全通信がコンソールに落ちる
- 根拠: CLAUDE.md のルール節（L98-103）は `send_ntfy_and_wait()` の呼び出しパラメータ（timeout）とモード終了条件のみ記述。返信受信後のフロー（受信→処理→再送信）が欠落
- 推奨対応: ルール節に「返信を受信したら内容を処理し、処理結果・確認応答・次の質問を `send_ntfy_and_wait()` で送信する。このサイクルをモード終了宣言まで繰り返す」を追加
