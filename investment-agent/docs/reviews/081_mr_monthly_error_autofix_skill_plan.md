## 【AI 誤読リスク】

### Risk-1: Layer 1「一致」判定の曖昧さ

**箇所**: `docs/plans/20260505_193700_monthly_error_autofix_skill.md:248-249`
> 042-1 パターンDB検索 → 既知パターンに一致？

**問題**: 「一致」の定義がない。以下のケースでAIは判断できない:
- ログに`regex.*一致なし`が出たが、パターンDBのE1事例とはregex不一致の原因が異なる場合
- D1（ドメイン変更）で404が出ているが、実際は一時的なサーバーダウンの場合
- E3（Gemini変換）の「判断基準」がパターンDBにあるが、今回のPDFがその基準の境界ケースの場合

**AI誤読パターン**: 「ログパターンが文字列として一致すれば既知パターン」と解釈し、根本原因が異なるエラーに既知の修正を適用 → 誤修正

### Risk-2: Step 2分類テーブルとLayer 2調査戦略テーブルのキー不一致

**箇所**: L62-70（Step 2分類）vs L288-298（Layer 2戦略テーブル）

**問題**: Step 2はD1-D4/E1-E6のコードで分類するが、Layer 2のテーブルは「パース/型エラー」「regex不一致」「年月検出失敗」等の自然言語ラベル。マッピングが1:1でない:
- 「パース/型エラー」はE4に対応？E5に対応？両方？
- 「Gemini応答異常」はE4だがStep 2の分類とLayer 2のラベルが微妙に異なる
- 「未分類のException」はStep 2のどのカテゴリにも該当しない場合のフォールバック？

**AI誤読パターン**: Step 2でE1に分類 → Layer 2に到達 → テーブルで「regex不一致」を探すが、「regex不一致」がE1の完全同義語か確信できず戦略選択に迷う

### Risk-3: Gemini API暗黙使用

**箇所**: L129, L141-143, L163

**問題**: CLAUDE.md §Gemini API: 「ユーザーの明示的な指示がない限り Gemini APIを呼び出さないこと」。しかしこのスキルはAgent型（独立コンテキスト）で、E3パターンの修復では `extraction_method: "gemini"` への変更が核心作業。さらにD1でも「Geminiで確認」と記載。

**曖昧さ**: スキル実行 = ユーザーの明示的指示と解釈してよいか？ スキルMDに「本スキル実行時はGemini API使用を許可する」の明示がないとAIが都度確認を求めてエージェント自律性が破綻する。

### Risk-4: 「調査の原則」と「30分以内に完了」の矛盾

**箇所**: L23（目標: 30分以内）vs L299-301（1社ずつ丁寧に。バッチ的な推定禁止）

**問題**: 6社のエラーを30分で解決するには1社あたり5分。Layer 3（全力新規調査 ~10分）に1社でも到達すると時間超過。AIは「30分目標」を優先して調査を打ち切るか、「1社ずつ丁寧に」を優先して時間超過するか判断できない。

## 【重大な指摘】（即修正）

### #1 Layer 1→2遷移条件の判定基準が未定義

**箇所**: `docs/plans/20260505_193700_monthly_error_autofix_skill.md:248-249`
**問題**: 「既知パターンに一致？」のYES/NO判定基準が自然言語の曖昧な問いかけのまま
**AIの誤読パターン**: ログ文字列の部分一致で「既知」と判断し、根本原因が異なるエラーに既知修正を誤適用
**トリガー**: パターンDBに類似エラーが蓄積されるほど、部分一致の誤判定リスクが上昇
**影響**: adapter誤修正 → 正常に動いていた抽出が壊れる（既存データ破壊）
**根拠**: パターンDB構造例のE1は「regex不一致（文字間スペース）」だが、regex不一致には「フォーマット変更」「PDF構造変更」「OCR誤認」等の別原因もある
**推奨対応**: Layer 1の一致判定に以下を明示:
  - 一致条件: (a) ログパターン文字列が一致 AND (b) 根本原因カテゴリ（パターンDBの「検出方法」に記載）を現物確認で一致させる
  - 「ログパターンのみ一致、根本原因が未確認」→ Layer 2に進む（Layer 1即適用しない）
**MD修正だけで足りるか**: 足りる。スキルMDの遷移条件セクションに判定基準を追加

### #2 パターンDB蓄積の「一致キー」設計が欠落

**箇所**: `docs/plans/20260505_193700_monthly_error_autofix_skill.md:222-228`（蓄積ルール）
**問題**: 蓄積ルールは「新パターンを発見したら即座に追記」「同一パターンの重複記載は禁止」だが:
  - 「同一パターン」の判定基準がない（ログ文字列？根本原因？修復手順？）
  - 将来のLayer 1検索で「既知パターンに一致するか」を判定するための検索キー（ログパターン文字列）がDB構造の必須フィールドとして定義されていない
**AIの誤読パターン**: 新パターン追記時に、検索に使えない自由記述で書いてしまい、将来のLayer 1検索が機能しない
**トリガー**: パターンが10件以上に増えた段階で検索精度が劣化
**影響**: Layer 1が事実上機能せず、毎回Layer 2から開始 → 30分目標未達
**根拠**: 現在のDB構造例（L178-220）は人間可読だが、AIが「このエラーはどのパターン？」を機械的に判定するための構造化キーがない
**推奨対応**: パターンDB各エントリに以下の構造化フィールドを必須化:
  ```
  - **一致キー**（ログgrepパターン）: `regex.*一致なし`
  - **確認条件**: PDFテキストにはデータが存在する
  - **除外条件**: PDF構造が前回と同一の場合はE1ではなくコード側バグ
  ```
**MD修正だけで足りるか**: 足りる。042-1のDBフォーマット定義を構造化

### #3 Step 2分類→Layer 2調査戦略のキーマッピング断絶

**箇所**: L62-70（D1-E6分類）vs L288-298（Layer 2テーブル）
**問題**: Step 2の出力（D1/D2/.../E6のコード）がLayer 2テーブルの入力キー（自然言語ラベル）と1:1対応していない
**AIの誤読パターン**: E5（空文字キー問題）をStep 2で分類した後、Layer 2テーブルにE5に対応する行がなく、「未分類のException」を選ぶか戦略なしで止まる
**トリガー**: Step 2で分類できたがLayer 2に該当行がないエラー全般
**影響**: 戦略選択の失敗 → 非効率な調査 → 時間超過
**根拠**: Layer 2テーブルには7行あるが、Step 2分類は10種（D1-D4, E1-E6）。E5/E6の調査戦略が欠落
**推奨対応**: Layer 2テーブルのキーをStep 2のコード（D1-D4, E1-E6）に統一。または各コードに対応する調査戦略を明示
**MD修正だけで足りるか**: 足りる

### #4 Gemini API使用の明示的許可が欠落

**箇所**: プラン全体（特にL129, L141-143, L163）
**問題**: CLAUDE.md §Gemini API「ユーザーの明示的な指示がない限り Gemini APIを呼び出さないこと」に対して、スキルMD内でGemini使用を許可する記述がない
**AIの誤読パターン**: E3修復でextraction_method:"gemini"に変更する作業自体は可能だが、D1でのドメイン確認にGeminiを使おうとして「CLAUDE.md違反では？」と自問してエスカレーション
**トリガー**: スキル実行のたびに発生
**影響**: 自律実行が不可能になる（毎回人間確認が必要 → スキルの意味がない）
**根拠**: CLAUDE.md §Gemini API, feedback_gemini_local_personal.md
**推奨対応**: スキルMDの冒頭に「本スキル実行時のGemini API使用は許可される（extraction_method変更・ドメイン確認に限る）」を明記。また CLAUDE.md §Gemini APIの条文を「ユーザーの明示的な指示 **またはスキルMDでの明示的許可** がない限り」に改訂提案
**MD修正だけで足りるか**: プランMD + CLAUDE.md の2箇所の改訂が必要

### #5 時間目標と調査原則の優先順位未定義

**箇所**: L23 vs L299-301
**問題**: 「30分以内完了」（目標）と「1社ずつ丁寧に。バッチ的な推定禁止」（原則）が衝突した場合の優先順位がない
**AIの誤読パターン**: Layer 3に2社到達した時点で20分経過 → 「30分に間に合わない」と判断して残り4社を打ち切り or 調査を雑にする
**トリガー**: 未知エラーが2社以上含まれる場合
**影響**: 調査品質低下 or 中途半端なエスカレーション
**根拠**: 背景で「所要2時間→目標30分」と書かれているが、Layer 3の~10分/社を考慮すると6社全部Layer 3だと60分
**推奨対応**: 「30分は目安。品質（1社ずつ丁寧に）を時間より優先する。ただし60分超過時はエスカレーション」等の優先順位を明示
**MD修正だけで足りるか**: 足りる
