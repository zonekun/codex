## 【パターン 2: 誤読・ミス原因分析】

### 事象
2019-H1バックフィル完了時、087メトリクスファイルは自動的に更新・コミットしたが、バックフィル計画MD（`docs/plans/20260427_140000_tdnet_2017_2022_backfill.md`）のステータステーブル（L17-24）および後片付けチェックリスト（L419-425）の更新を怠った。ユーザーに「MDファイル更新したか」と指摘されて初めて対応。

### 読み手がどう解釈した可能性があるか
- memory `feedback_backfill_metrics_auto.md` が「ジョブ完了検知時に自動で087知見ファイルを更新」と明記。AIは「バックフィル完了時の自動記録義務=087への記録」と等置し、プランMDの更新は別途指示があるまで不要と判断した可能性が高い
- CLAUDE.md §知見ファイル整合義務は「スクリプトの動作変更時」に発火するルールであり、「作業の進捗変化時」には発火条件が合致しない。AIがこのルールを認識していても「今回はスクリプトを変更していないので対象外」と正当化できる

### 直接原因
- memory feedbackが087メトリクス記録のみを自動化義務として定義しており、プランMDの進捗更新が義務の射程外だった
- プランMD自体の「後片付け」セクション（L419-425）に `[ ] 本プランのステータスを ✅ 完了 に更新` が既に記載されていたが、完了時にこのチェックリストを参照するフローが確立されていなかった

### 根本原因
1. **義務の分散と不完全な網羅**: バックフィル完了時の更新義務が「087メトリクス」（memory feedback）と「プランMDステータス」（プランMD末尾チェックリスト）に分散しており、一方だけ実行して他方を忘れる構造
2. **先行事故の教訓未活用**: 041（2026-04-30）で「スクリプト改修後の知見MD更新漏れ」が発覚し、CLAUDE.md L221 に知見ファイル整合義務が追加された。しかしこの義務は「スクリプトの動作変更」が発火条件であり、「プランに紐づく作業の進捗変化」をカバーしていない。041の教訓の一般化が不十分だった
3. **チェックリスト参照のトリガー不在**: プランMDの「後片付け」チェックリストは書かれているが、「いつ参照するか」のトリガーが定義されていない。完了時に自動的にこのセクションを読みに行く仕組みがない

### 誤読を許したMD上の原因
- **`CLAUDE.md:221`**: 知見ファイル整合義務の発火条件が「既存スクリプトの動作・出力・依存関係を変更した場合」に限定されており、「プランに紐づく作業が完了/進捗した場合」をカバーしていない
- **memory `feedback_backfill_metrics_auto.md`**: 「087知見ファイルの該当バッチセクションを更新」のみ記載。「対応するプランMDの進捗も更新」への言及なし
- **`docs/plans/20260427_140000_tdnet_2017_2022_backfill.md:419-425`**: 後片付けチェックリストが存在するが、「各H完了時にこのセクションを確認すること」という参照トリガーが書かれていない

### 再発防止の方向性
1. CLAUDE.md §知見ファイル整合義務の発火条件を拡張し、「プランに紐づく作業が完了した場合、プランMDのステータス・進捗テーブルを更新する」義務を追加する
2. memory `feedback_backfill_metrics_auto.md` に「プランMDの進捗更新も含む」旨を追記する
3. プランMDテンプレートの「後片付け」セクションに「各マイルストーン完了時にこのチェックリストを確認すること」の注記を追加する
