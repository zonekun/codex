## 【パターン 2: 原因分析】

### 1. 事象

Codex側からClaude Code側へ887行のPythonスクリプトを取り込む際、同じ作業でプランMD・CSV・HTMLはCopy-Itemでコピーしたにもかかわらず、スクリプトだけReadで全文読み込み→Writeで書き出し。入力+出力トークンを二重消費。

### 1.5. AIの思考回路（推定）

1. Codex取り込み指示を受ける
2. 083の取り込み方式を参照。cherry-pick不可の場合のフォールバックとして「ファイルコピー」を選択
3. スクリプトファイルについては**内容を確認・レビューする意図**からReadを実行
4. Read結果がコンテキストに載った状態で、Copy-Itemではなく**そのままWriteでコピー先に書き出し**
5. 「Read→Write」も「ファイルコピー」の一形態と判断（誤り）

**分岐点**: ステップ4で「Readで確認した後、コピーはCopy-Itemで別途実行する」と判断すべきだった。Readの目的（内容確認）とコピーの手段（OS操作）を分離する判断基準が存在しなかった。

### 2. 直接原因

- 「内容確認のためのRead」と「コピー操作」が一連の流れで実行され、Read結果をそのままWriteに流す方が手順として短いと判断した
- Copy-Itemに切り替えるべきという明示的なルールが083・004のいずれにも存在しない

### 3. 根本原因

- **ツール選択基準の不在**: 「ファイルの内容を移動・複製する」操作について、OSコマンド（Copy-Item/cp）と Read+Write の使い分け基準がどの知見MDにも定義されていない
- 083の「ファイルコピー / 手動編集」は方式名のみで、具体的な実行手段（Copy-Item/cp）が記載されていない

### 4-1. MD上の原因

- **083 L47**: 「ファイルコピー / 手動編集 | 最終手段」— 方式名だけで実行手段が曖昧。Read+Writeもファイルコピーの一形態と解釈可能
- **004 L348-369**: ファイル同期・コピー時の「内容種別検証」はあるが「手段選択」の基準がない

### 4-2. MD構成原因

083のCodex取り込みフローには、git操作（cherry-pick, patch）の具体的コマンドは記載されているが、フォールバックの「ファイルコピー」だけ具体性が欠如。AIは具体的コマンドが書かれていない操作について、手持ちのツール（Read+Write）で代替する傾向がある。

### 5. 再発防止

**083への追記**（記載先判定: Q1=Yes → 知見MD）:

083 §取り込み方式の優先順位のフォールバック（優先度3）に、以下の注記を追加:

> ファイルコピーは `Copy-Item`（PowerShell）または `cp`（Bash）で実行する。Read+Writeによるコピーはトークンを浪費するため禁止。Readは内容確認・レビュー目的のみに使用し、コピー操作とは分離すること。

**004への追記を検討したが不要と判断**: これはCodex取り込み固有の文脈であり、004の汎用コーディング規約に載せるとスコープ過剰。083に閉じた方が適切。

### 6. 新規リスク

083にCopy-Item/cp指定を追記した場合の副作用:
- Linux VM環境ではCopy-Itemが使えない → 「`Copy-Item`（PowerShell）または `cp`（Bash）」と両方記載で対応
- Read自体の禁止と誤読されるリスク → 「Readは内容確認・レビュー目的のみ」と明記して回避
