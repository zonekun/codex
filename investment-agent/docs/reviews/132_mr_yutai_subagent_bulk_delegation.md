# 運用事故報告: 株主優待フォーマット処理のサブエージェント一括委譲による品質劣化リスク

- 日時: 2026-05-09 JST
- 対象: 株主優待（yutai）フォーマット処理タスク（148件）
- パターン: 4（運用事故 — 自己の行動不備記録）
- 出力先: `docs/reviews/132_mr_yutai_subagent_bulk_delegation.md`

---

## 事象

株主優待情報のフォーマット処理（生テキスト → 098フォーマットルール適用 → 構造化JSONL出力）を148件に対して実施。

- **前半87件**: メインセッションで1件ずつAIテキスト処理。各バッチをオペレーターがレビュー・フィードバック。フォーマットルールの解釈が会話を通じて校正（キャリブレーション）された
- **後半61件**: 「効率的」という判断でサブエージェントに一括委譲。1回のAgent呼び出しで61件をまとめて処理させた

ユーザーが即座にNGを指摘: **バッチ委譲されたサブエージェントの処理品質は、1件ずつオペレーターレビューを経た処理品質と同等とは言えない**。

## 根本原因

### 1. スループット優先のバイアス

87件の手動処理で「パターンが見えた」と判断し、残り61件を一括処理に切り替えた。しかし、株主優待のフォーマット処理は機械的変換ではなく、各銘柄の優待内容に応じたAI判断が伴うタスクである。パターン化できる部分と個別判断が必要な部分の見極めが不十分だった。

### 2. サブエージェントの構造的限界を軽視

サブエージェントには以下が欠落しており、メインセッションと同等の処理品質を保証できない:

- **オペレーターフィードバックの蓄積**: 87件の処理を通じてオペレーターが行った修正指示・微調整・「こういう場合はこう」という暗黙の校正がサブエージェントに伝わらない
- **会話コンテキスト**: メインセッションで蓄積された098フォーマットルールの解釈経験、エッジケースの処理例、「この表現はOK/NG」の判断基準がサブエージェントにない
- **逐次フィードバックループ**: メインセッションでは各バッチ後にオペレーターが目視確認→修正指示→次のバッチに反映、というサイクルが回っていた。サブエージェントでは61件が一括処理され、途中での軌道修正ができない

### 3. 月次開示パイプラインの教訓未適用

月次開示（月次adapter整合・BC突合）で繰り返し発生した同パターンの事故: 「効率化」のためにバッチ処理・一括委譲に切り替えた結果、体系的なエラーが発生し、手戻りコストが当初の手動処理コストを上回った。この教訓が株主優待タスクに適用されなかった。

## 影響

- 61件の処理品質が不確定。検証・手直しが必要
- ユーザーの信頼低下: 「また同じことをやっている」
- 月次開示の教訓が行動に反映されていないことの露呈

## 再発防止ルール

### 追加すべきルール: AI判断を伴う反復処理のサブエージェント一括委譲禁止

**N件（N>=3）のアイテムに対してAIテキスト処理・判断を行うタスクでは、サブエージェントへの一括委譲を禁止する。** 各アイテムをメインセッション内で同一のアプローチで処理し、オペレーターのフィードバックループを維持すること。

**適用対象**:
- 株主優待フォーマット処理
- adapter調査・修正（1社ずつPDF読んで逆引き）
- NG分析・分類
- 決算短信の構造読み取り
- その他、品質がオペレーターの校正・会話コンテキストに依存するタスク

**禁止行動**:
- 「パターンが見えた」「残りは単純」等の理由でサブエージェントに残件を一括委譲する
- Agentツールで複数件をまとめて処理させる（1件1回のAgent呼び出しも同様 — コンテキストが引き継がれないため）
- 「効率化」を理由にオペレーターレビューサイクルをスキップする

**機械的変換との区別**:
- 機械的変換（正規表現置換、フォーマット変換、列名リネーム等、判断が不要な処理）はバッチ処理・スクリプト化が適切
- **判断基準**: 「このアイテムの処理結果が、直前のアイテムの処理経験によって変わりうるか？」 → Yes ならAI判断タスク、サブエージェント委譲禁止

**関連ルール**:
- CLAUDE.md §AI手動反復処理の逐次永続化義務 — 永続化の義務（1件1永続化）。本ルールは委譲の禁止（同一セッション内処理の義務）であり、補完関係
- `feedback_no_shortcut_investigation.md` — 同じ原則: 1社ずつ処理、バッチ・推定・Gemini逃げ禁止
- 月次開示パイプラインの手戻り事故群 — バッチ処理・一括委譲による品質劣化の先行事例

  1. **メインセッション内で処理**: サブエージェント（Agentツール）への一括委譲を禁止。サブエージェントにはオペレーターフィードバックの蓄積・会話コンテキスト・逐次校正が引き継がれない
