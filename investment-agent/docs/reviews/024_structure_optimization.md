### RD-1: ライン会話モードの「状態遷移モデル」の明示的設計

- 元指摘: 020 重大#2, 021 重大#1/#3 -- 相互作用問題（統合過程で発見）
- 箇所: `CLAUDE.md:92-108` 全体
- 改善方針: 6件の事故を俯瞰すると、根本にあるのは「ライン会話モードがどの状態にいるか」のモデルが暗黙的であること。CLAUDE.mdは「ルールの箇条書き」で動作を規定しているが、AIは複数ルールの優先順位を文脈依存で判断する必要があり、L100（非同期フロー）とL107（コンテキストクリア待機）の競合（021事故）はその典型。

  明示的な状態遷移:
  ```
  [通常モード] --発動宣言--> [LINE会話中: 同期ループ]
  [同期ループ] --サブタスク起動--> [非同期待ち: 中間報告済み]
  [非同期待ち] --サブタスク完了--> [同期ループ: 最終報告]
  [同期ループ] --コンテキストクリア指示--> [クリア待ち: /clear案内済み]
  [クリア待ち] --BG完了通知--> [出力読み取り→クリア待ちに戻る or 指示変更で同期ループに復帰]
  [クリア待ち] --クリア完了--> [同期ループ]
  [任意状態] --終了宣言--> [通常モード]
  ```

  これをCLAUDE.mdに図として追加することで、「現在どの状態にいるか」に基づいて次のアクションを一意に判断できるようになる。ただし、CLAUDE.mdのトークン増加（推定+15行）と、状態遷移図の維持コストを考慮する必要がある。

  **現時点での推奨**: Rebuild レベルの変更は即実行ではなく、SR-1のルール節再構成を先行実施し、それでも同種事故が再発した場合に状態遷移モデルの導入を検討する段階的アプローチを推奨

- 影響度: 高（AI迷走リスクの構造的排除。ただしトークン増加と維持コストのトレードオフあり）
