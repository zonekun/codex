## 【パターン 2 のみ: 誤読・ミス原因分析】

### 事象
前回レビュー007の重大指摘 #1 で「memoryファイルの接続コマンドに `--tunnel-through-iap` を追加」と推奨した。しかしこの推奨は表層的な対症療法であり、根本原因である「memoryに知見MDの情報を複製していること」を放置していた。ユーザーが正しく指摘した通り、修正すべきだったのは「memoryからコマンドを削除し、知見MDへのポインタだけにする」だった。

### 読み手がどう解釈した可能性があるか
- 007レビューの読み手（AI）は「memoryにフラグを足せば直る」と解釈し、今後も同種の乖離が発生した際に「memoryの方を修正する」パターンを踏襲する可能性がある
- 「知見MDとmemoryで同じ情報を二重管理しても、両方を正しく保てばよい」という誤ったメンタルモデルを補強しかねない

### 直接原因
007レビューが「memoryにIAPフラグがない → memoryに足す」という直接的な差分修正に走り、「なぜmemoryにコマンドが書かれているのか」という構造的な問いを立てなかった。

### 根本原因
1. **レビュースキルに「情報の正本はどこか（Single Source of Truth）」を問う観点がない**: md-reviewerのStep 6（指示優先順位・文脈境界レビュー）は複数MD間の衝突を見るが、「そもそもこの情報はこのファイルに置くべきか」という正本帰属の判断基準がない
2. **CLAUDE.mdのmemory制約（L535）と007レビューの推奨が矛盾していた**: 「メモリは行動ルール・ユーザー情報・プロジェクト進捗の概要ポインタのみ」というルールがあるのに、007レビューはmemoryにコマンド（=操作手順の詳細）を追加することを推奨した。レビュー時にこの上位ルールとの整合性チェックが抜けた
3. **既存フィードバック `feedback_memory_usage.md` との照合が抜けた**: 「コードを読めば分かることはmemoryに書かない」という既存ルールが適用されるべきだったが、007レビュー時に参照されなかった

### 誤読を許した MD 上の原因

| 箇所 | 問題 |
|------|------|
| `docs/reviews/007_vm_ssh_iap_misread.md:102` | 「memoryファイルの修正が最優先」と記載。修正の方向を「フラグ追加」としたが「コマンド削除+ポインタ化」とすべきだった |
| `docs/reviews/007_vm_ssh_iap_misread.md:111-119` | 重大指摘#1が「memoryにフラグを追加」。CLAUDE.md L535のmemory制約との整合性未検証 |
| `docs/reviews/007_vm_ssh_iap_misread.md:171-174` | ソースコード・仕組み側への波及がmemoryファイルの「修正」に留まり、「複製の排除」に踏み込めていない |
| `skills/md-reviewer.md` Step 6 | 「情報の正本帰属」を問う観点がレビュープロセスに組み込まれていない |

### 再発防止の方向性
1. **007レビューMDに追記**: 重大指摘#1が誤推奨であったこと、正しい対応は「コマンド削除+ポインタ化」であったことを追記する
2. **一般ルール化の検討**: 「memoryに知見MDの詳細情報を複製しない。memoryはポインタのみ」というルールを、既存の `feedback_memory_usage.md` に追記するのが自然

## 【重大な指摘】（即修正）

### #1 007レビューの重大指摘#1が誤推奨のまま残存
- 箇所: `docs/reviews/007_vm_ssh_iap_misread.md:111-119`
- 問題: 重大指摘#1が「memoryファイルの接続コマンドに `--tunnel-through-iap` を追加」と推奨しているが、これは対症療法であり、正しい推奨は「memoryからコマンドを削除し知見MDへのポインタだけにする」

- 推奨対応: 007レビューMDの末尾に追記セクションを設け、重大指摘#1が誤推奨であったこと、実施された正しい対応（コマンド削除+ポインタ化）を記録する
