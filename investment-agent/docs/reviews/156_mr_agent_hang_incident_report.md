## 【AI 誤読リスク】

### R-1: 「既存原則で十分」が対処療法の隠蔽になるリスク

`155_ir:68-73` — 再発防止策 #1, #2, #4 が「既存原則で十分」で閉じている。

AIがこのMDを読んだ場合、「既存ルールを再確認すれば再発しない」と解釈する。しかし、CLAUDE.md §4.1（確認優先）と §4.2（ユーザー指示優先）は今回事故の時点で既に存在しており、それでも違反が発生した。「既存原則で十分」という結論は、既存原則が**認知されていたにもかかわらず適用されなかった**理由を説明しない。

### R-2: 「追記検討」の曖昧さ

`155_ir:73` — 再発防止策 #3「085_crash_recovery.md に追記検討」

「検討」は操作動詞として曖昧（md-reviewer Step 4の重点確認対象）。AIは「検討する」を「やらなくてもよい」と解釈する余地がある。追記するなら具体的な追記内容を示すべき。

### R-3: タイトルと内容のスコープ不一致

タイトルは「サブエージェントハング後の対応失敗」だが、内容は「メインエージェントの対応失敗5件」に限定されている。サブエージェントがハングした根本原因（Grepディレクトリ全体検索）への対策は100知見MDに記載されているが、本MDからの明示的なポインタがない。AIが本MDだけで事故全体を理解しようとすると、ハング防止策を見落とす。

## 【MD 構成リスク】

### S-1: 対応失敗5件のフラット列挙

#1〜#5が独立に列挙されているが、共通する根本パターンの統合分析がない。例えば:
- #1と#2は「確認前の断定」という同じ思考パターン
- #2と#3は「知見MD・ログの参照省略」という同じ行動パターン
- #4は#1の結果として派生

これらが統合されていないため、AIは「5つの独立した問題がある」と解釈し、個別対策を5つ立てようとする。実際には2-3の根本行動パターンに集約できる。

### S-2: 根本原因分析の3項目と対応失敗5件の対応関係が不明

根本原因 1-3 と 対応失敗 #1-#5 のどれがどれに対応するか、マッピングが明示されていない。

## 【指示優先順位・文脈境界】

### P-1: 100_agent_stuck_recovery.md との責務分担

本MD（155_ir）は「メインエージェントの対応失敗」を記録し、100知見MDは「サブエージェント詰まり復旧手順」を記載する。この責務分担自体は妥当だが、本MDから100知見MDへの明示的ポインタが再発防止策 #1 にしかない。

根本原因セクションの「100_agent_stuck_recovery.md は存在したが、メインエージェントが参照しなかった」（L62）は重要な指摘だが、**なぜ参照しなかったか**の分析がない。CLAUDE.md §10 の知見索引に100知見MDへの導線は登録されているか？

確認: CLAUDE.md §10 の高頻度参照テーブルに「サブエージェント詰まり」「ハング」「中断」のエントリは存在しない。100知見MDは2026-05-12に作成されたばかりであり、CLAUDE.md索引への未登録が「参照しなかった」一因である可能性がある。ただし本事故は100知見MD作成のきっかけとなった事故そのものであるため、事故時点で100知見MDが存在しなかったのは当然。この点は本MDで明確にすべき。

### P-2: 085_crash_recovery.md との関係

再発防止策 #3 で「085_crash_recovery.md に追記検討」とあるが、085は「クラッシュ後の作業再開」であり、「サブエージェント中断後の復旧」とはスコープが異なる。085は`list_claude_sessions.py`ベースのセッション復元手順であり、サブエージェントのJONLログ探索は100知見MDの責務。追記先として085が適切かどうか再考が必要。

具体的には: 085の §手順 は「セッション一覧表示 → ログ読み → active_jobs確認」であり、サブエージェント中断という状態に対応するステップがない。「コンテキスト圧縮後、作業文脈が不明な場合はセッションログを読んで復元する」（CLAUDE.md §5）の延長として、圧縮後にサブエージェント稼働状況を確認するステップを追加するなら085の拡張は妥当だが、その場合は100知見MDとのクロスリファレンスが必要。

## 【重大な指摘】（即修正）

### #1 再発防止策が「既存原則で十分」で閉じ、構造的強制への踏み込みがない

- **箇所**: `155_ir:68-73`（再発防止策テーブル全体）
- **問題**: 5件中3件が「既存原則で十分」。しかし CLAUDE.md §4.1（確認優先）は以前から存在し、behavior:unverified-claim は 004-1 蓄積ログに MR-035/073/119/129/142 と**5回以上**記録されている同型違反。「既存原則で十分」は繰り返し破られてきた原則の再周知にすぎず、対処療法。
- **AIの誤読パターン**: AIがこのMDを読んで「ルールは既にあるので追加対策不要」と判断し、次回同じ状況で同じ失敗を繰り返す
- **トリガー**: サブエージェント中断後にメインエージェントが復旧を試みるとき
- **影響**: 同型事故の再発
- **根拠**: 004-1 の behavior:unverified-claim エントリが複数回蓄積されている事実は、意志依存型ルールの限界を示している
- **推奨対応** [方向性]: 再発防止策に「なぜ既存原則が今回機能しなかったか」の分析を追加し、意志依存を超える対策（例: サブエージェント中断検知時のチェックリスト化、100知見MDへの自動導線）の方向性を記載する。具体的な仕組み設計は本MDのスコープ外だが、「既存原則で十分」で閉じないこと
- **MD修正だけで足りるか**: 本MD単体の修正では不十分。CLAUDE.md §10 に100知見MDへの導線追加、および085知見MDに圧縮後サブエージェント確認ステップの追加が必要

### #2 対応失敗5件の因果連鎖・共通パターンが未統合

- **箇所**: `155_ir:24-58`（対応失敗の詳細 #1〜#5）
- **問題**: 5件がフラットに列挙されているが、共通する行動パターンの統合分析がない。#1(確認前行動)→#2(虚偽断定)→#3(指示無視)は連鎖しており、根底には「自身の推測を外部証拠より優先する」という単一の行動パターンがある。#5(圧縮後文脈喪失)は独立した構造的問題。この区別がないと、AIは5つの独立した問題に5つの独立した対策を立てようとする
- **AIの誤読パターン**: 「5つの別々の問題がある」と解釈し、個別対症療法を量産
- **トリガー**: 本MDを参照して再発防止策を実行するとき
- **影響**: 根本行動パターンへの介入ではなく、個別症状への対策になり、次の変種で再発
- **根拠**: 根本原因分析 #3「ユーザー報告より自身の推測を優先した」が #1, #2, #3 の共通根本だが、対応失敗セクションでは各件が独立に「違反原則」を持つ構成
- **推奨対応** [方向性]: 対応失敗セクションの後に「共通行動パターン分析」節を追加し、(A)「確認前断定」パターン(#1,#2,#4が該当)、(B)「指示・知見MD参照省略」パターン(#3が該当)、(C)「圧縮後文脈喪失」パターン(#5が該当) に統合する
- **MD修正だけで足りるか**: 本MD内の構成改善で対応可能

### #3 AIの思考回路再構成が欠落

- **箇所**: `155_ir:24-58` 全体
- **問題**: 各対応失敗に「違反原則」「正しい対応」はあるが、「なぜAIがその行動を正しいと判断したか」の思考回路再構成がない。事故報告としてはパターン2のmd-reviewerフォーマット（§1.5 AIの思考回路）に相当する分析が必要。例えば#2「一度も起動していません」と断定した際、AIはどのような情報（権限プロンプトの記憶？）を根拠に判断し、なぜsubagentsディレクトリの確認を省略したのか
- **AIの誤読パターン**: 思考回路が不明なため、「何をしたか」は分かるが「どの判断分岐で誤ったか」が分からず、次回同じ判断分岐に到達しても修正できない
- **トリガー**: 類似状況（サブエージェント中断後の状態確認）で再びAIが判断を迫られるとき
- **影響**: 誤判断の分岐点が特定されないため、同じ思考パスで同じ結論に至る
- **根拠**: md-reviewer スキル §パターン2 必須評価項目 1.5「AIの思考回路」が事故分析の標準フォーマット
- **推奨対応** [方向性]: 各対応失敗に「推定される判断チェーン」を追記。特に#2は「権限プロンプト却下の記憶 → サブエージェント未起動と推論 → subagents確認を省略」という因果を明示すべき
- **MD修正だけで足りるか**: 本MD内の追記で対応可能
