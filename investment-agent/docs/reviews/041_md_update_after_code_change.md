# ソースコード改修後の関連MD更新漏れ — ユーザー指摘まで気づかなかった

- 提出日: 2026-04-30 JST
- パターン: 2（誤読・ミス報告に対する改善レビュー）
- 報告者: メインエージェント

---

## 事象

コンセンサス取得スクリプト2本（`update_conse_ifis.py`, `update_conse_rakuten.py`）のCSV出力ロジックをBQ VIEW経由に改造した。改造完了後、「MDファイル更新」としてコーディング規約MD（`004_coding_conventions.md`）にlib_*.pyの命名規則を追記した。

しかし、直接関連する知見ファイル `022_consensus_load.md` の更新は行わなかった。ユーザーが「コンセMDに記載すべき事項はない？」と指摘して初めて確認・更新した。

### 更新すべきだった内容

1. 関連ファイルに `lib_conse_csv_from_view.py` を追加
2. CSV副本の説明をVIEW経由に変更
3. CSV出力セクションの新設（仕組みの変更を記載）

### 会話ログ（該当部分）

```
AI: 完了。変更まとめ：（3ファイルの変更サマリ）

ユーザー: MDファイル更新 libの保管場所、ネーミングもついでに記載

AI: （004_coding_conventions.md にlib_*.py規約を追記）

ユーザー: コンセMDに記載すべき事項はない？

AI: ある。以下を更新すべき：
  1. 関連ファイルに lib_conse_csv_from_view.py 追加
  2. L54 の CSV副本の説明を更新
  3. CSV出力の仕組みが変わったことの記載
```

## 根本原因

スクリプト改修 → 完了報告の流れで、関連知見MDの更新チェックを自発的に行わなかった。CLAUDE.md の知見管理セクションには「知見ファイル・スキル・MDの追加・移動・リネーム時はINDEX.md更新」の義務があるが、**既存スクリプトの動作変更時に対応する知見MDも更新する**という義務が明文化されていなかった。

ただし、明文化の有無に関わらず、スクリプトの動作を変えたら対応する知見MDの記述が陳腐化するのは自明であり、自発的に気づくべきだった。

## 再発防止

スクリプト改修完了時に以下をセルフチェックする：

1. `docs/knowledges/INDEX.md` で改修対象スクリプトに紐づく知見ファイルを特定
2. 知見ファイルの記述が改修後の動作と矛盾していないか確認
3. 矛盾があれば知見ファイルも更新する

## AI可読性レビュー追記: 2026-04-30 14:07 JST -- md-reviewer

パターン: 2（誤読・ミス報告に対する改善レビュー）

### 1. 事象の記述について

事象の記述は正確かつ十分。会話ログの引用により、AIが自発的にコンセMD更新に気づかず、ユーザーの「コンセMDに記載すべき事項はない？」という問いかけで初めて認識した経緯が明確に再現されている。更新すべきだった3項目も具体的で、「何が漏れたか」の解像度は高い。

### 2. 根本原因の分析について

根本原因の分析は**概ね妥当だが、1段浅い**。

提出MDは「CLAUDE.mdに明文化されていなかった」を主因に挙げつつ「明文化の有無に関わらず自明」と補足している。この補足は正直だが、**なぜ「自明」なことを実行しなかったのか**の分析が欠けている。

具体的に不足している分析:

- **改修完了時の認知フロー**: コード改修が完了した時点でAIの注意は「完了報告」に向かっている。この時点で「関連するドキュメントは？」という逆方向の思考を自発的に起こすには、明示的なトリガーが必要。ユーザーが「MDファイル更新」と指示した時点でも、指示された004のみに注意が向き、022まで展開しなかった。これは**指示駆動で動くAIの特性**（指示されたことはやるが、指示されなかったことは漏れやすい）を示しており、「自明」で片付けるべきではない
- **INDEX.mdの逆引き不在**: INDEX.md §導線チェックリストは「ファイル追加・移動・名前変更時」のチェックリストであり、「**既存スクリプトの動作変更時**」をカバーしていない。AIがINDEX.mdを参照しても、今回のケース（既存スクリプトの改修）ではチェックリストが発火しない。これはMD構造の欠陥であり、AIの注意力の問題に帰着させるべきではない

### 3. 再発防止策について

提出された3ステップのセルフチェックは方向性として正しいが、**実効性に疑問がある**。

**問題点**:

- **「セルフチェックする」という再発防止策は、今回の事故そのものの繰り返し**。AIは今回も「セルフチェックすべきだった」のにしなかった。同じ認知レベルの対策を繰り返しても、次回も同じ理由で漏れる。AIに「気をつける」と約束させても、それは仕組みではない
- **発火タイミングの曖昧さ**: 「スクリプト改修完了時に」とあるが、AIが「完了」と判断するタイミングは様々（コード修正完了、テスト完了、commit完了、ユーザーへの報告完了）。どの時点でチェックを挟むかが不明確
- **チェック対象の特定方法が未定義**: ステップ1「INDEX.mdで改修対象スクリプトに紐づく知見ファイルを特定」は正しいが、INDEX.md側にスクリプト名→知見ファイルの逆引きマッピングが整備されていない前提で、AIがどうやって「紐づく」知見を特定するのかが不明

**実効性のある対策の方向性**:

(A) **CLAUDE.md §知見管理に明文ルールを追加**: INDEX.md更新義務（L216）の直後に、「**既存スクリプトの動作・出力・依存関係を変更した場合も、対応する知見ファイルの記述を確認・更新すること**」を追加する。現在のINDEX.md更新義務は「追加・移動・リネーム時」のみで、「既存ファイルの動作変更時」をカバーしていない

(B) **INDEX.md §導線チェックリストに項目追加**: 現在の7項目は全て「ファイル追加・移動・名前変更時」が対象。8項目目として「[ ] **既存スクリプト改修**: 改修したスクリプトに紐づく知見ファイル（INDEX.md §タスク別索引で特定）の記述が改修後の動作と整合しているか」を追加する

### 4. CLAUDE.md / 知見ファイルへの反映提案

**CLAUDE.md L216 への追記案**:

現状:
```
> **INDEX.md 更新義務**: 知見ファイル・スキル・MDの追加・移動・リネーム時は INDEX.md §導線チェックリスト（7項目）に従い関連セクションを更新すること
```

提案:
```
> **INDEX.md 更新義務**: 知見ファイル・スキル・MDの追加・移動・リネーム時は INDEX.md §導線チェックリスト（7項目）に従い関連セクションを更新すること
> **知見ファイル整合義務**: 既存スクリプトの動作・出力・依存関係を変更した場合、INDEX.md §タスク別索引で対応する知見ファイルを特定し、記述が改修後の実態と整合しているか確認・更新すること
```

**INDEX.md §導線チェックリスト への項目追加案**:

```
8. [ ] **既存スクリプト改修**: 改修したスクリプトに紐づく知見ファイルの記述が改修後の動作と整合しているか
```

この2箇所への反映により、「ファイルの追加・移動・リネーム」と「既存コードの動作変更」の両方がカバーされ、AIが改修完了時にチェックリストを参照する導線が確保される。「セルフチェックする」という認知的対策ではなく、既存のチェックリスト機構に項目を追加するという仕組みベースの対策になる。

### 総括

提出MDは事象の記述と率直な自己分析は適切だが、根本原因の掘り下げが1段足りず、再発防止策が認知レベルの「気をつける」に留まっている。CLAUDE.mdとINDEX.mdに明文ルールを追加し、既存のチェックリスト機構に組み込むことで、AIの注意力に依存しない仕組みベースの対策とすべき。
