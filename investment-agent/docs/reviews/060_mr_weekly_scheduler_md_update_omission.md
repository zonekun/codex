# MR-060: 週次AI Scheduler設定時のMD更新漏れ

**種別**: 運用事故（ドキュメント陳腐化）
**発生日**: 2026-05-02
**検知**: ユーザー指摘（「適宜のMDファイル更新要」）
**影響**: 知見ファイルが事実と乖離した状態で残存

---

## 事象

`tdnet-ai-weekly` Cloud Scheduler 作成 + `ai_processing_flow` に `recent_only` パラメータ追加を実施。以下の作業を完了した:

1. ワークフロー改修（`recent_only` パラメータ、switch分岐追加）
2. Cloud Scheduler 作成（`tdnet-ai-weekly`、毎週土 07:00 JST）
3. デプロイ完了

しかし、ユーザーが「適宜のMDファイル更新要」と明示的に指示するまでMD更新を行わなかった。

## 更新が必要だったファイル

| ファイル | 更新内容 | 陳腐化の深刻度 |
|---------|---------|-------------|
| `docs/knowledges/tools/013_tdnet_load.md` | 「⚠️ 残課題: Scheduler 未設定」→「✅ 設定済み」、現況サマリ、定期スケジューラ化セクション全面書き換え | **高** — 次セッションが「未設定」を前提に行動する |
| `workflows/ai_processing_flow.yaml` ヘッダーコメント | 起動方法・パラメータ一覧に `recent_only` 追記 | 中 — コード読解時に混乱 |

## 根本原因

GCPリソース変更（Scheduler作成・Workflow改修・デプロイ）のタスク完了に集中し、CLAUDE.md §知見ファイル整合義務のチェックを省略した。変更完了時に「関連知見ファイルの整合性確認」ステップを自発実行しなかった。

## 違反したルール

- CLAUDE.md §知見管理: 「知見ファイル整合義務: 既存スクリプトの動作・出力・依存関係を変更した場合、対応する知見ファイルの記述が実態と整合しているか確認・更新すること」

## 再発防止策

**GCPリソース変更時のドキュメント整合チェック義務**:

GCPリソース（Cloud Scheduler / Cloud Run Job / Workflows / Cloud Functions）を変更・作成・削除した場合、変更完了直後に以下を自発実行する:

1. `docs/knowledges/INDEX.md` §タスク別索引で該当知見ファイルを特定
2. 知見ファイル内の「現況サマリ」「ステータス」「残課題」セクションが実態と整合しているか確認
3. 乖離があれば即時更新（ユーザー指示を待たない）
4. コード内のドキュメンテーションコメント（ヘッダー等）も同時更新

**判定基準**: 「次のセッションがこの知見ファイルを読んだとき、現在のGCP状態と矛盾しないか？」
