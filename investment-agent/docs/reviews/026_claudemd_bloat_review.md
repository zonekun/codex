## 【推奨検証（Step 8）】

### 正本帰属チェック（8a）

- 推奨#1（索引テーブル外部化）: 索引テーブルの正本は外部化後のファイルに移動。CLAUDE.mdは高頻度エントリのサブセットのみ保持する「キャッシュ」的位置づけになる。正本が2箇所に分裂しないよう、CLAUDE.md側の記述を「索引テーブル全体は`docs/knowledges/INDEX.md`が正本」と明記する必要がある
- 推奨#2-#6: いずれも「ポインタ化」（詳細を外部に移し、CLAUDE.mdはリンクのみ保持）であり、正本帰属は外部ファイルに移動。CLAUDE.mdが正本ではなくなることを明記する必要がある

### 上位ルール整合性（8b）

- 推奨とCLAUDE.md自身のルールの整合: CLAUDE.md L559「知見ファイルは最後まで読む」ルールは、索引テーブル外部化後も有効。外部化によりCLAUDE.mdは短縮されるが、参照先の知見ファイルを読む負荷は変わらない
- CLAUDE.md L544「調査結果のメモリ保存厳禁」: 推奨は外部化であり、memoryへの移動は含まないため整合
- **CLAUDE.md自体に対する指摘（8b特記）**: 本レビューはCLAUDE.md自体の肥大化を問題として指摘している。CLAUDE.mdは最上位ルールファイルだが、「CLAUDE.mdは最小限であるべき」というメタルールはCLAUDE.md自身に記載されていない。structure-optimizerへの後続作業として、CLAUDE.mdの冒頭に「本ファイルの方針: 方針・制約・禁止事項に限定。手順詳細・実装詳細は知見ファイルに委譲」というメタルールの追加を推奨する

### 副作用シミュレーション（8c）

**(i) 単体副作用**:
- 索引テーブル外部化後、AIが「CLAUDE.mdに索引がない → 索引を確認しなくてよい」と誤認するリスク。対策: CLAUDE.mdに「タスク受領時は必ず`docs/knowledges/INDEX.md`を確認せよ」の命令を残す
- クラッシュ復旧手順外部化後、AIがクラッシュ復旧指示を受けた際に知見ファイルを読みに行く1ステップが追加される。ただし、クラッシュ復旧は低頻度（月数回）であり、1ステップ追加の影響は軽微

**(ii) クロスルール競合**:
- 推奨#1で索引テーブルを外部化した場合、L327「まず以下の索引テーブルで該当知見を特定する」のルールは「まず`docs/knowledges/INDEX.md`で」に書き換わる。feedback memory `feedback_claudemd_index_first.md` の「CLAUDE.md索引」という表現との整合性を更新する必要がある
- 推奨#3でstall検知を外部化した場合、L37-54の「監視する/見張る」定義の「必ずプロセスを立ち上げる」ルールは残る。stall検知は「プロセスを立ち上げた後の品質要件」であり、方針ルールと矛盾しない

**(iii) 状態依存シナリオ**:
- ライン会話モード中にクラッシュ復旧が必要になった場合: 復旧手順が外部化されても、LINE会話モードのルール（L92-112）はCLAUDE.mdに残るため、復旧作業中もLINE経由で応答するルールは維持される。競合なし

### 事後確認事項（8d）

- 索引テーブル外部化後、AIが新規タスク受領時に外部索引を確実に参照しているか（019事故の再発チェック）
- クラッシュ復旧手順外部化後、AIがクラッシュ復旧指示時に知見ファイルを読みに行けているか
- ポインタ化後、AIがポインタ先のファイルを「最後まで読む」ルール（L559）を遵守しているか
- 外部化で削減されたトークン量と、外部ファイル参照の追加トークン量のバランスが実際に改善しているか
