- **箇所**: `bq_fin_summary.md` L268-269 vs L285 vs L388

## 【パターン 4: 原因分析】

### 事象

`STOCK.fin_summary` の Cloud Scheduler が2つ（02:00 JST / 17:00 JST）に設定されていたが、データカタログには「毎日21:00 JST」と記載されていた。005知見ファイルの既存Job一覧でもスケジュール欄が「未設定」だった。是正措置としてデータ収集フローセクションと005知見ファイルは修正されたが、`bq_fin_summary.md` のL285・L388に「毎日21:00」が残存している。

### AIの思考回路

Cloud Schedulerの作成・変更を実施した際の推定思考:
1. `gcloud scheduler jobs create` を実行 → 成功を確認
2. CLAUDE.md §知見ファイル整合義務「GCPリソース変更直後に対応知見MDを更新」は存在するが、feedback_gcp_md_sync.md への到達は memory 経由
3. memory の `feedback_gcp_md_sync.md` を参照しなかった、または参照したが「知見MDを更新」の対象を005知見ファイルのみと解釈し、データカタログMDを対象外と判断した可能性
4. 結果、Cloud Scheduler設定とドキュメントの乖離が放置された

### 直接原因

1. Cloud Scheduler作成時に `bq_fin_summary.md` と `005_cloudrun_job_deploy.md` のスケジュール記載を更新しなかった
2. 是正措置においても `bq_fin_summary.md` の全箇所を網羅的に確認せず、L285・L388の「毎日21:00」を見落とした

### 根本原因

1. **トリガー導線の弱さ**: CLAUDE.md → memory(`feedback_gcp_md_sync.md`) → 知見MD という到達経路は、コンテキスト圧縮後にmemoryが参照されない場合に断絶する。CLAUDE.md §知見ファイル整合義務は1行記述であり、具体的な更新対象ファイルの特定手順（data_catalog配下の該当MDを探す等）が含まれていない
2. **同一ファイル内の情報分散**: `bq_fin_summary.md` にスケジュール関連記述が3箇所あり、1箇所を修正しても残り2箇所の存在に気づきにくい構造
3. **是正時の網羅性チェック欠如**: 是正措置で「21:00」をファイル内検索すれば残存箇所を発見できたが、データ収集フローセクションのみ修正して完了とした

### MD上の原因

1. **`bq_fin_summary.md` L285** (`docs/data_catalog/bq_fin_summary.md:285`): 「期間（TO）: 毎日21:00 JST 自動更新」— データ収集フロー（L268-269）と矛盾。是正漏れ
2. **`bq_fin_summary.md` L388** (`docs/data_catalog/bq_fin_summary.md:388`): 「fin_summaryの更新（毎日21:00）」— 同上
3. **CLAUDE.md §知見ファイル整合義務**: 「GCPリソース変更直後に対応知見MDを更新」は原則として正しいが、更新対象の特定手順（知見MD + データカタログMD）が明示されていない

### MD構成原因

- `feedback_gcp_md_sync.md` は memory にあり、CLAUDE.md からの直接到達は §知見ファイル整合義務の1行のみ。この1行は「知見MD」としか書いておらず、データカタログMDも対象であることが読み取りにくい
- `bq_fin_summary.md` 内でスケジュール情報が3箇所に分散しており、正本が明示されていないため部分修正で矛盾が生まれる構造

### 再発防止

1. **`bq_fin_summary.md` L285・L388の是正**: 「毎日21:00」を実態に合わせて修正する。または正本（データ収集フローセクション）への参照に置き換える
2. **CLAUDE.md §知見ファイル整合義務の表現改善**: 「対応知見MDを更新」→「対応知見MD **および** data_catalog配下の該当MDを更新」に変更することで、データカタログが対象であることを明示化する（Q1: Yes — 005知見MDの手順追記で対応可能。ただしCLAUDE.md側の表現も改善の余地あり）
3. **005知見ファイル §⑦ への注記追加**: Scheduler作成手順の直後に「作成後、005既存Job一覧 + data_catalog配下の該当MDのスケジュール記載を更新すること」を追記

### 対策スコープ

- 対象MD固有fix（L285・L388修正）+ 005知見MD §⑦ への注記追加が最小スコープ
- CLAUDE.md §知見ファイル整合義務の文言微修正は、影響範囲が全GCPリソース変更に及ぶため、005知見MDへの追記で十分か要判断（Step 8b で検証）
