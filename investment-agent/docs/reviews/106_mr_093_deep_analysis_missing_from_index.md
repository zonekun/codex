## 【パターン 2: 誤読・ミス原因分析】

### 1. 事象

ユーザーが「決算じっくり分析について 今ある機能を一覧表示」と質問。AIはCLAUDE.md §高頻度参照テーブルから「決算」関連3件を返したが、093（決算じっくり分析）が欠落していた。

### 2. 読み手の解釈

AIは CLAUDE.md §知見管理の手順に忠実に従った:
1. 高頻度参照テーブルで「決算」を検索 → 3件ヒット
2. 「一致があれば即座に Read」→ 3件を回答として提示
3. INDEX.md フォールバックは「一致がなければ」条件が偽（3件あるため）→ 不発火

### 3. 直接原因

**CLAUDE.md 高頻度参照テーブルに 093 のエントリが存在しない**こと。

093 の作成コミット（`1b7e6ad`, 2026-05-03）を確認すると:
- INDEX.md には093エントリが追加されている（diff で確認済み）
- CLAUDE.md には変更なし

つまり、093 作成時に導線チェックリスト項目3「高頻度タスク: 週1回以上参照されるなら CLAUDE.md 高頻度参照テーブルに追加したか」が実行されなかった、または「まだ新設なので週1回の基準を満たさない」と判断された。

### 4. 根本原因

3層の根本原因が重なっている:

**(A) 導線チェックリストの判定基準が曖昧**

INDEX.md:195 の項目3:
> 高頻度タスク: 週1回以上参照されるなら CLAUDE.md 高頻度参照テーブルに追加したか

「週1回以上参照される」は**過去の実績**を見る基準であり、**新設ファイルには適用できない**。新設時点では参照実績がゼロのため、チェックリストを通過してしまう。

**(B) 高頻度参照テーブルの「高頻度」基準がanalysis/カテゴリに不利**

高頻度参照テーブルは tools/ 系（デプロイ・ETL・モニタリング等の日常オペレーション）に最適化されている。analysis/ は「ユーザーが特定テーマについて質問・分析依頼したとき」に必要になるファイルであり、参照頻度は tools/ より低いが、**参照時に到達できないと致命的**（今回の事象そのもの）。

**(C) ルックアップ手順の「部分一致で打ち切り」が安全側でない**

CLAUDE.md:207 の「一致があれば即座に Read。一致がなければ INDEX.md」は、高頻度参照テーブルの**完全性を前提**としている。しかし高頻度参照テーブルは網羅的ではなく「頻出の速引き」であるため、部分一致で打ち切ると漏れが生じる。

### 5. MD上の原因

| 箇所 | 問題 |
|------|------|
| CLAUDE.md:211-232（高頻度参照テーブル） | analysis/ カテゴリのエントリが0件。「決算じっくり分析」はおろか、BACKTEST_PASS済みの007(TOB)すら未登録 |
| CLAUDE.md:207（ルックアップ手順） | 「一致があれば即座に Read」が「部分一致で十分」と読める。「一覧表示」「全部」系の質問に対して INDEX.md を併せて参照する指示がない |
| INDEX.md:195（導線チェックリスト項目3） | 「週1回以上参照されるなら」が新設ファイルに適用不能。新設時の判定基準が欠落 |

### 6. MD構成原因

- CLAUDE.md 高頻度参照テーブル → INDEX.md のフォールバック導線は存在するが、フォールバック条件が「0件ヒットの場合のみ」と狭い
- 高頻度参照テーブルは「速引きキャッシュ」の位置づけだが、AIの実際の挙動ではキャッシュヒットした時点でバックエンド（INDEX.md）を参照しない。キャッシュの不完全性が直接的に回答の不完全性に直結する設計

### 7. 再発防止の方向性

**(a) 即修正**: CLAUDE.md 高頻度参照テーブルに 093 を追加

**(b) 構造的対策**: ルックアップ手順の改善 — 「一覧表示」「全部見せて」「機能一覧」等の網羅性が求められる質問に対しては、高頻度参照テーブルだけでなく INDEX.md も必ず参照するルールを追加

**(c) 導線チェックリストの判定基準改善**: 新設ファイル向けの基準追加。「過去実績が0でも、関連テーマの既存エントリが高頻度参照テーブルにあるなら、同テーブルに追加する」

### 8. 対策スコープ

今回は093固有の問題ではなく、analysis/ カテゴリ全体（16ファイル）が高頻度参照テーブルに不在という構造的問題。以下の対策はすべてCLAUDE.md / INDEX.md レベルの汎用的改善。
