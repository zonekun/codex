## 概要

決算反応モデル（059）は「翌日の株価方向」を予測する短期モデル。本ファイルは**決算内容そのものを深掘りし、中長期の投資判断材料を抽出する**ための分析フレームワーク。

翌日反応モデルでは捕捉できない（しかし市場が大きく評価する）構造的変化を扱う。

## 059反応モデルとの棲み分け

| 観点 | 059 翌日反応モデル | 093 じっくり分析 |
|------|-------------------|-----------------|
| 時間軸 | 翌営業日 | 中長期（数ヶ月〜） |
| 判断対象 | ヘッドラインOP/コンセ乖離/YoY | セグメント構成・事業構造・質的変化 |
| データ | J-Quants/BQ集計値 | 決算短信本文・説明資料・セグメント情報 |
| アウトプット | UP/NEUTRAL/DOWNスコア | 投資テーマ・ウォッチリスト候補 |

## 分析観点（順次追加）

### 1. セグメント構成変化

主力事業と成長事業の利益逆転、新セグメント台頭など。ヘッドラインの集計OPでは見えない事業構造の転換点。

**着眼点**:
- セグメント間の利益比率が前期比で大きく変動（例: 成長セグメントが主力を逆転）
- 新セグメント新設・旧セグメント統合
- セグメント別の利益率トレンド（売上横ばいでも利益率改善/悪化）

### 2. テーマ横断スクリーニング（BQベクトル検索+キーワード共起）

特定の投資テーマ（例: 生成AI半導体、光電融合）に関連する好業績銘柄を、TDNET決算資料のCHUNK_TEXTから網羅的に探す。業種分類では拾えない「隠れテーマ銘柄」（例: TOTOの半導体向けセラミック）の発掘に有効。

**手法**: 2段構え
- **Step 1（キーワード共起）**: CHUNK_TEXT内で「テーマワード」×「好調表現」が同一チャンクに共起するものを抽出
- **Step 2（ベクトル類似検索）**: テーマに関連するキーワード群をembeddingに変換し、BQ `ML.GENERATE_EMBEDDING` + `ML.DISTANCE` でコサイン距離の近いチャンクを検索。キーワードに明示的に書かれていない関連話題を意味的に拾う

**クエリテンプレート（Step 1）**:
```sql
SELECT DISTINCT t.TICKER, s.STOCK_NAME, t.DOC_TITLE, t.MAIN_CATEGORY, t.SUBMISSION_DATE
FROM `gmailpj-357912.STOCK.TDNET_DOCUMENTS_ENHANCED` t
LEFT JOIN `gmailpj-357912.STOCK.STOCK_CODE_LIST` s ON t.TICKER = s.TICKER AND s.EXCHANGE = 'TSE'
WHERE SUBMISSION_DATE BETWEEN @start_date AND @end_date
  AND MAIN_CATEGORY IN ('決算短信', '決算説明資料')
  AND REGEXP_CONTAINS(CHUNK_TEXT, @theme_keywords)
  AND REGEXP_CONTAINS(CHUNK_TEXT, r'増収|増益|好調|堅調|伸長|拡大|過去最高|上方修正|大幅増|順調|上振れ|上回')
ORDER BY SUBMISSION_DATE, TICKER
```

**クエリテンプレート（Step 2）**:
```sql
WITH query_emb AS (
  SELECT ml_generate_embedding_result AS emb
  FROM ML.GENERATE_EMBEDDING(
    MODEL `gmailpj-357912.STOCK.embed_model`,
    (SELECT @theme_query_text AS content),
    STRUCT(TRUE AS flatten_json_output)
  )
)
SELECT t.TICKER, s.STOCK_NAME, t.DOC_TITLE, t.SUBMISSION_DATE,
       ROUND(ML.DISTANCE(t.EMBEDDING, q.emb, 'COSINE'), 4) AS cosine_dist
FROM `gmailpj-357912.STOCK.TDNET_DOCUMENTS_ENHANCED` t, query_emb q
LEFT JOIN `gmailpj-357912.STOCK.STOCK_CODE_LIST` s ON t.TICKER = s.TICKER AND s.EXCHANGE = 'TSE'
WHERE t.SUBMISSION_DATE BETWEEN @start_date AND @end_date
  AND t.MAIN_CATEGORY IN ('決算短信', '決算説明資料')
  AND t.EMBEDDING IS NOT NULL
  AND ML.DISTANCE(t.EMBEDDING, q.emb, 'COSINE') < 0.40
ORDER BY cosine_dist ASC
LIMIT 50
```

**BQコスト目安**: Step 1 + Step 2合計で1週間分 $0.05以下。`ML.GENERATE_EMBEDDING` のクエリ1回は実質無料（~200文字）。コストの大部分はEMBEDDING列スキャン。

**前提**:
- `embed_model`（BQ ML remote model、text-embedding-004）がSTOCKデータセットにデプロイ済み
- SAに `roles/bigquery.connectionUser` 権限が付与済み（vertex_ai_conn経由）
- EMBEDDINGは決算短信・決算説明資料・月次開示の3カテゴリのみ付与。業績修正・業績予想はNULL

**スクリプト実装**: `scripts/093_deep_analysis_screener.py`（BQ実行→マージ→CSV出力を自動化。トークン削減用）

**結果表示フォーマット（2表構成）**:

| 列名 | 内容 |
|------|------|
| Ticker | 銘柄コード |
| 銘柄名 | STOCK_CODE_LIST.STOCK_NAME |
| 時価総額(億) | YF_STOCK_INFO最新スナップショットから算出 |
| Hit種別 | BOTH / KEYWORD_ONLY / VECTOR_ONLY |
| cosine距離 | ベクトル検索のmin距離（KEYWORD_ONLYはN/A） |
| 意外度 | 高/中/低。銘柄名・業種イメージと半導体事業の距離。高=社名から半導体を連想しにくい（発掘価値大） |
| 偽陽性 | ○=偽陽性候補（業種名・銘柄名ベースの初期判定）。本表にも参考表にも表示する |
| 裏どり結果 | 偽陽性○の銘柄のみCHUNK_TEXT確認結果を記載。確認前は空欄 |
| 考察 | テーマとの関連についてのコメント |

**表の振り分けルール**:
1. 全銘柄に対し、銘柄名・業種イメージから偽陽性○を初期判定（機械的）
2. 偽陽性○の銘柄はCHUNK_TEXTで裏どり
3. 裏どりの結果:
   - テーマ関連が確認された → **本表**に残す（偽陽性○マーク+裏どり結果は残す）
   - テーマ無関係と確認 → **参考表**に移す（偽陽性○マーク+裏どり結果を記載）
   - 未確認 → **本表**に残す（裏どり結果=空欄）
4. 偽陽性○でない銘柄は無条件で本表

**ソート**: 意外度（高→中→低）の順。同一意外度内はcosine距離昇順

### 3. セグメント変態検知（テーマ出現頻度の時系列変化）

特定テーマのキーワードが、ある企業の決算資料に出現する頻度と好調度を時系列で追跡し、**事業構造の転換（変態）を初期段階で検知**する。

**背景**: TOTO（トイレ→半導体セラミック）、日本フェンオール（防災→半導体センサ）のように、本業イメージとかけ離れた事業が成長ドライバーに転換する企業がある。市場の認知後（株価急騰後）では遅い。

**手法**:
1. 対象銘柄群を決定: `--disclosure-dates` で指定した日の銘柄を取得。**TDNET実績テーブルを先に参照し、0件ならEARNINGS_DISCLOSURE_CALENDARにフォールバック**（将来日はカレンダーから取得）。`--tickers` 直接指定時もカレンダーから発表予定日を自動取得して出力に付加
2. テーマキーワードの出現チャンク数を期間別に集計（prior: 24ヶ月以上前 / mid: 12-24ヶ月前 / recent: 直近12ヶ月）
3. 変態シグナルを検出:
   - **漸増**: prior < mid < recent で一貫増加
   - **新出**: prior=0 から mid/recent で初出現
   - **好調転化**: recent >= 3チャンク かつ positive比率 >= 50%
   - **急増**: recent が mid の2倍以上（かつ5chunks以上）
   - **本業好調**: 上記いずれにも該当しないが、prior >= 20（本業ど真ん中）かつ recent >= 5 かつ positive >= 3。変態ではなく本業が好調な銘柄を捕捉（例: 7609 ダイトロン）
4. シグナルあり銘柄のCHUNK_TEXTを全件確認（偽陽性排除）

**スクリプト**: `scripts/093_deep_analysis_transform_scanner.py`

```bash
# 来週の決算予定銘柄 × AI半導体+光電融合テーマ（将来日→カレンダー自動フォールバック）
PYTHONUTF8=1 python scripts/093_deep_analysis_transform_scanner.py \
  --disclosure-dates 2026-05-11,2026-05-12 \
  --themes semiconductor_ai,photonic_fusion \
  --since 2020-04-01

# 過去日は TDNET 実績から自動取得
PYTHONUTF8=1 python scripts/093_deep_analysis_transform_scanner.py \
  --disclosure-dates 2026-05-07 \
  --themes semiconductor_ai \
  --since 2020-04-01
```

**出力列**: DISCLOSURE_DATE / TICKER / STOCK_NAME / theme / signal / tc_prior〜pc_recent / mcap_oku（末尾）

**指標の定義**:
- `theme_chunks`: CHUNK_TEXT内にテーマキーワードを含むチャンク数（その期間の全決算資料通算）
- `positive_chunks`: theme_chunksのうち好調表現（増収|増益|拡大|好調|過去最高|伸長|順調|上振れ|上回）も同時に含むもの
- `positive比率`: positive_chunks / theme_chunks。テーマ事業が「言及のみ」→「業績貢献」に転化した度合い

**変態パターンの類型**:

| 類型 | 特徴 | 代表例 |
|------|------|--------|
| 漸増型（TOTO型） | 毎期着実にchunk増加。positive比率も上昇。数年かけて変態 | TOTO、西部技研 |
| M&A型 | 買収により突然テーマ出現。chunk数が急増 | イトーキ（ダルトン）、SGホールディングス（Morrison） |
| 回復型 | 一度減少後に再増加。市況回復局面で拾える | 澁谷工業、テクノホライゾン |
| スパイク型 | 小型株で1Q分だけ突出。業績寄与の初回決算 | 日本フェンオール |
| 本業好調型 | 元から本業ど真ん中（prior>=20）で好調継続。変態ではないが見逃し防止 | ダイトロン |

**偽陽性パターン（注意）**:
- 比喩表現: 「食の半導体」（イフジ産業 — 卵が食品産業のインフラという意味）
- 役職名: 「CPO」= Chief Product Officer（kubell — Chatwork運営）
- 市況言及のみ: 「半導体市況の影響で…」（半導体を使う側ではなく外部環境として言及）

**パターン2（テーマ横断スクリーニング）との使い分け**:

| 観点 | パターン2 | パターン3 |
|------|-----------|-----------|
| 時間軸 | 直近1週間のスナップショット | 過去数年の時系列 |
| 目的 | 今期テーマ好調な銘柄の網羅 | 変態途中の銘柄を早期発見 |
| 出力 | Hit種別＋cosine距離 | シグナル種別＋期間別chunk推移 |
| 使いどころ | 決算シーズン中の週次スクリーニング | 決算発表前の事前調査 |

### チューニングガイド（パターン2・3横断）

テーマスクリーニングの精度は**キーワード**・**シグナル閾値**・**ベクトルクエリ**の3軸で調整する。漏れ銘柄が見つかったら、以下の手順で原因を特定し、該当する軸をチューニングする。

**漏れ原因の切り分けフロー**:
1. `--verify <ticker>` でCHUNK_TEXTを取得し、テーマ関連の記述があるか確認
2. CHUNK_TEXTにテーマ記述がある → キーワードで拾えているか確認
   - キーワードで拾えていない → **キーワード追加**（下記①）
   - キーワードで拾えている → **シグナル閾値**の問題（下記②）
3. CHUNK_TEXTにテーマ記述がない → そもそも対象外（正しい漏れ）

**① キーワードチューニング**（パターン2・3共通）:

テーマキーワードはパターン2（screener CLI引数）とパターン3（THEMES定数）で共有すべき用語セット。追加時は以下を守る:
- **テーマ固有の専門用語のみ追加**。汎用語（検査装置・洗浄装置・モールド等）はテーマ外の業種にも大量ヒットし偽陽性が爆発する
- 追加候補はBQで `COUNT(DISTINCT TICKER)` を確認し、ヒット銘柄数が妥当な範囲か検証する
- パターン2のCLI引数 `--keywords` とパターン3の `THEMES` 定数の両方に反映する
- ベクトルクエリファイル（`config/themes/`）にも関連用語を追加してベクトル空間のカバレッジを広げる

**② シグナル閾値チューニング**（パターン3固有）:

| 調整対象 | デフォルト | 調整の考え方 |
|---------|-----------|-------------|
| 好調転化の比率閾値 | >= 50% | 厳しすぎると本業銘柄が漏れる。緩めると偽陽性増加 |
| 急増の倍率 | recent >= mid × 2 | M&A型は1期で急増するため2倍が妥当 |
| 本業好調のprior閾値 | >= 20 | 低くすると非本業銘柄まで拾う。高くすると中規模企業が漏れる |
| 本業好調のpositive数 | >= 3 | 比率ではなく絶対数。比率だと分母が小さい期に不安定 |

**③ ベクトルクエリチューニング**（パターン2固有）:

cosine距離閾値（デフォルト0.40）とクエリテキスト（`config/themes/*.txt`）で調整。キーワードで拾えない「意味的に近い」銘柄を発見するのがベクトル検索の役割。

**本ガイド自体のチューニング**: 上記の3軸・閾値・切り分けフローは2026-05-08時点の初版。運用で新しい漏れパターンや過検知パターンが見つかったら、このガイド自体も更新すること。チューニング方法を固定化しない。

**チューニング実績**（2026-05-08）:
- 7609ダイトロン漏れ → 原因: シグナル閾値（本業ど真ん中でどのシグナルにも非該当）→ 「本業好調」シグナル新設で解決
- キーワード見直し → CMP追加。検査装置・洗浄装置等は過検知リスクで見送り

## 既知の問題・バグ

### VEC_ONLY誤分類問題（2026-05-10発見）

**症状**: テーマど真ん中の銘柄（7729東京精密、4186東京応化工業）がパターン2でVEC_ONLYと表示され、tc推移やpc_recentがゼロ表示になる。

**再現条件**: パターン3 + パターン2ベクトル検索を横断表示する際に発生。

**根本原因**: アドホック分析コードでパターン3結果を `pc_recent` 上位N件（例: top-30）でカットし、表示対象を絞った後に、ベクトル検索結果を追加するロジック。

1. パターン3はテーマの全銘柄を評価し、7729（tc_prior=490, pc_recent=25）や4186（tc_prior=64, pc_recent=11）を正しくシグナル検出する
2. 表示時に `pc_recent` top-30で絞ると、pc_recentが相対的に低いこれらの銘柄が落ちる
3. その後ベクトル検索で再発見され、VEC_ONLYとして追加される（パターン3データを参照しないため metrics=0）

**問題の本質**: `pc_recent` は「直近期のキーワード言及密度」であり、テーマとの関連度そのものではない。tc_prior=490の東京精密は半導体計測のど真ん中だが、長期にわたって安定言及のため pc_recent の相対順位は高くない。

**影響**: 投資判断上のミスリード。VEC_ONLYは「キーワードでは拾えないがベクトル的に近い隠れ銘柄」を意味するが、実態は「既にパターン3で検出済みの本命銘柄」。

**修正方針**（未実装）:
- 案A: top-Nカット時に `tc_prior >= 100` の銘柄はカットしない（長期本業銘柄を保護）
- 案B: ベクトル検索結果を追加する際、パターン3のフルデータ（カット前）と照合し、存在すれば実メトリクスを使ってBOTH扱いにする
- 案C: 表示ランキングを `pc_recent` 単独ではなく `tc_prior * 0.3 + pc_recent * 0.7` 等の複合スコアにする
- **推奨**: 案Bが最も安全（既存ロジックへの影響が小さく、情報損失がない）

### 注目理由の生成指針

- **本業ど真ん中**: 「〇〇本業」「〇〇専業」— テーマの供給側で主力製品が該当
- **素材・部品供給**: 「〇〇(用途)」— 部分的にテーマに関与
- **織り込み浅**: 直近４０営業日（二か月）で+10%未満の本業企業
