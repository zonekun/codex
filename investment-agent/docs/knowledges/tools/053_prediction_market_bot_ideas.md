## 重要な前提

以下のアイデアは**予測市場（Prediction Market）向けの設計をベースに抽象化したもの**であり、
株式トレードへの応用は一つの考え方として参照するにとどめる。
絶対に採用しなければならない手法ではない。実際の分析・バックテストで効果が確認できた場合に採用を検討すること。

### 積極的手法への昇格ルール

投資アイデアの分析・バックテストにおいて、以下のアイデアを**実際に適用した結果が有益と認められた場合**、
必ずユーザーに報告すること。報告を受けてユーザーが判断し、「積極的に使う手法」として昇格させる。

> **昇格の目安**: 分析精度の向上・オーバーフィット回避・ドローダウン抑制・リスク管理強化など、
> 定量的に有益と確認できたもの。「なんとなく良さそう」では昇格しない。
> 昇格後はこのファイルのステータスと関連知見ファイルを更新すること。

## 分析・アイデア評価フェーズでの活用

### アイデア1: Expected Value（EV）フレームワーク

```
EV = p_up × E[上昇幅] - (1 - p_up) × E[下落幅]

例: 確率60%で+8%、40%で-4%
EV = 0.6 × 8% - 0.4 × 4% = +3.2%
```

**活かし方**: 投資アイデアを評価するとき、単に「統計的有意性（p値）があるか」だけでなく、
**確率 × 幅の積（期待値）** まで計算して初めて追求価値があるかを判断する。
p値が有意でも期待値がゼロ近傍なら追求しない。

---

### アイデア2: Mispricing Score（市場コンセンサスとのズレのZ-score）

```
δ = (p_model - p_mkt) / σ

株式版: δ = (自モデルの予測リターン - アナリストコンセンサス予測) / 予測分散
```

**活かし方**: 「自モデルが上昇を予測」よりも「市場がまだ織り込んでいないズレがあるか」のほうが実際のエッジに近い。
楽天証券コンセンサスや J-Quants `/fins/estimates` と自モデル予測を比較する指標として使える。
δが大きい銘柄を優先的に分析対象にする、というスクリーニング軸になりうる。

---

### アイデア3: Bayes Update（複数シグナルの逐次統合）

```
P(H|E) = P(E|H) · P(H) / P(E)

初期確率（モメンタム） → 更新（決算サプライズ） → 更新（逆日歩急騰） → 最終確率
```

**活かし方**: 複数の独立シグナルが重なる銘柄の優先順位付けに使える。
各シグナルを独立に検定するのではなく、「これが重なった場合の合成確率」を計算してスコアリングする。

---

### アイデア4: エッジ閾値（分析追求の足切り基準）

```
edge = p_model - p_mkt   →   edge > 0.04（4%）のみ追求
```

**活かし方**: アイデアが来た時点で「このアイデアが正しかった場合の期待エッジは最低XX%あるか」を
大まかに見積もる。エッジ見込みが小さすぎるアイデアには分析コストを投じない、という判断基準になりうる。

## バックテストフェーズでの活用

### アイデア5: Fractional Kelly によるポジションサイジング

```python
f_full = (p * b - q) / b      # フルKelly（p=確率, b=オッズ-1, q=1-p）
f = alpha * f_full             # alpha=0.25〜0.5（分散・ドローダウン抑制）
```

**活かし方**: 等ウェイトや固定サイズの代替として、予測確率ベースの動的サイジングを試す。
フルKellyは推定誤差に敏感なのでFractional（0.25〜0.5倍）から開始が無難。
バックテスト内でこのサイジングルールを組み込むと、より実運用に近い評価になる。

---

### アイデア6: MDD閾値によるエントリーブロック

```python
# バックテスト内でドローダウン中の新規エントリーを停止
if current_drawdown > 0.08:   # 8%超
    skip_new_entry = True
```

**活かし方**: 通期シャープが良くても「大きく負けた後に損失を拡大しない」リスク管理を
バックテスト内でシミュレートする。実運用に近い挙動をエミュレートでき、結果の過大評価を防ぐ。

---

### アイデア7: Brier Score によるモデル事前検証

```python
BS = (1/n) * sum((p_pred - actual_outcome)**2)
# BS < 0.25: ランダム予測（BS=0.25）より良い → バックテスト進む
# BS >= 0.25: ランダム以下 → バックテスト中止
```

**活かし方**: 方向予測モデル（上昇/下落の確率推定）を使う場合、
バックテスト本体に入る前にモデルのキャリブレーション品質を確認するゲートとして使う。
確率の精度が担保できないモデルでバックテストしても、過信したポジションサイジングになるだけ。
