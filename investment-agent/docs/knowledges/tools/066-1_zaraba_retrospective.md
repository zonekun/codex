## 書き込みルール（トークン最小化）

反省会ログ追記は **Git Bash echo** を使用。**Edit ツール禁止**（old_string/new_string のトークン浪費を回避）。**PowerShell echo 禁止**（UTF-16 BOM 混入のため）。

パス: フォワードスラッシュ `docs/knowledges/tools/066-1_zaraba_retrospective.md`

### 日次ヘッダー追加（1コマンドで一括）
```bash
printf '\n## YYYY-MM-DD\n\n| 区分 | Ticker | 銘柄 | score | 予測 | 実績 | 考察 |\n|------|--------|------|-------|------|------|------|\n' >> docs/knowledges/tools/066-1_zaraba_retrospective.md
```

### 銘柄行追加（1行ずつ）
```bash
echo "| ✓ハズレ | 5449 | 大阪製鐵 | +3 | UP | -5.2% | 考察テキスト |" >> docs/knowledges/tools/066-1_zaraba_retrospective.md
```

### 課題・改善方針追記
```bash
printf '\n### MM/DD 課題\n\n' >> docs/knowledges/tools/066-1_zaraba_retrospective.md
echo "- **P1: タイトル**: 説明" >> docs/knowledges/tools/066-1_zaraba_retrospective.md
```

## ザラ場反省会の運用手順

ユーザーが「ザラ場反省会 YYYYMMDD」と指示したら:

1. 当日の results.csv を確認（ローカル `C:\tmp\zaraba_cache\YYYYMMDD\results.csv` or GCS `zaraba_scoring_results/results_YYYYMMDD.csv`）
2. 因子表の基準は 066 本体 §スコアリング因子を部分Read（offset/limit指定）で確認。066本体の全量Readは不要
3. 銘柄別ログを本ファイルに追記（上記書き込みルールに従う）
4. 改善TODOは 066 本体 §未解決TODO に移設（本ファイルの課題セクションに初出記載→066移設）

## 銘柄別ログの検証ルール

- ユーザーがコメント・議論した銘柄 → 区分に「✓」を付与（検証済み）
- Claudeが自動生成した考察のみ → 無印（未検証）
- **テーマ・TODOとして採用するのは✓付き案件から導出されたもののみ**
