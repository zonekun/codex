## フィードバック先A: アダプター作成プログラム (build_monthly_extractor.py)

### A-1. 年バグ: `.*?` を含む row_label_regex が年テキストを誤抽出

**症状**: `our_value = 2025` または `2026` など年の数字が返る
**根本原因**: `row_label_regex` に `.*?` が入っており、`re.search(pattern, full_text, re.DOTALL)` でマッチ後、`rest = src_line[m.end():]` から最初の数字を取得するロジックが「2025年」「2026年」等のテキストを掴む。

**再発パターン**:
- `.*?` を含むが値のキャプチャグループなし → 行末から年を誤取得
- 固定値（特定月の数値）を regex にハードコード（141Aの例: `^売上高\s+101\.4\s+98\.3`） → 月が変わると古い値を返す

**修正ルール**:
```
1. row_label_regex には必ずキャプチャグループ（丸括弧）を付与し、
   グループ1で「値」を直接キャプチャすること。
   NG: "不動産売買事業における.*?取引件数は"
   OK: "取引件数は\\s*([\\d,]+)件"

2. .*? を使う場合は、マッチ範囲内に年テキストが入らないようキャプチャグループで限定。
   NG: "業績は.*?前年同月比で"  →  rest から 2025 を拾う
   OK: "前年同月\\s*比で\\s*[+＋]?([\\d\\uff10-\\uff19.]+)[%\\uff05]"

3. 固定値を regex にハードコードしないこと。数値は必ずキャプチャグループで動的取得。
```

---

### A-2. 複数フィールド同値: 1つの regex が複数フィールドにヒット

**症状**: `our_value` が複数フィールドで同じ値
**根本原因**:
1. **Rolling table で行特定できない**: `STRING_AGG` 後は空白区切りになり列数が月により変動するため、固定列数パターンが崩れ全フィールドが同一値を返す
2. **セクション区別なし**: 複数フィールドが同一キーワード（「合計」「売上高」等）を共有
3. **STRING_AGG の空白区切り**: 元文書の改行は `STRING_AGG` で全て空白に変換されるため、`\n` を含む regex は常に NO_MATCH になる

**修正ルール**:
```
1. STRING_AGG（空白区切り）を前提としてアダプターを生成。
   元文書の改行位置を考慮した \n を含む regex は動作しない。全て \s+ で代替。

2. 複数フィールドが同一の row_label_keyword を持つ場合、
   セクションヘッダや前置文字列を regex に含めて一意に区別。
   NG: "合計"
   OK: "報告セグメント別売上高.*?合計\\s+[\\d,]+\\s+([\\d.]+)"

3. rolling table（複数月の数字が横並び）パターン:
   - セクション固有の見出し語を prefix に含める
   - use_last_number: true を明示的に設定
   - 年間集計行との混同を避けるため、セクション名と単位記号を regex に含める
   例: "全店\\s+前年比\\s+（％）\\s+売上高\\s+([\\d.]+(?:\\s+[\\d.]+)*)"
       + use_last_number: true
```

---

### A-3. 抽出位置ズレ: 表の列順を誤認識

**症状**: `our_value` が金額ではなく前年比（%）の値を返す
**根本原因**: テーブルが `店舗数 前年比 売上高 前年比 ...` の形式で、アダプターが金額列でなく前年比列の数字を返す。

**再発例**: 9936 (王将): `direct_all_stores_sales_million_yen = 100`（our）vs `9,470`（BC）
- 実テキスト: `99.7 1,274 107.9 8,428 103.6 6,677 ... 9,470` → 100/103 は前年比%

**修正ルール**:
```
1. 表形式データでは列の型（金額列 vs %列）を明示的に区別。
   金額列の後ろに前年比列が来る場合:
   "売上高\\s+([\\d,]+)\\s+[\\d.]+\\s+"  # 金額([\\d,]+)、次の数字(%列)は非キャプチャ

2. フィールド名に _million_yen / _billion を含む場合、
   カンマ区切り数字（[\\d,]+）を優先的にキャプチャし、
   小数点のみの数字（前年比%）は誤抽出しないよう regex を設計。
```

## フィードバック先B: 数値化プログラム (extract_monthly_data.py)

### B-1. 全角数字の変換漏れ

**症状**: `our_value = '７'`（U+FF17 全角7）として返る → BC比較で不一致またはエラー
**根本原因**: PDF抽出テキストに全角数字（０-９）が混入する場合があり、`_extract_from_match()` がキャプチャグループをそのまま返すと `float()` 変換が失敗（`float('７')` はエラー）。

**修正ルール**:
```python
# 値を数値に変換する前に全角→半角変換を追加
import unicodedata
def normalize_value(raw: str) -> str:
    return unicodedata.normalize('NFKC', raw)
# _extract_from_match() または _extract_numbers() の冒頭で呼ぶ
```

---

### B-2. +100 オフセット: 増減値（+16.5%）と比率（116.5%）の表現差

**症状**: `our_value ≈ bc_value - 100`（例: our=16.5, bc=116.5）
**根本原因**: 文書が「前年同月比 +16.5%」（増減値）、BC が「116.5」（比率）で表現する場合に不一致。現状 extract_monthly_data.py に「抽出値 + 100」の変換フラグなし。

**修正ルール**:
```
extract_adapter.json に "offset_100: true" フィールドを追加し、
value_type="percentage" かつ offset_100=true の場合に extracted_value + 100 して保存。

アダプター例:
{
  "key": "all_store_sales_yoy",
  "row_label_regex": "...",
  "value_type": "percentage",
  "offset_100": true,
  "_note": "文書は増減値(+7.2%)、BCは比率(107.2%)で表現"
}
```

> **注意**: `yoy_offset` を adapter に追加しても無効。`extract_monthly_data.py` の `offset_100` フラグで制御すること（yoy_offset追加は二重加算で悪化）。
