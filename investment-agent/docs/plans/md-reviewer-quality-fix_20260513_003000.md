## 診断: なぜ命中率が下がったか

### 根本原因: 「MD改善」以外の出力モードが存在しない

md-reviewer のスキルMDは **全てのステップが「MDのどこが悪いか見つけて直せ」を前提にしている**。

- Step 2: 「AIがどう誤読するか」をシミュレーション
- Step 3: 4軸でMD品質を評価
- Step 4: 曖昧表現を重点確認
- Step 5: MD構成レビュー
- Step 7: エスカレーション → ソースコード・仕組み側への波及
- 出力テンプレート: 全セクションがMD起因の指摘を前提

**MDの記述が明確なのにAIが従わなかったケース**（153, 156, 157）では、このパイプラインが空振りする。153_mrはAccuracy: S / Completeness: S / AI可読性: A と自分で評価した上で「MD側に改善すべき曖昧性は見当たらない」と書きながら、それでもMD改善の重大指摘を1件出している。

### 助長要因1: 出力テンプレートの圧力

613行のスキルMDが定義する出力テンプレートには12セクション以上がある。「該当なし」で埋めるより何か書いたほうがスキルの指示に従っている感覚になるため、低品質な指摘が生成される。

### 助長要因2: 自己レビュー(065/133)でプロセスが増えたがフィルタは増えなかった

065で追加: §3スコープ次元、Step 8b Q1-Q3、パターン2評価項目7「対策スコープ」、Step 7b制度的エスカレーション
133で追加: Step 8e出力内部整合性チェック(i)(ii)(iii)、Step 8c(ii)クロスルール競合

**全て「追加」であり「削減」や「打ち切り分岐」は1つもない**。結果、プロセスが重くなった分だけ出力も重くなり、しかし命中率は改善していない。

## 改修方針

### 方針A: 「MD非原因」早期分岐の追加（主改修）

Step 2（静的推論分析）の直後に **「MD品質は十分か？」の判定分岐** を挿入する。

```
Step 2 完了
  ↓
4軸(Accuracy/Completeness/Relevance/Actionability)が全てA以上か？
  ├── No → 通常フロー（Step 3以降を全実行）
  └── Yes → 「MD非原因モード」に遷移
         ├── パターン1/3 → 「AI可読性は十分。重大な指摘なし」で短縮完了
         └── パターン2/4 → 原因分析に集中（下記）
```

**「MD非原因モード」パターン2/4の出力**:
- 事象・AIの思考回路・直接原因・根本原因 → 通常通り記述
- **MD上の原因 → 「MDの記述は明確。問題は行動側にある」で明示的に打ち切り**
- 再発防止 → MD改善ではなく「構造的強制（hook/validator）で防げるか」「本件はmd-reviewerのスコープ外（行動問題）か」の2択に限定
- 【重大な指摘】【改善提案】→ MD改善が不要なら**出さない**。「重大な指摘: なし（MDは十分に明確）」と明記

### 方針B: 出力テンプレートの軽量化（副改修）

現行テンプレートの12セクション全記述を必須としない。

- 「MD非原因モード」用の短縮テンプレートを定義
- 必須セクション: サマリー / 品質評価(4軸の1行評価のみ) / パターン2/4原因分析 / 推奨検証(Step 8) / 確認できなかった事項
- 省略可能: AI誤読リスク / MD構成リスク / 指示優先順位・文脈境界 / 修正文案 → MD品質がA以上の場合、対象MDに起因する誤読・構成・優先順位の問題は定義上存在しないため

### 方針C: スキルMD全体の行数削減（付随改修）

613行→目標450行以下。

削減候補:
- Step 8の冗長な背景説明（L322-324: 007レビューの教訓）→ 1行ポインタに圧縮
- 修正文案の「本当に必要な時だけ書く」を構造的に強制: MD非原因モード時は修正文案セクション自体を省略
- 起動方式の説明(L11-28)を簡潔化: 現行は理由の説明が冗長
- 呼び出し方(L477-503)のサンプル群を2例に削減

**削減しないもの**: Step 1-8の本体、パターン1-4定義、最優先指針4項目、評価ランク定義、苦情受付窓口、不備蓄積ログ節

## 指摘項目

### P0-1. 「MD非原因」分岐の不在 🚨

**症状**: MDの記述が明確なケースで、レビューワがMD改善を推奨し全却下される（153, 156, 157）

**該当**: `skills/md-reviewer.md` — Step 2（L199-211）の直後に分岐がない

**根本原因**: 全てのレビューが同一パイプライン（Step 1→2→3→4→5→6→7→8→出力）を通過する。「MDに問題がない」という結論に到達するパスが存在しない

**修正方針**: Step 2 と Step 3 の間に「MD品質判定分岐」を挿入

```markdown
# after: Step 2の直後に追加

### Step 2.5: MD品質判定分岐

Step 2 の推論結果に基づき、4軸(Accuracy/Completeness/Relevance/Actionability)を速断する。

- **全軸A以上** → 「MD非原因モード」に遷移。Step 3-6を省略し、Step 7（エスカレーション判定）に直行する。パターン2/4の場合は原因分析セクション（事象/思考回路/直接原因/根本原因）のみ記述し、MD上の原因は「MDの記述は明確。問題は行動側にある」で打ち切る。【重大な指摘】はMD改善が必要な場合のみ記載し、不要なら「なし」と明記する
- **いずれか1軸でもB以下** → 通常フロー（Step 3以降を全実行）
```

**呼び出し側への波及**:
- 出力テンプレート: 「MD非原因モード」用の短縮テンプレートを追加
- Step 7: MD非原因モードからの流入を想定した記述追加（「MDは十分だが、構造的強制で防げるか」の判定）
- Step 8: MD非原因モードでは8a-8cの一部を省略可能

**検証**: 153_mr（索引ファースト）の事象をこの新フローに通して、「MD非原因モード → 重大指摘なし → 構造的強制の検討のみ」に到達するかシミュレーション

**ロールバック**: スキルMDのgit revertで即時復元可能

### P0-2. 出力テンプレートの肥大 🚨

**症状**: 12セクション全記述の圧力で、MDに問題がないケースでもセクションを埋めようとして低品質指摘が生成される

**該当**: `skills/md-reviewer.md:400-446`（出力テンプレート全体）

**根本原因**: テンプレートが全セクション必須に見える構成。「該当なしの場合はセクション自体を省略」の明示がない

**修正方針**: テンプレートを2モードに分割

```markdown
# after: 出力テンプレートを分岐

## 出力スタイル

### 通常モード（Step 2.5 で1軸以上B以下）

（現行テンプレートをそのまま使用。変更なし）

### MD非原因モード（Step 2.5 で全軸A以上）

パターン1/3 の場合:

    # MD AI可読性レビュー: <対象の短い説明>
    （ヘッダ）
    ## 【サマリー】
    AI可読性評価(S-A) / 誤読リスク評価 / 重大な指摘: なし
    ## 【Markdown 品質評価】
    4軸の1行評価
    ## 【確認できなかった事項】

パターン2/4 の場合:

    # MD AI可読性レビュー: <対象の短い説明>
    （ヘッダ）
    ## 【サマリー】
    ## 【Markdown 品質評価】
    4軸の1行評価
    ## 【パターン 2/4: 原因分析】
    事象 / AIの思考回路 / 直接原因 / 根本原因
    MD上の原因: 「MDの記述は明確。問題は行動側にある」
    ## 【エスカレーション判定】
    構造的強制（hook/validator）で防げるか / md-reviewerのスコープ外か
    ## 【推奨検証（Step 8）】
    ## 【確認できなかった事項】
```

**呼び出し側への波及**: 不備蓄積ログ追記ルール — MD非原因モードでも蓄積ログへの追記は実施する。タグは `behavior:*` 系（既存）を使用。ただし【重大な指摘】【改善提案】がない場合は蓄積ログへの追記は「原因分析のみ・MD改善指摘なし」と記録

**検証**: 157_mr の事象をこの新テンプレートで再構成し、不要セクションが省略されるかシミュレーション

**ロールバック**: git revert
