- 前プランで58→9件に改善したが、6040(diff=18-26K)・2736(diff=1)・8267(2回失敗) の3社がスキップ

- `5bcea27` で「PDF blob欠落時にBQフォールバックせずskip+warning」を実装済み
- 事故パターン E5-1 として `042-1_monthly_error_fix_patterns.md` に追記済み

## 判明した事実

### 1. url_adapter.json は不要

6040 は TDnet ソースのため、PDF は `gs://stock_data_1930932/tdnet/6040/` に既に存在する。`url_adapter.json` は月次専用ダウンロード用であり、TDnet型には不要。extractコードは `_pdf_blob_map` で `tdnet/{ticker}/` の PDF を直接マッチする。

### 2. extractコード修正（2件・デプロイ済み）

#### Fix 1: `if not rec:` 分岐で PDF テキストにフォールバック（L3617-3629）
- 変更前: BQ `full_text`（テーブル構造崩壊テキスト）にフォールバック → regex マッチ不可
- 変更後: `_has_row_regex and _cached_pdf` のとき `_extract_pdf_text()` で PDF テキストを使用

#### Fix 2: blob マッチングで submission_date 優先（L3536-3545）
- 変更前: `_pdf_blob_map.get(doc_title)` のみ → 最古の FY blob にフォールバック
- 変更後: sub_date プレフィックス一致 → doc_title 部分一致の2段マッチ

両方 Cloud Build でデプロイ済み（ビルド `2b1d4c8f` SUCCESS）。

### 3. コードレビュー完了（品質 A）

`docs/reviews/164_cr_extract_regex_pdf_fallback.md` に記録。主な指摘:
- `_has_row_regex=False` アダプターでは依然 BQ フォールバックが残存（設計意図として問題なし: 旧形式 regex は BQ テキストで動作）
- `5bcea27` ガード後の `if matched_blob:` が Dead Guard 化（改善提案）
- PDF DL 失敗時のフォールバック挙動のコメント不足（改善提案）

### 4. regex → Gemini に方針転換

regex アプローチの問題:
- `計\s+月計` アンカーがおにぎり店セクションにミスマッチ（桁違い値を抽出）
- 累計 vs 月計の混同
- アンカー改良後も 9/10 OK・1 NG（2025-12）で完全一致せず
- 2025-12 は BQ doc 欠落（TDnet 2026年1月提出が GCS/BQ 両方に不在）で regex では到達不能

#### Gemini アダプタで解決

`source: "non-tdnet(pdf)"` + `gemini_multi_month: true` + `overwrite_past_months: true` に変更。

- 各 PDF を Gemini に直接送信し、全月分を一括抽出
- `gemini_custom_prompt` で「当期のみ・月計行・ウィンターシーズン計のみ」を指示
- 2025-12 は 20260210 PDF（1月+12月合算提出）から正しく 274 を取得
- テスト結果: FY2025（7ヶ月）+ FY2026（6ヶ月）= **全値 BC 完全一致**
