## 方針

2024年プランと同一方式。新アーキ（`tdnet-load-daily` + `ai_processing_flow` Workflows）を使用。**2回に分割、各回 ~3-3.5時間**（2024年Run1実績ベース: Load 206 docs/min、AI Q並列投入）。投入タイミングはユーザーが決定。

**dedup**: `_load_processed_file_names()` が BQ `FILE_NAME` を日付範囲で取得し既存 blob をスキップ。既存 41,324 件に影響なし。

**干渉リスク**: なし（`tdnet-load-daily-daily` Scheduler PAUSED、`ai_processing_flow` Scheduler 未設定）

**実行順序**: 2024年バックフィル完了後に実行すること（同時実行は AI 処理の TPU 競合リスク）

## Run 1: 2025年 上半期（1-6月、~3.5h）

### 内訳（2024年Run1実績ベース）

| ステップ | 処理内容 | 対象件数 | 推定所要 |
|---------|---------|---------|---------|
| L1 | Load (BQ投入) | ~17,355 gaps | ~1h24m |
| A1 | AI処理 Q1 (1-3月) | ~7,808 | ~1h41m（Q2と並列） |
| A2 | AI処理 Q2 (4-6月) | ~9,547 | ~2h04m（Q1と並列） |
| | **合計** | **~17,355** | **~3h28m** |

### コマンド

```bash
# Step 1: Load 上半期（1回で6ヶ月分ロード）
gcloud run jobs execute tdnet-load-daily --region us-west1 \
  --args="--job-mode=load" \
  --update-env-vars DATE_FROM=20250101,DATE_TO=20250630,ALLOW_FULL_BACKFILL=1

# Step 2: AI処理 Q1（load完了後）
gcloud workflows execute ai_processing_flow \
  --location=us-central1 \
  --data='{"date_from":"20250101","date_to":"20250331"}'

# Step 3: AI処理 Q2（A1完了後）
gcloud workflows execute ai_processing_flow \
  --location=us-central1 \
  --data='{"date_from":"20250401","date_to":"20250630"}'
```

## 注意事項

1. **`ALLOW_FULL_BACKFILL=1`**: 31日超の日付範囲は backfill ガードで拒否される。この env var で override
2. **`--job-mode=load`**: 新アーキでは `--args="--job-mode=load"` を使用。旧アーキの `RUN_MODE=full` は使わない
3. **AI は 3ヶ月単位**: TPU preemption リスク抑制のため。load は 6ヶ月一括で OK
4. **投入タイミング**: ユーザーが決定。推奨は平日 15:00〜24:00 JST or 週末（us-central1-b TPU spot 需要低）
5. **既存データへの影響なし**: load は FILE_NAME dedup でスキップ、Workflows は AI_STATUS='pending' のみ処理
6. **2024年バックフィルとの順序**: 2024年完了後に実行（TPU 競合回避）
