## 背景と目的

### 問題

現在の CLAUDE.md（357行）は以下が混在し、AI読み取り負荷が高く重要規則がノイズに埋もれている:

- **憲法**（原則・禁止事項）
- **運用マニュアル**（LINE会話モードの詳細フロー等）
- **事故記録**（MR-071/131/134/136/139 の事故番号・経緯）
- **チェックリスト**（ディスク管理5項目等）
- **FAQ**（用語解釈）

同一系統の規律が別々のセクションで膨張:
- 「指示の字義優先」「AI直接処理」「既存コード移植」「ステップ完了検証」「自己検証」→ 全て「AIが自己判断で逸脱するな」の変種
- 「監視」「LINE会話モード」「クラッシュ復旧」「端末移管」→ 全て「長時間運用・継続実行」の手順

### ゴール

1. CLAUDE.md を「**原則 + 禁止事項 + 導線**」に絞る（憲法+索引モデル）
2. 運用手順・事故記録・チェックリストは知見MD（`docs/knowledges/`）に委譲
3. 同系統の規律を統合し、原則→適用例の構造にする
4. MR事故番号をCLAUDE.mdから削除（知見MD側に完全移譲）
5. 行数目標: **200行以下**（現357行 → 44%削減）

### 制約

- 知見MDへの導線は維持・強化する（削るのは本文であってポインタではない）
- 高頻度参照テーブルは残す（セッション開始時の自動ロードに不可欠）
- 既存の事故パターンDB（004 §P-001）は維持。今回の再編でCLAUDE.md側の個別ルールが統合されても、004側のテーブルはデータとして残す

### 肥大化の構造的原因（再発防止）

CLAUDE.md が357行に膨張した直接原因は事故→ルール追加の繰り返しだが、その**ドライバー**はレビューエージェント（特に md-reviewer）のスキルMD自体にある。

md-reviewer の以下3箇所が「事故を見つけたらCLAUDE.mdにルール追加を推奨せよ」と指示している:

1. **§スコープの次元**（L57-62）: 「CLAUDE.mdへの汎用ルール追加を推奨に含める」「初回であってもCLAUDE.mdレベルの包括的対策を提案する」
2. **§制度的エスカレーション**（L315-318）: 「個別MD → CLAUDE.md / スキルMDへの汎用ルール追加を指摘する」
3. **§CLAUDE.md不足検出チェック質問**（L348-351）: Q1-Q3の3問全てが「CLAUDE.mdに追加すべきか？」で終わる

CLAUDE.mdを再編成しても、レビューエージェントの行動指針を変えなければ再膨張する。Step 0 でスキルMDを先に改訂する。

#### §4 基本原則 の統合設計（核心部分）

**4.1 確認優先（推測禁止）** — 以下を1原則に統合:
- 「推測で発言してから確認するな」
- 「データ・ファイルがないと断定するな」
- 「ログを鵜呑みにしない」
- 「知見ファイルは最後まで読む」

```md
### 4.1 確認優先
事実確認が可能なことを、確認せずに発言・報告しない。
- データ属性はBQ・CSV等で裏取り。日付属性はpython/dateで確認
- 不在断定禁止: 知見MDで永続化先を全て確認してから判断
- ログは症状。原因は中間ログ→コード→手動テスト差異→1社分詳細の順で追跡
- 知見ファイルは最後まで読む（制約は後半の「注意事項」に集約）
```

**4.2 ユーザー指示優先（AI逸脱禁止）** — 以下を1原則+適用例に統合:
- 「指示の字義優先」（メタルール）
- 「既存コード移植ルール」
- 「AI直接処理の指示ルール」
- 「ステップ完了検証義務」
- 「ユーザー異常報告時の自己検証」

```md
### 4.2 ユーザー指示優先
ユーザー指示は、AIの技術的判断・プランMDの構造・慣習的実行単位より常に優先する。
指定された手順・参照先・手段・ツールを、自分の判断で省略/改変してはならない。

- 適用判定: 「指定された手段Xを省略/変更しようとしている」と認識した時点で発火
- 異常報告を受けたら外部要因より先に自分を疑う（知見MDで自分の実行内容を検証）
- ユーザーが同じ指示を2回繰り返したら、前回の実装を0ベースで再評価
- 破壊的な結果を招く場合のみ実行リスクを提示

→ 適用例・判定フロー・事故事例: `004_coding_conventions.md` §事故パターンDB P-001
→ 移植/手動処理/検証の詳細: `004_coding_conventions.md` §既存コード移植 / §AI直接処理
```
