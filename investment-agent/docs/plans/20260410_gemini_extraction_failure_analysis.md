# Gemini抽出失敗 原因分析レポート（212A・2670）

**作成日**: 2026-04-10
**目的**: custom_promptが効かなかった原因を特定し、再発防止策を確立する

---

## 概要

212A（フィットイージー）と2670（ABCマート）は、いずれもシンプルなテーブル構造のPDFであるにもかかわらず、Gemini 3 Flash（PDFバイナリモード）で正しい値を抽出できなかった。custom_prompt追加やモデル変更（3.1 Pro）でも改善しなかった。

原因を調査した結果、**プロンプトの問題ではなくPDFの構造認識の問題**であることが判明した。

---

## 212A フィットイージー（3件NG）

### NG内容

| 年月 | フィールド | 抽出値 | BC値 | 差分 |
|------|-----------|--------|------|------|
| 2025-11 | 全店 店舗数 | 181 | 240 | 59 |
| 2025-11 | 会員数（万人） | 15.0 | 23.1 | 8.1 |
| 2025-11 | 会員数（前年同月比） | 151.5 | 153.6 | 2.1 |

### PDFの構造

pdfplumber解析結果（1ページ目に4つのテーブル）:

```
T0: 会員数（全店）    → 23.1万人, 前年同月比 153.6%  ← BC値はこちら
T1: 会員数（既存店）  → 15.0万人, 前年同月比 151.5%  ← Geminiが取得した値
T2: 店舗数（全店、FC含む）→ 240店                    ← BC値はこちら
T3: 店舗数（直営店のみ） → 181店                     ← Geminiが取得した値
```

### 失敗の根本原因

**Geminiが「全店」テーブルではなく「既存店/直営店」テーブルを読んだ。**

なぜ間違えたか:
1. **4つのテーブルが同一ページに縦並び**で、ヘッダーの差が小さい（「会員数」と「既存店会員数」等）
2. **pdfplumberのテーブル解析結果を見ると、テーブルのセル内容が断片化**している（例: R1が `数 23.1 万⼈)` のように行ラベルが途切れている）。これはPDFの文字配置がセル境界と一致しないため
3. PDFバイナリモードでは、Geminiが内部的にPDFをレンダリングして画像として認識する。**テーブルのヘッダー部分が画像内で視覚的に区別しにくい**（同じフォント・サイズ・色で「会員数」と「既存店会員数」が並ぶ）
4. Geminiは**最初にマッチしたテーブル（既存店）を返す傾向**がある。「全店」と「既存店」の2つが並んでいるとき、上から順に読んで最初の数値を返す

### 以前のcustom_promptが効かなかった理由

以前のcustom_prompt:
```
「当期」テーブルと「前年度（参考情報）」テーブルがあります。必ず当期テーブルから取得してください。
```

**問題**: 「当期/前年度」の区別を指示していたが、実際の問題は「全店/既存店」の区別。指示の的が外れていた。

### 修正後のcustom_prompt

```
このPDFには4つのKPIテーブルがあります（上から順に）:
1. 会員数（全店）: 23万人台の大きな数値 ← こちらを使う
2. 会員数（既存店）: 15万人台の小さな数値 ← 使わない
3. 店舗数（全店、FC含む）: 240前後の大きな数値 ← こちらを使う
4. 店舗数（直営店のみ）: 181前後の小さな数値 ← 使わない
「全店 店舗数」→ 3番目テーブル（FC含む全店、数値が大きい方）
「会員数」→ 1番目テーブル（全店会員数、数値が大きい方）
「会員数（前年同月比）」→ 1番目テーブルの前年同月比行
```

**改善ポイント**: テーブル番号＋具体的な数値の大きさを指定することで、Geminiが「どのテーブルか」を数値レンジで判断できるようにした。

## 2670 ABCマート（4件NG）

### NG内容

| 年月 | フィールド | 抽出値 | BC値 | 差分 |
|------|-----------|--------|------|------|
| 2026-01 | 全店 売上（前年同月比） | 8.5 | 107.0 | 1.5 |
| 2026-01 | 全店 客単価（前年同月比） | 2.1 | 103.2 | 1.1 |
| 2026-01 | 既存店 売上（前年同月比） | 8.5 | 105.9 | 2.6 |
| 2026-01 | 既存店 客単価（前年同月比） | 2.1 | 102.7 | 0.6 |

### PDFの構造

pdfplumber解析結果（1ページに1テーブル、14行）:

```
テーブルT0（14行）:
  R0（ヘッダー上段）: [3月, 4月, 5月, 第1四半期, 6月, 7月, 8月, 第2四半期, 上半期]
  R1: 既存店 売上高    4.1  3.5  9.9  5.8  6.2  4.5  8.5  6.3  6.0
  R2: 既存店 客数      2.6  -0.9 5.6  2.4  3.4  ...
  R3: 既存店 客単価    1.4  4.5  4.1  3.3  2.7  ...
  R4: 全店 売上高      4.5  4.2  10.4 6.3  6.1  4.6  8.7  6.6  6.3
  R5: 全店 客数        2.6  -0.7 5.5  2.4  2.9  ...
  R6: 全店 客単価      1.8  4.9  4.6  3.8  3.2  ...
  
  R7（ヘッダー下段）: [9月, 10月, 11月, 第3四半期, 12月, 1月, 2月, 第4四半期, 下半期]
  R8: 既存店 売上高    1.3  2.1  5.6  3.2  -0.4 5.9  ...
  R9: 既存店 客数      ...
  R10: 既存店 客単価   ...
  R11: 全店 売上高     1.1  2.8  6.7  3.8  0.2  7.0  ...
  R12: 全店 客数       ...
  R13: 全店 客単価     6.3  4.4  3.2  4.6  4.7  3.2  ...
```

### 失敗の根本原因

**3つの問題が重なっている:**

#### 問題1: 上下段テーブルの列位置ミス

テーブルが上段（3月〜8月）と下段（9月〜2月）に分かれている。1月のデータは下段R7-R13にある。

Geminiは上段R0-R6から値を取得した:
- our=8.5 → R1(既存店 売上高)の「8月」列の値（上段の右端付近）
- our=2.1 → R3(既存店 客単価)の「6月」列付近の値

**上段のデータを下段の1月と誤認した。** 上下段のヘッダー切り替え（R0→R7）をGeminiが認識できていない。

#### 問題2: 既存店と全店の取り違え

1月のBC値:
- 全店 売上 = 107.0（PDF上: 7.0）
- 既存店 売上 = 105.9（PDF上: 5.9）

Geminiが返した8.5は上段の既存店行。全店行ではない。

#### 問題3: 増減率 vs インデックス形式

PDFの値は増減率（7.0 = +7.0%）。BC値は100+増減率（107.0）。adapter に yoy_offset=100 が設定されていなかった。

### 以前のcustom_promptが効かなかった理由

以前のcustom_prompt:
```
この企業のテーブルは上期（3月-8月）と下期（9月-2月）の2ブロックに分かれています。
対象月が下期（9月〜2月）の場合、必ず下段のテーブルブロックから値を取得してください。
上段ブロック（3月-8月）の値を絶対に返さないでください。
前年同月比の値は増減率（例: 7.0%）で記載されています。そのままの数値（7.0）を返してください。
```

**問題**: 
1. 「上期/下期」という抽象的な表現で、Geminiはテーブル内のR0-R6/R7-R13の物理的な分離を認識できなかった
2. 列ヘッダーの具体的な内容（3月,4月,...,第1四半期,...）を示していなかったため、列位置の特定ができなかった
3. 「第1四半期」「上半期」等の累計列の存在を警告していなかった

### 修正後のcustom_prompt

```
このPDFのテーブルは上下2段構成です:
上段(R0-R6): 3月,4月,5月,第1四半期,6月,7月,8月,第2四半期,上半期
下段(R7-R13): 9月,10月,11月,第3四半期,12月,1月,2月,第4四半期,下半期

1月のデータは下段の「１月 January」列にあります。
「第3四半期」「第4四半期」「上半期」「下半期」の列は累計値です。月次値ではありません。

行構造:
- 既存店 Existing Stores: 売上高/客数/客単価
- 全店 All Stores: 売上高/客数/客単価

値は増減率（例: 7.0 = +7.0%）で記載されています。そのまま7.0を返してください。
「全店」フィールドには「全店 All Stores」行の値を返してください。「既存店」行の値ではありません。
```

**改善ポイント**: 列ヘッダーの完全リスト、累計列の警告、行構造の明示。

### 追加修正

- `yoy_offset=100`: BC値=100+増減率のため
- `overwrite_past_months=true`: 速報値の確報差対策

## 共通の失敗パターンと教訓

### パターン1: 類似テーブルの取り違え（212A）

| 要素 | 詳細 |
|------|------|
| **症状** | 同一ページに「全店」「既存店」等の類似テーブルが並び、Geminiが間違った方を読む |
| **根本原因** | テーブルヘッダーの視覚的差異が小さく、Geminiが区別できない |
| **効かなかったプロンプト** | 「当期/前期を区別せよ」→ 問題の軸（全店/既存店）とズレていた |
| **効いたプロンプト** | テーブル番号＋具体的な数値レンジ（「23万人台が全店」「15万人台が既存店」） |
| **教訓** | **抽象的な指示ではなく、数値の大きさやテーブルの物理的位置（N番目）で指定する** |

### パターン2: 上下段テーブルの列位置ミス（2670）

| 要素 | 詳細 |
|------|------|
| **症状** | 1つのテーブル内に上段（上期）と下段（下期）があり、Geminiが上段の値を返す |
| **根本原因** | テーブル内のヘッダー行切り替え（R0→R7）をGeminiが認識できない |
| **効かなかったプロンプト** | 「上期/下期の2ブロック」→ 抽象的すぎて列位置の特定に至らない |
| **効いたプロンプト** | 列ヘッダーの完全リスト（「上段: 3月,4月,...,8月」「下段: 9月,...,2月」）+ 累計列の明示的除外 |
| **教訓** | **テーブル内の列ヘッダーを全て列挙し、対象月がどの段のどの列かを具体的に指定する** |

### パターン3: yoy_offset未設定

| 要素 | 詳細 |
|------|------|
| **症状** | 抽出値（7.0）とBC値（107.0）が100差 |
| **根本原因** | PDFは増減率、BCはインデックス形式。yoy_offset=100が未設定 |
| **教訓** | **PDFの値形式とBC値形式の差を事前に確認し、yoy_offsetを適切に設定する** |

## 再発防止策

### custom_prompt作成ガイドライン

1. **抽象表現を避ける**: 「上期/下期」「当期/前期」ではなく、テーブル番号・行番号・列ヘッダーの具体的な値で指定
2. **数値レンジで区別**: 類似テーブルが並ぶ場合、「大きい方（240店）が全店」「小さい方（181店）が直営」のように数値の大きさで判別基準を与える
3. **列ヘッダーを全列挙**: 月次列と累計列（四半期/半期/通期）が混在する場合、全列ヘッダーをリストアップして累計列を明示的に除外
4. **行構造を明示**: 「既存店: 売上/客数/客単価」「全店: 売上/客数/客単価」のように行の並び順を記述
5. **値の形式を明示**: 「増減率（7.0）をそのまま返す」「インデックス形式（107.0）で返す」を明記

### 調査時の必須チェック項目

1. **pdfplumberで全テーブル構造を確認**: 何番目のテーブルか、何行何列か
2. **数字逆引き**: BC値とour値がPDFのどこにあるか特定
3. **類似テーブルの存在確認**: 全店/既存店、当期/前期、連結/単体等の並列テーブル
4. **累計列の有無**: 四半期/半期/通期の累計値列が月次値列に混在していないか
5. **値形式の確認**: 増減率/インデックス/絶対額のいずれか
