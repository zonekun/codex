## 指摘項目

### P0-1. F12 PEG スコアリングにFYガードが無い 🚨

**症状**: `batch_rerun_predict.py` の F12 PEG スコアリング（L702-716）は `next_year_op_change` を参照するが、`cur_per == "FY"` チェックが無い。3Q/2Q/1Qでも `nx_fop` が存在すれば PEG が計算されスコアに加点される。

**該当**: `scripts/earnings_model/batch_rerun_predict.py:L702-L716` / `compute_score()`

```python:L702-716
    per = row.get("per")
    nyc_12 = row.get("next_year_op_change")
    if (
        not row.get("has_stock_split")
        and per is not None and pd.notna(per) and per > 0
        and nyc_12 is not None and pd.notna(nyc_12) and nyc_12 > 0
    ):
        growth_pct = nyc_12 * 100
        peg = per / growth_pct if growth_pct > 0 else float("inf")
        if peg < 0.5:
            score += 2; reasons.append(f"PEG割安 {peg:.1f} ...")
        elif peg < 1.0:
            score += 1; reasons.append(f"PEG割安 {peg:.1f} ...")
        elif peg > 2.0:
            score -= 1; reasons.append(f"PEG割高 {peg:.1f} ...")
```

**根本原因**: F12 は F5 の翌期予想を分母に使うため FY のみで意味がある。zaraba_earnings.py（L1782-1793）は `if cur_per == "FY" and not has_stock_split:` ガードがあるが、batch_rerun_predict.py 側に移植漏れ。

**修正方針**: L702 の条件に `cur_per == "FY"` を追加

```python
# before
    per = row.get("per")
    nyc_12 = row.get("next_year_op_change")
    if (
        not row.get("has_stock_split")
        and per is not None and pd.notna(per) and per > 0
        and nyc_12 is not None and pd.notna(nyc_12) and nyc_12 > 0
    ):

# after
    cur_per = row.get("quarter", "")
    per = row.get("per")
    nyc_12 = row.get("next_year_op_change")
    if (
        cur_per == "FY"
        and not row.get("has_stock_split")
        and per is not None and pd.notna(per) and per > 0
        and nyc_12 is not None and pd.notna(nyc_12) and nyc_12 > 0
    ):
```

**注意**: `cur_per` は L654 の F5 ブロックで既に参照されているが、compute_score() 内でローカル変数として定義されているか要確認。関数引数 `row` に `quarter` キーが含まれている（L569で格納済み）。

**呼び出し側への波及**: 無し（compute_score() 内部の変更のみ）

**検証**: 
- 過去の prediction JSON（3Q銘柄で `next_year_op_change` が非NaN のケース）で batch_rerun を再実行し、F12 PEG が非FYで発火していないことを確認
- `zaraba_earnings.py` は既にガード済み（L1782）なので変更不要

**ロールバック**: commit revert で済む。過去予測への影響は、非FYで nx_fop が存在するケースが稀（J-Quants は FY 以外の NxFOP をほぼ返さない）なため実害は軽微。

### P1-1. データ構築部で非FYでも next_year_op_change を計算 ⚠️

**症状**: `batch_rerun_predict.py` L537-539 で `cur_per == "FY"` ガードがあるため、実際には非FYで計算されない。**現行コードは正しい。**

```python:L537-539
        next_year_op_change: float | None = None
        if cur_per == "FY" and pd.notna(nx_fop) and pd.notna(op) and op != 0:
            next_year_op_change = float((nx_fop - op) / abs(op))
```

**結論**: データ構築部のガードは正しく実装されている。L583 の `next_year_disclosed` も `bool(cur_per == "FY" and pd.notna(nx_fop))` で FY 限定。問題なし。

### P1-2. F5 スコアリング部の `nyc` 参照にFYガード不足 ⚠️

**症状**: `batch_rerun_predict.py` L654-659:

```python:L654-659
    nyc = row.get("next_year_op_change")
    if nyc is not None and pd.notna(nyc):
        if nyc > 0.10:
            score += 2; reasons.append(f"来期OP増益 {nyc:+.1%}")
        elif nyc < -0.10:
            score -= 2; reasons.append(f"来期OP減益 {nyc:+.1%}")
    elif cur_per == "FY" and row.get("next_year_disclosed") is False:
```

**分析**: `nyc`（= `next_year_op_change`）は P1-1 で確認した通り FY 以外では None が保証される（データ構築部で FY ガード済み）。よって `if nyc is not None` は非FYでは False になり、スコアリングは発火しない。

**ただし防御的にFYガードを追加すべき**: データ構築部のガードに依存する暗黙の前提は脆い。将来 ML 特徴量として非FYでも計算するよう変更した場合、ここが壊れる。

**修正方針**:
```python
# after（防御的ガード追加）
    nyc = row.get("next_year_op_change")
    if cur_per == "FY" and nyc is not None and pd.notna(nyc):
        if nyc > 0.10:
            score += 2; reasons.append(f"来期OP増益 {nyc:+.1%}")
        elif nyc < -0.10:
            score -= 2; reasons.append(f"来期OP減益 {nyc:+.1%}")
    elif cur_per == "FY" and row.get("next_year_disclosed") is False:
```

**呼び出し側への波及**: 無し
