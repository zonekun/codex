# 改修プランテンプレートにライフサイクル後半（実装記録・ステータス）を追加

**作成日時**: 2026-05-12 17:50 JST
**ステータス**: 完了
**対象ファイル**: `docs/plans/_template_refactor.md`（120行）、`skills/planning.md`（L169-274 改修プランフォーマット節）
**対象読者**: md-reviewer サブエージェント / 次セッション担当
**目的**: 改修プランテンプレートにステータスフィールドと実装記録セクションを追加し、プランMDのライフサイクル後半（実装→検証→完了）を構造化する。汎用テンプレート（`skills/planning.md` L286-328）にはステータスと振り返りが存在するが、改修プランテンプレートには未移植であり、プランMD更新義務（CLAUDE.md §4.3）がAIの行動に変換されない構造的欠陥を解消する。スコープ外: 既存プランMDの棚卸し・archive移動（別タスク）。

**起因レビュー**: `docs/reviews/150_mr_plan_lifecycle_tracking_gap.md`（パターン4事故レビュー）

## 前提サマリ

- 汎用テンプレート（`skills/planning.md` L286-328）: `**ステータス**` (L289) と `## 振り返り` (L323-327) が存在

## 指摘項目

### P0-1. `_template_refactor.md` 冒頭にステータスフィールド追加 🚨

**症状**: 改修プラン作成後、実装が完了してもプランMDのステータスが不明。後続セッションのAIが未実装プランと誤認し二重実装を試みるリスク。

**該当**: `docs/plans/_template_refactor.md:L3-L6` / 冒頭メタ情報

```markdown:L3-L6
**作成日時**: YYYY-MM-DD HH:MM JST
**対象ファイル**: `scripts/foo/bar.py`（N 行、commit <hash> 時点）
**対象読者**: code-reviewer サブエージェント / 次セッション担当
**目的**: <1-2文で改修の主旨。スコープと非スコープを明示すると尚良い>
```

**根本原因**: 汎用テンプレートのステータスフィールドが改修テンプレートに未移植。

**修正方針**:

```markdown
# before (L3-L6)
**作成日時**: YYYY-MM-DD HH:MM JST
**対象ファイル**: `scripts/foo/bar.py`（N 行、commit <hash> 時点）
**対象読者**: code-reviewer サブエージェント / 次セッション担当
**目的**: <1-2文で改修の主旨。スコープと非スコープを明示すると尚良い>

# after
**作成日時**: YYYY-MM-DD HH:MM JST
**ステータス**: 未着手 / 進行中 / 完了 / 中止
**対象ファイル**: `scripts/foo/bar.py`（N 行、commit <hash> 時点）
**対象読者**: code-reviewer サブエージェント / 次セッション担当
**目的**: <1-2文で改修の主旨。スコープと非スコープを明示すると尚良い>
```

**呼び出し側への波及**:
- `skills/planning.md:L180-L184` — 冒頭メタ情報の例示にステータス行を追加
- 既存プランMDへの影響: なし（テンプレートの変更であり、既存ファイルは変更しない）

**検証**: テンプレートをコピーして新規プランMDを作成し、ステータスフィールドが含まれることを目視確認

**ロールバック**: git revert で即時戻し。テンプレート変更のみでデータ影響なし

### P0-2. `_template_refactor.md` 末尾に実装記録セクションと実装後チェック追加 🚨

**症状**: 実装後の記録先がテンプレートに存在しないため、検証結果・code-reviewer推奨の採否・実装commitが追跡不能。

**該当**: `docs/plans/_template_refactor.md:L108-L120` / 提出前セルフチェック以降（末尾）

**根本原因**: テンプレートが「計画→提出→レビュー」までのライフサイクルしかカバーしていない。

**修正方針**: 「提出前セルフチェック」の後に以下2セクションを追加する。

```markdown
# after（L120の後に追加）

---

## 実装記録（実装後に記入）

**実装 commit**: `<hash>` — YYYY-MM-DD HH:MM JST
**検証結果**:
- smoke test: <PASS/FAIL — 実行コマンドと結果の1行要約>
- dev 実機: <PASS/FAIL — 結果の1行要約>
- 本番適用: <適用済み / 未適用>

**code-reviewer 推奨の採否**:
| # | 推奨内容 | 採否 | 理由 |
|---|---------|------|------|
| 1 | <推奨の要約> | 採用 / 不採用 / 次回対応 | <理由> |

---

## 実装後チェック（実装完了時に記入）

- [ ] 冒頭のステータスを「完了」に更新したか
- [ ] 実装 commit hash を記録したか
- [ ] 検証結果（smoke / dev）を記録したか
- [ ] code-reviewer 推奨の採否を記録したか
- [ ] 関連知見MD（冒頭「関連ドキュメント」記載のMD）にこのプランの変更を反映したか
- [ ] 完了プランを `docs/plans/archive/YYYYMM/` に移動したか
```

**呼び出し側への波及**:
- 無し。テンプレート末尾への追加のみ

**検証**: テンプレートをコピーして新規プランMDを作成し、実装記録セクションと実装後チェックが含まれることを目視確認

**ロールバック**: git revert で即時戻し

### P0-3. `skills/planning.md` 改修プランフォーマット節に「8. 実装記録」を追加 🚨

**症状**: フォーマット仕様にライフサイクル後半の記述がないため、AIが改修プランフォーマットを「プランMDの全仕様」として読むと、実装後更新を義務と認識しない。

**該当**: `skills/planning.md:L169-L274` / 改修プランフォーマット節（セクション1-7のみ定義）

**根本原因**: フォーマット仕様が作成フェーズのみを定義し、実装フェーズの更新義務を含まない。

**修正方針**: `### 7. 関連ドキュメント（必須）` 節の最終行（L260）と `### 書く時のポイント` 見出し（L262）の間に「8. 実装記録（実装後に記入）」を追加。

```markdown
# after（「### 7. 関連ドキュメント（必須）」と「### 書く時のポイント」の間に挿入）

### 8. 実装記録（実装後に記入）

実装完了時に以下を記入する。CLAUDE.md §4.3「プランMD更新」義務の具体的実現。

- **ステータス更新**: 冒頭メタ情報の `**ステータス**` を `完了` または `中止` に変更
- **実装 commit**: hash と日時
- **検証結果**: smoke test / dev 実機 / 本番適用の各結果
- **code-reviewer 推奨の採否**: 推奨ごとに 採用 / 不採用 / 次回対応 + 理由
- **実装後チェック**: テンプレート末尾のチェックリストを全消化
- **archive 移動**: 完了プランは `docs/plans/archive/YYYYMM/` に移動（`skills/planning.md` §完了後の配置ルール）
```

**呼び出し側への波及**:
- `CLAUDE.md:§9` — 「完了マーキング」の対象が具体化される（改修プランでもチェックボックスが生まれる）。CLAUDE.md自体の修正は不要
- `skills/planning.md:L351-356`「計画の更新」節 — 汎用テンプレート向けのステータス遷移記述。改修プランの完了手順はセクション8に従う旨のクロスリファレンス追加

**検証**: `skills/planning.md` の改修プランフォーマット節を読み直し、セクション1-8の流れが自然であることを確認

**ロールバック**: git revert で即時戻し
