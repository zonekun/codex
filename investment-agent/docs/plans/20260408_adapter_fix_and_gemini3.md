## Phase 1: adapter修正54社（04/08実施）

### 実施内容
- NG96社調査（Gemini画像分析）で「adapter修正可能」と判定された54社のadapterを修正
- git版adapterを基準に修正を適用（← **ミスの原因**、後述）
- GCSにアップロード後、regex method 33社のみ6b Cloud Run再実行

### 修正項目
| 修正種別 | 対象 | 内容 |
|---------|------|------|
| unit_scale | 3690, 6238, 8739 | 千円→百万円、万→実数、億円→百万円 |
| regex | 138A, 2705, 3191, 8142等 | row_label_regex改善 |
| overwrite_past_months | 2750, 3608, 9223, 9941 | 最新PDFから全月上書き |
| manual_override | 54社全て | 自動rebuild防止フラグ |

### 結果: 65.3% → 67.3%（+2.0pt）

### 教訓（重要）
1. **yoy_offset=100は追加不要**: `_extract_pdf_by_column`が既にインデックス形式（94.0 = 前年比-6%）で抽出。yoy_offset追加は二重加算で17.6%まで悪化した
2. **Gemini method銘柄は6b再実行不要**: adapter変更（yoy_offset/unit_scale/regex）はcompare_monthly_buffett.pyのみで使用。extract_monthly_data.pyの抽出結果には影響しない
3. **git版adapterでローカル修正を上書きすると悪化**: 7422(-14OK), 3073(-10OK)等。GCSバージョニング未設定のため復旧不可 → 6a再生成が必要

## Phase 2: Gemini 3 Flash化29社（04/08〜09実施）

### 背景
- NG96調査で「コード修正必要」と判定された29社（2分割テーブル15社/前期テーブル誤取得13社/列ズレ3社）
- `_extract_pdf_by_column`のテーブル解析ロジック改修は工数大
- → Gemini 3 Flash（個人API）に切り替えて解決

### 対象29社
```
2654,2670,2674,3038,3077,3160,3174,3181,3195,3329,3549,3566,
4666,4776,5888,6627,7059,7445,7564,7606,7643,8166,8255,8798,
9039,9252,9616,9941,9990
```

うち18社はregex→geminiに変更、11社は既にgemini（再抽出のみ）。

### 実施手順
1. adapter の `extraction_method` を `"gemini"` に変更 → GCSアップロード
2. ローカルテストスクリプト（`C:\tmp\test_gemini3_29.py`）で実行
   - google-genai + 個人APIキー（GEMINI_API_KEY）
   - モデル: `gemini-3-flash-preview`
   - `response_schema` でOBJECT型を明示（list返却防止）
   - プロンプト構造化: タスク/文書情報/フィールド/ルールを分離
3. 29社×平均10文書 = 約290 Gemini APIコール、約50分で完了
4. 結果をGCS monthly_records.json にマージ保存

### プロンプト設計のポイント
```
# ルール
1. PDFにはテーブルが複数月分含まれます。**{target_month}月の列だけ**を読んでください。
2. テーブルが上期/下期で2つに分かれている場合、対象月が含まれるテーブルから取得。
3. 「当期」テーブルと「前期（参考）」テーブルがある場合、必ず当期テーブルから取得。
4. 前年同月比は、PDFに記載されている数値をそのまま返す（例: 94.0ならそのまま94.0）。
```

### 残りNG（29社、43件）の原因分類

| 原因 | 件数 | 銘柄 | 詳細 |
|------|------|------|------|
| **unit_scale不一致**（百万円↔円） | 12 | 9252 | ストック型売上: Gemini抽出=百万円、BC=円。unit_scale=1000000が必要 |
| **前年同月比の形式差**（増減率↔指数） | 12 | 2670, 8798 | Gemini抽出=増減率(8.5%)、BC=指数(107.0)。yoy_offset=100が必要な特殊ケース |
| **値の微差**（diff≤5） | 8 | 3077, 4776, 7606, 7643 | Gemini読み取り精度の限界。PDFテキスト品質に依存 |
| **テーブル混同**（当期/前期） | 5 | 2674, 6627, 9616 | Geminiが前期参考テーブルの値を取得 |
| **件数/台数の混同** | 4 | 4666 | 駐車場件数と台数をGeminiが取り違え |
| **月ずれ** | 2 | 3195 | Geminiが隣の月の値を取得 |
