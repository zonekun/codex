### P0-1. F1（進捗率）がFYで発火する 🚨

**症状**: F1は1Q/2Q/3Qの進捗率サプライズ因子だが、FYでも発火する。FYでは累計OP÷通期予想=100%前後になり、期待進捗率1.0との比較で surprise≈1.0 → 通常は発火しないが、effective_forecast_opがBQ priorの旧予想値の場合に乖離が出て誤発火する。6557では cumulative_op=1,219M ÷ effective_forecast_op=750M = 162% → surprise=1.62 > 1.2 で「進捗↑162%」が+1点。

**該当**: `scripts/zaraba_earnings.py:L1662-L1676` / `_score_record()`


### P0-2. コンセンサス比較の項目不一致（`_guidance_vs_consensus`） 🚨

**症状**: `_guidance_vs_consensus` が翌期会社予想の営業利益（NxFOP）をコンセンサスの経常利益（ORD_PROFIT）と比較している。異種利益の比較であり、乖離率が無意味。

**該当**: `scripts/zaraba_earnings.py:L1587-L1595` / `_guidance_vs_consensus()`

```python:L1587-L1595
def _guidance_vs_consensus(rec: dict, prior: dict) -> float | None:
    """翌期会社予想 vs 来期コンセンサス の乖離率。観察用。"""
    nx_op = _to_num(rec.get("NxFOP"))
    cons_next = prior.get("consensus_next")
    cons_next_odp = cons_next.get("ORD_PROFIT") if isinstance(cons_next, dict) else None
    if nx_op is None or not cons_next_odp or cons_next_odp == 0:
        return None
    cons_yen = cons_next_odp * 1_000_000
    return round((nx_op - cons_yen) / abs(cons_yen), 4)
```

**根本原因**: NxFOPは `NEXT_YEAR_FORECAST_OP`（営業利益予想）なのにコンセンサス側を `ORD_PROFIT`（経常利益）から取得。schema v3で `OP_PROFIT` が利用可能になった後も未更新。

**修正方針**: コンセンサス側を `OP_PROFIT`（営業利益）に統一する。

```python
# before
    cons_next_odp = cons_next.get("ORD_PROFIT") if isinstance(cons_next, dict) else None

# after
    cons_next_op = cons_next.get("OP_PROFIT") if isinstance(cons_next, dict) else None
```

変数名も `cons_next_odp` → `cons_next_op` にリネーム（以降の参照3箇所: L1592, L1594, L1595）。

**呼び出し側への波及**:
- `scripts/zaraba_earnings.py:L1932` — `_guidance_vs_consensus` の戻り値を `obs_guidance_vs_consensus` として results.csv に出力。型（float|None）は不変。値の意味が「営業利益同士の乖離」に変わるが、列名 `obs_guidance_vs_consensus` は汎用的なので変更不要。

**検証**: consensus_next に OP_PROFIT と ORD_PROFIT の両方がある銘柄で、NxFOP との乖離率が OP_PROFIT ベースで計算されることを確認。

**ロールバック**: commit revert で済む。観察用フィールドのためスコアに影響なし。

**症状**: F4c（コンセンサス乖離）が経常利益ベースだが、他の因子（F1/F2/F4/F5等）は営業利益ベース。旧仕様（コンセに経常利益しかなかった）の名残。

**該当**: `scripts/zaraba_earnings.py:L1814-L1846` / `_score_record()` 内 F4c ブロック

```python:L1814-L1819
    # ── F4c: コンセンサス乖離（経常利益 vs コンセンサス）────
```

**根本原因**: 一律 ORD_PROFIT を使っていたが、コンセンサスのデータソースによって利用可能な項目が異なる:

**修正方針**: 通期（FY）は営業利益同士、四半期（1Q/2Q/3Q）は経常利益同士で比較する。

```python
    cons_profit = cons_q_data.get("ORD_PROFIT") if isinstance(cons_q_data, dict) else None
    actual_odp = _to_num(rec.get("OrdinaryProfit"))  # 経常利益（円）
    if actual_odp is not None and cons_profit and cons_profit != 0:
        cons_yen = cons_profit * 1_000_000  # 百万円 → 円
        cd = (actual_odp - cons_yen) / abs(cons_yen)

# after
    # ── F4c: コンセンサス乖離 ────
    # 通期: 営業利益同士（QUICK に OP_PROFIT あり）
    # 四半期: 経常利益同士（IFIS に ORD_PROFIT のみ）
    cons_by_q = p.get("consensus_by_q")
    cons_q_data = cons_by_q.get(cur_per) if isinstance(cons_by_q, dict) else None
    if cur_per == "FY":
        cons_val = cons_q_data.get("OP_PROFIT") if isinstance(cons_q_data, dict) else None
        actual_val = cumulative_op  # 営業利益（累計 = 通期実績）

    if actual_val is not None and cons_val and cons_val != 0:
        cons_yen = cons_val * 1_000_000  # 百万円 → 円
        cd = (actual_val - cons_yen) / abs(cons_yen)
```

**注意（CR-126 F-2）**: `cumulative_op` と `OrdinaryProfit` はどちらも XBRL 累計優先ロジック（`zaraba_tdnet_poller.py:L488-493` で `YearDuration`/`AccumulatedQ` を `QuarterDuration` より優先）で抽出された累計値。期間スコープの変化はない。

**呼び出し側への波及**:

- 無し（スコアリング結果の型・構造は不変）

**検証**: (a) FY銘柄で OP_PROFIT ベースの乖離率が計算されることを確認 (b) 1Q/2Q/3Q銘柄で ORD_PROFIT ベースの乖離率が従来通り計算されることを確認 (c) QUICK データなし銘柄（FY で OP_PROFIT=NULL）では F4c が不発火になることを確認

### P0-4. 新因子: 通期実績 vs 通期予想の乖離（FY専用） 🚨

**症状**: P0-1 で F1 を FY 除外すると、「通期実績が会社予想を大幅に上回った/下回った」ケースがどの因子にも捕捉されなくなる。F2（ガイダンス修正）は「今日の新FOP vs 直前FOP」であり、FOP非開示（6557のケース）ではカバーできない。偶然のキャッチではなく、専用因子として正式に設計する。

**該当**: `scripts/zaraba_earnings.py` / `_score_record()` — 新規追加

**根本原因**: FY で「実績 vs 予想」の乖離を評価する因子が存在しない。

**修正方針**: F15（通期着地サプライズ）を新設する。FY限定。

```python
# after（新規追加、F1ブロック直後に配置）
    # ── F15: 通期着地サプライズ（FYのみ）─────────────────
    # 通期実績OPが通期予想OPを大幅に上回った/下回った場合に発火
    if cur_per == "FY" and cumulative_op is not None and effective_forecast_op and effective_forecast_op != 0:
        fy_surprise = (cumulative_op - effective_forecast_op) / abs(effective_forecast_op)
        if fy_surprise > 0.20:
            score += 2
            factors.append(f"通期上振れ{fy_surprise:+.0%}")
        elif fy_surprise > 0.05:
            score += 1
            factors.append(f"通期上振れ{fy_surprise:+.0%}")
        elif fy_surprise < -0.20:
            score -= 2
            factors.append(f"通期下振れ{fy_surprise:+.0%}")
```
