# Segment Structure Codex Procedure

作成日: 2026-05-24
対象: Codexによる決算資料のセグメント構成変化分析

## Purpose

この手順書は、Codexが決算資料から「セグメント構成変化」を分析する時の運用手順を定める。

分析フレームの背景は `docs/knowledges/analysis/093_earnings_deep_analysis.md` を参照する。ただし、このファイルはCodex側の運用手順を所有し、093本体から独立して扱う。

## Execution Shape

実行単位は次の4段階に固定する。

1. BQ取得: 一括
2. 個社分析: 1社=1分析単位で、指定並列度に従ってエージェント並列
3. 横断見直し: 最後にまとめて
4. Excel出力: 一括

PythonはBQ取得、対象絞り込み、候補チャンク整形、Excel整形などの機械的処理だけに使う。個社の判定、投資上の見方、意外感の抽出はCodexまたはCodexから起動したサブエージェントが読む。

## BQ取得

対象期間、時価総額、除外業種、対象資料カテゴリを先に確定する。

- 決算発表日または資料提出日で期間を絞る。
- 時価総額条件は億円単位で明示する。
- 公共セクターや規制色の強い業種を除外する場合は、除外した業種名を作業メモまたは最終報告に残す。
- BQ取得は一括で行い、対象一覧、最新版資料、候補チャンクをまとめて作る。

この段階では分析結果を作らない。

## 個社分析エージェント

個社分析は、1社を1つの独立した分析単位として扱う。

対象社数が複数ある場合は、ユーザーが指定した並列度に従って、Codexがサブエージェントへ割り当てる。並列度の指定がない場合は、作業量とコンテキスト量を見てCodexが保守的に決める。

各エージェントには、対象会社1社分の候補資料、判定基準、出力スキーマだけを渡す。複数社を同じエージェントにまとめて渡さない。これにより、会社間の数字混同と浅い要約を避ける。

Codex本体は、エージェントの結果をそのままExcel化しない。すべての個社結果を受け取った後、横断見直しでスコア境界、表現の粒度、別軸の驚きの拾い漏れを確認する。

## 個社分析項目

1社ごとに次を埋める。

- パターン
- 判定スコア
- 判定ラベル
- 数字根拠強度
- 内容
- 根拠
- 持続性
- 意外感/驚き
- 投資上の見方
- 注意点

判定スコアは、今回のテーマ本体だけで付ける。セグメント構成変化の分析では、需要先、用途先、地域、顧客、収益モデルの変化だけでスコアを上げない。

ただし、分析中にテーマ外の大きな発見を見つけた場合は、低スコアでも `意外感/驚き` に明示する。`スコア1 = 何もない` ではなく、`本テーマでは低いが別テーマでは重要` を区別して書く。

## Score Criteria

| スコア | ラベル | 目安 |
|---:|---|---|
| 1 | 変化なし | 全社業績や既存主力の延長で、事業構成の変化が数字で読めない |
| 2 | 兆しあり | 新領域、成長投資、セグメント変更などの兆しはあるが、売上または利益貢献はまだ小さい |
| 3 | 変化余地あり | 成長領域の数字は読めるが、利益中核の転換までは未確認 |
| 4 | 変化進行中 | 成長領域が売上または利益で明確に伸び、会社計画でも拡大が確認できる |
| 5 | 変化した | 利益中核の入れ替わり、または主力事業を上回る利益貢献が数字で確認できる |

数字根拠が弱い場合は無理に判定しない。セグメント別または事業別の売上、利益、構成比、前年差、計画値が十分に読めない時は `数字根拠弱い` として扱う。

## Output Columns

Excelの `分析結果` は次の順にする。

1. 銘柄コード
2. 会社名
3. 時価総額(億円)
4. 判定
5. 数字根拠
6. 内容
7. 根拠
8. 持続性
9. 意外感/驚き
10. 投資上の見方
11. 注意点

`根拠`、`持続性`、`意外感/驚き`、`投資上の見方`、`注意点` の順を優先する。

## Cross-Company Review

全社の個社分析が終わってから、最後に横断見直しを行う。

横断見直しでは次を確認する。

- 同じ数字水準の会社に同じスコアが付いているか。
- テーマ本体では低スコアだが、別軸の驚きが大きい会社を拾えているか。
- 5点、4点、3点の境界がブレていないか。
- 数字根拠が弱い会社を無理に高評価していないか。
- `意外感/驚き` が単なる言い換えではなく、投資上の発見になっているか。

横断見直しで個社スコアを修正してよい。ただし、修正理由は数字根拠またはテーマ定義に基づける。

## Excel Output

Excel出力は最後に一括で行う。

出力先の既定値:

```text
C:\Users\zonekun\Dropbox\stock\AI分析優待\セグメント構成変化CODEX.xlsx
```

Excelには分析結果を入れる。BQチャンク、資料本文、作業用パック、候補一覧は入れない。

出力後は最低限、次を確認する。

- ファイルが存在する。
- シート名が日本語で正しく表示される。
- `分析結果` の行数が対象件数と一致する。
- 日本語セルが文字化けしていない。
- スコア分布が想定と大きくズレていない。
