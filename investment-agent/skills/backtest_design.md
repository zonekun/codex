## 0. 哲学

**Goal**: 壊れにくい戦略を見つける ≠ 利益最大化

戦略にフリクションを加え、ストレステストし、生き残ったものだけを採用する。悲観的な条件下で耐えた戦略は、実運用でも機能する可能性が高い。

**時間配分**: アイデア生成に 20%、それを壊す試みに 80%。

### Seven Sins of Quantitative Investing

定量投資で陥りやすい7つの罪（Deutsche Bank）。バックテスト設計の各段階でこれらを意識する。

| Sin | 概要 | 対策（本スキルの該当セクション） |
|-----|------|------|
| サバイバーシップバイアス | 上場廃止・倒産銘柄を除外したデータで検証 | §2 |
| 先読みバイアス（Look-Ahead） | 取引時点で入手不可能な情報を使用 | §2 |
| ストーリーテリング | 後付けの説明で結果を正当化 | §1 仮説先行 |
| オーバーフィッティング | パラメータ過多、狭い最適値への依存 | §3 Walk-Forward / パラメータ感度 |
| 取引コスト軽視 | 手数料・スリッページ・インパクトの過小評価 | §4 コストモデル |
| アウトライヤー依存 | 少数の異常値が結果を支配 | §3 年度別分析 |
| 空売りの非対称性 | ショートは逆指値・貸株料・踏み上げリスクが非対称 | §4 貸株料 |

→ 詳細: `docs/references/backtest-expert/methodology.md` §7

## 1. 設計前チェック

バックテストを書く前に、以下を全て言語化する。

### 1-1. 仮説の明文化

エッジを1文で定義する。1文で言えなければテストに進まない。

**例**: 「FY決算で弱気ガイダンスを出した超大型株（MC≥1兆）は、暴落後5営業日で反発するリバーサルエッジがある」

### 1-2. ルールのゼロ裁量化

以下を完全に特定する。主観的判断の余地を残さない。

- **エントリー**: 条件、タイミング、使用する価格（始値/終値/VWAP）
- **イグジット**: ストップロス、利益確定、時間ベースイグジット
- **ポジションサイジング**: 固定金額 / ポートフォリオ比率 / ボラティリティ調整
- **フィルタ**: 時価総額、出来高、セクター、ボラティリティ条件
- **ユニバース**: 対象銘柄の定義

### 1-3. 仮説の対称性確認

投資仮説には多くの場合、対称な2方向が存在する。片方向しか検証しないまま BACKTEST_FAIL で終了しない。

| 仮説 | ショート方向 | ロング方向 |
|------|------------|-----------|
| 野菜価格急騰 → 外食株下落 | 急騰シグナル → ショート | **急落シグナル → ロング** |
| 決算サプライズ | 下振れ → ショート | 上振れ → ロング |

> **教訓**: 002 野菜価格分析で「急騰→株価下落」のみ実装し、「急落→ロング」を未検証のまま FAIL で終了した。

### 1-4. 指標スクリーニング（BT前必須ステップ）

バックテスト本体に入る**前**に、指標の予測力を事前検証する。
→ **`045_backtest_evaluation_metrics.md` §6 のスクリーニング手順を実施**

BT固有の補足:
- スクリーニングは In-Sample 期間の**前半のみ**で実施。後半は OOS 確認用に温存
- 複数指標を同時にスクリーニングする場合は Bonferroni 補正を適用
- 経済的直感のない指標は「たまたま有意」でも脆い。なぜ効くか仮説を必ず言語化してから採用

## 2. データ取得原則

### 2-1. BQクエリ最小化

→ **`045_backtest_evaluation_metrics.md` §7 のデータ取得原則に従う**

BT固有の補足:
- パラメータスイープ（保有日数・フィルタ閾値等）のループ内にBQ呼び出しを置かない
- 最大保有日数分の価格を1回で取得し、ループ内は pandas で `rn` 列切り替え
- 不変のマスタ（YF_STOCK_INFO等）は1回取得して dict/df で保持

### 2-2. 先読みバイアス（Look-Ahead Bias）回避

取引時点で入手不可能な情報を使わない。

**エントリーラグの設定**:

| データ頻度 | シグナル確認タイミング | 現実的なエントリー |
|-----------|---------------------|-----------------|
| 週次 | 週末（金曜）または翌週初 | **翌週月曜寄り付き** |
| 日次 | 当日引け後 | **翌日寄り付き**（または当日引け） |
| 月次 | 月末発表 | **翌月第1営業日** |

**CARとBTのラグ対応**:
```python
# ❌ 分析側のCAR（シグナル週当日を含む）
car = sum(r[i : i + window])

# ✅ BT側（翌週エントリーに対応）
car = sum(r[i+1 : i+1 + window])
```

**厳密なタイムスタンプ制御**: EODデータをイントラデイ判断に使わない。翌日始値を当日終値判断に使わない。

### 2-3. サバイバーシップバイアス対策

現在上場している銘柄だけでテストすると、上場廃止・倒産銘柄が除外され結果が楽観的になる。可能な限り上場廃止銘柄を含むデータセットを使う。

## 3. バックテスト構造

### 3-1. Walk-Forward Analysis

1. 訓練期間（例: Year 1-3）でパラメータ最適化
2. 検証期間（Year 4）で固定パラメータのまま検証
3. ウィンドウをロールフォワードして繰り返し
4. In-Sample と Out-of-Sample のパフォーマンスを比較

**警告サイン**:
- OOS が IS の 50% 未満
- パラメータの頻繁な再最適化が必要
- 期間ごとにパラメータが大きく変動

**訓練/テスト分割の原則**: 訓練期間のみでモデル・閾値を学習し、テスト期間は訓練済みパラメータを固定して適用する。テスト期間を含めて fit し直すのは先読みバイアス。

### 3-2. パラメータ感度テスト — Plateau を探す

パフォーマンスが安定する**パラメータ範囲（Plateau）**を探す。最適値のピークではなく。

- ストップロス: ベースラインの 50%, 75%, 100%, 125%, 150%
- 利益確定: 80%, 90%, 100%, 110%, 120%
- エントリー/イグジットタイミング: ±15-30 分
- フィルタ閾値: 複数段階で層別

**Good**: ストップロス 1.5%〜3.0% のどこでも利益が出る
**Bad**: ストップロスが正確に 2.13% のときだけ機能する

安定したパフォーマンス = 本物のエッジ。狭い最適値 = カーブフィッティングの疑い。

### 3-3. 時間的ロバスト性

- **最低 5年**（理想は 10年以上）のテスト期間
- **年度別パフォーマンス分析**: 大半の年でプラスの期待値があること。1-2年の例外的成績に依存しない
- **複数のマーケットレジームを含む**: 強気相場、弱気相場、高ボラ、低ボラ

### 3-4. レジーム分析（Regime Analysis）

日本市場向けのレジーム分類:

**ボラティリティベース**（日経VI）:
- 低ボラ: 日経VI < 20
- 通常: 日経VI 20-30
- 高ボラ: 日経VI 30-40
- 極端: 日経VI > 40

**トレンドベース**（TOPIX 6ヶ月騰落率）:
- 強い上昇: +10% 超
- 穏やかな上昇: +5%〜+10%
- 横ばい: -5%〜+5%
- 下落: -5% 未満

**金融政策環境**: 日銀の金融政策スタンス（緩和/中立/引き締め）も考慮

ロバストな戦略は大半のレジームでプラスの期待値を持ち、特定レジームで壊滅的な損失を出さない。

### 3-5. 層別分析

パラメータ探索と合わせて、属性（時価総額・セクター・ROA等）での層別を実施する。

> **教訓（014 FY弱気ガイダンスBT）**: 全銘柄では負のエッジ（WR 39%）だったが、時価総額で層別すると MC≥1兆 で Sharpe 1.23 / WR 61.9% と単調増加を発見。層別なしでは棄却していた戦略。

## 4. コストモデル（日本株個人投資家）

### 4.1 投資家前提（全BT共通）

| 項目 | 前提 |
|------|------|
| 投資家種別 | **個人投資家**（機関投資家ではない） |
| 資金規模 | 数百万〜数千万円、**マーケットインパクトを与えない小口** |
| 委託手数料 | **無料**（日本株の主要ネット証券は個人向け手数料ゼロ） |
| 市場インパクト | 実質ゼロ |

### 4.2 デフォルトコスト構造

| コスト要素 | 値 |
|------|-----|
| 委託手数料 | **0 bps** |
| 市場インパクト | **0 bps** |
| スプレッド（bid-ask の半分） | **大型=1 bp / 中型=2 bp / 中小型=3 bp** |
| スリッページ | 指値=0 / 成行=0.5〜2 bps |
| **合計片道コスト** | **1〜3 bps** |
| 空売り貸株料 | **年 2%**（デフォルト、銘柄により 1〜4%） |
| 譲渡益税 | **20.315%** |

```python
ONEWAY_COST_BPS = 2      # 片道 2 bps（中型株想定）
BORROW_RATE     = 0.02   # 空売り貸株料 年 2%
TAX_RATE        = 0.20315
```

### 4.3 実装可能性の制約

1. **銘柄数制約**: 1銘柄最小投資額 ≈ 20万円（単元株100株 × 平均株価2,000円）。500万円運用で最大 ~25銘柄
2. **執行タイミング**: 実装可能パターンは**前日引け後シグナル → 翌日寄成 or 翌日引け成行**。「寄付後にシグナルを見て数分以内に発注」は個人では機能しない
3. **税金**: 日次リバランスは毎年利益確定が発生し、税繰延べの恩恵なし

### 4.4 結果報告の3段階

Sharpe・年率リターンは必ず以下3段階で報告する:

1. **グロス**（コスト無し、比較可能性のため）
2. **コスト差引後**（取引コスト + 貸株料）
3. **税引き後**（譲渡益税 20.315% 控除後）

### 4.5 ストレステスト用コスト

通常の 1.5〜2倍のスリッページでストレステストする:

| 時価総額 | 通常スリッページ | ストレステスト |
|---------|---------------|-------------|
| 超大型（1兆円超） | 1 bp | 1.5〜2 bp |
| 大型（1000億〜1兆） | 2 bp | 3〜4 bp |
| 中型（100億〜1000億） | 3〜5 bp | 5〜10 bp |
| 小型（100億未満） | 5〜10 bp | 10〜20 bp |

悲観的な仮定で生き残った戦略は、実運用でBTより良い結果を出すことが多い。

### 4.6 旧コスト設定（機関投資家想定、参考のみ）

> ⚠️ 個人投資家前提（4.1-4.5）を優先すること。

```python
COMMISSION  = 0.001   # 片道 0.1%
SLIPPAGE    = 0.0005  # 片道 0.05%
```

## 5. 実行可能性フィルタ

### 5-1. シグナルの寿命 > 執行ラグ

個人投資家は「前日夜にシグナル計算 → 翌朝寄成注文」という執行制約を持つ。この制約下で戦略が機能するには、**シグナルが執行までの時間を生き延びている**必要がある。

| 検証 | シグナル寿命 | 執行ラグ | 寿命 > ラグ? | 税後 Sharpe | 結果 |
|---|---|---|---|---:|---|
| 011-1 overnight→daytime | ~24時間 | ~24時間 | 寿命≈ラグ | 0.19 | FAIL |
| 011-2 大型→中小型 | 数日 | 1日 | 寿命>ラグだが弱い | 0.47 | FAIL |
| 011-3 クラスタ間 | <1日 | 1日 | 寿命<ラグ | -0.23 | FAIL |
| 011-4 米国→日本 | 翌日 | 3-4時間 | 寿命>>ラグ | 0.99-1.58 | PASS |

この知見は 011 系（部分空間正則化PCAリードラグ）で導出。別のアプローチでは結論が変わる可能性があるため、全戦略に無条件適用して棄却するのは過剰。「寿命 < ラグ」のアイデアには追加の根拠を求める、という初期スクリーニング基準として運用する。

## 6. 合格基準・判定

→ **`045_backtest_evaluation_metrics.md` の5次元スコアリングで判定**

| 次元 | 配点 | 評価内容 |
|------|------|---------|
| Sample Size | 20 | トレード数（30+基礎点、100+十分、200+高信頼） |
| Expectancy | 20 | 勝率 × 平均勝ち/負け比 |
| Risk Management | 20 | MDD + Profit Factor |
| Robustness | 20 | テスト期間 + パラメータ数 |
| Execution Realism | 20 | スリッページテスト実施有無 |

**判定**: ≥70 Deploy / 40-69 Refine / <40 Abandon

**Red Flag チェック** → 045 参照（小サンプル、スリッページ未テスト、MDD>50%、パラメータ≥7個、テスト期間<5年、負の期待値、結果が良すぎる）

## 7. 結果の解釈

### BACKTEST_PASS（Deploy）の場合

```
→ デモトレード（フォワードテスト）へ移行
→ docs/knowledges/strategies/ に戦略知見を記録
→ アイデアのステータスを BACKTEST_PASS → CANDIDATE に更新
```

### BACKTEST_REFINE（Refine）の場合

```
→ 弱い次元を特定し、改善可能か検討
→ パラメータ調整・フィルタ追加で改善を試みる
→ 改善後に再評価（ただしデータスヌーピングに注意）
```

### BACKTEST_FAIL（Abandon）の場合

失敗理由を以下のパターンから特定し、記録する:

| パターン | 症状 | 教訓 |
|---------|------|------|
| パラメータ感度 | 特定パラメータ値でのみ機能 | Plateau がなければカーブフィッティング |
| レジーム依存 | 特定の年だけ好成績 | 多様な市場環境で耐えない |
| スリッページ感度 | コスト加算で利益消失 | エッジがフリクションより小さい |
| サンプル不足 | 少数トレードで高勝率 | 運と区別できない |
| 先読みバイアス | 結果が良すぎる | データ整合を監査 |
| 過最適化 | IS は好成績だが OOS で崩壊 | パラメータ削減、シンプルな戦略を優先 |

### BACKTEST_FAIL 記録テンプレート

失敗したBTは以下のフレームワークで記録する（知見MDに追記）:

```
1. 仮説: 何のエッジを捕捉しようとしたか
2. ルール: エントリー/イグジット/フィルタの完全な定義
3. 結果:
   - 基本指標（トレード数、勝率、平均勝ち/負け、MDD、年度別リターン）
   - パラメータ感度（Plateau の有無）
   - レジーム分析（どのレジームで問題が起きたか）
4. 破綻点: 具体的に何が戦略を壊したか
5. 教訓: 何の前提が間違っていたか、次回何を変えるか
```

→ 詳細: `docs/references/backtest-expert/failed_tests.md` §3
