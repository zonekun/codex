## 0. 設計前チェック: 分析結果の棚卸し

バックテストを書く前に、分析（ANALYZED_PASS）で得られた結果を整理する。

```
□ シグナルの方向は何か？（急騰 / 急落 / 両方）
□ 有意だったラグは何週か？
□ 対象銘柄は何社か？
□ 仮説は対称か？（→ 後述）
```

---

## 1. 仮説の対称性を必ず確認する【最重要】

投資仮説には多くの場合、**対称な2方向**が存在する。
分析フェーズで片方向しか検定していなくても、バックテストでは**両方向を実装・比較**すること。

| 仮説の例 | ショート方向 | ロング方向 |
|---------|------------|-----------|
| 野菜価格急騰 → 外食株下落 | 急騰シグナル → ショート | **急落シグナル → ロング** |
| 逆日歩急増 → 株価上昇 | — | 急増シグナル → ロング |
| 決算サプライズ | 下振れ → ショート | 上振れ → ロング |

> **実例（野菜価格分析）**: v3分析で「急騰→株価下落」のCARが有意だったため
> バックテストはショートのみ実装した。しかし「急落→ロング」は**未検証のまま**
> BACKTEST_FAILとして終了。ロング方向にアルファが存在した可能性を見落とした。
> → `docs/knowledges/analysis/002_yasai_price_earnings_prediction.md` 参照

**判断フロー**:
```
分析で有意だった方向を確認
    ↓
反対方向（ロング/ショート）も理論的に成立するか？
    ↓ YES
両方向をバックテストに実装する
    ↓ NO（例: 片方向のみが経済的に意味を持つ）
その理由をコメントに明記してから片方向のみ実装する
```

## 2. エントリー・イグジットのラグ設定

分析コードとバックテストの最大の乖離源。**実際にエントリーできる最速タイミング**をコードに反映する。

| データ頻度 | シグナル確認タイミング | 現実的なエントリー |
|-----------|---------------------|-----------------|
| 週次 | 週末（金曜）または翌週初 | **翌週月曜寄り付き** |
| 日次 | 当日引け後 | **翌日寄り付き**（または当日引け） |
| 月次 | 月末発表 | **翌月第1営業日** |

### CARとバックテストのラグ対応

```python
# ❌ 分析側のCAR（シグナル週当日を含む）
car = sum(r[i : i + window])        # r[i] = シグナル週のリターン

# ✅ バックテスト側（翌週エントリーに対応）
car = sum(r[i+1 : i+1 + window])    # r[i+1] から累積
```

分析のCAR結果がバックテストで再現できない場合、まずここを確認する。

## 3. 訓練・テスト分割（必須）

アウトオブサンプル検証なしのバックテストは意味をなさない。

```
推奨分割比: 前 60% 訓練 / 後 40% テスト

訓練期間でやること:
  - ARモデル学習（白色化用）
  - イベント閾値の決定（パーセンタイル）
  - 必要に応じてパラメータチューニング

テスト期間でやること:
  - 訓練済みモデル・閾値をそのまま適用
  - パラメータは一切変更しない
```

> 週次データで379週あれば、訓練227週・テスト152週程度が目安。

### ARモデルのアウトオブサンプル適用（ルックアヘッドバイアス回避）

白色化にARモデルを使う場合、**訓練期間のみでモデルを学習し、テスト期間は訓練済みパラメータを固定して適用する**。
テスト期間を含めてfitし直すのはルックアヘッドバイアスになる。

```python
from statsmodels.tsa.ar_model import AutoReg
import numpy as np

TRAIN_END = "2021-12-31"

def fit_ar_on_train(series_train, max_ar=8):
    """訓練期間でAR(p)を学習。ラグ次数はAIC最小で選択。"""
    best_aic, best_fit = np.inf, None
    for p in range(1, max_ar + 1):
        try:
            fit = AutoReg(series_train, lags=p, old_names=False).fit()
            if fit.aic < best_aic:
                best_aic, best_fit = fit.aic, fit
        except Exception:
            break
    return best_fit

def apply_ar_residual(fit, series_full):
    """訓練済みARパラメータをフル系列（訓練+テスト）に適用して残差を計算。
    fit は訓練期間のみで学習したもの。テスト期間にもそのまま適用する。"""
    lags_list = fit.model.ar_lags      # [1, 2, ..., p]
    p         = max(lags_list)
    intercept = fit.params[0]
    coefs     = fit.params[1:p + 1]
    resid = np.full(len(series_full), np.nan)
    for i in range(p, len(series_full)):
        lag_vals = np.array([series_full[i - lag] for lag in lags_list])
        fitted   = intercept + np.dot(coefs, lag_vals)
        resid[i] = series_full[i] - fitted
    return resid

# ---- 実際の使い方 ----
train_mask  = df["date"] <= TRAIN_END
series_full = df["delta_heinen"].values   # Δ平年比（全期間）
series_train = series_full[train_mask]

fit = fit_ar_on_train(series_train)       # 訓練期間のみでfit
resid_full = apply_ar_residual(fit, series_full)  # 全期間に適用

# 閾値も訓練期間の残差から決定
threshold = np.nanpercentile(resid_full[train_mask], 85)
```

**よくある誤り:**

| 誤り | 問題 |
|------|------|
| `AutoReg(series_full).fit()` で全期間を学習 | テスト期間の情報がモデルに入る（ルックアヘッド） |
| 訓練期間の `fit.resid` をそのまま使う | 訓練期間の長さしかなく、テスト期間の残差が得られない |
| `fit.model.lags` でラグ数を取得 | `AttributeError`。正しくは `fit.model.ar_lags`（リスト形式）|

## 4. コスト設定

### 4.1 投資家前提（全バックテスト共通）★最重要

**このプロジェクトの全バックテストは以下の投資家プロファイルを前提とする**。ユーザーが明示的に別条件を指定した場合のみ上書きしてよい。

| 項目 | 前提 |
|------|------|
| 投資家種別 | **個人投資家**（機関投資家ではない） |
| 資金規模 | 数百万〜数千万円、**マーケットインパクトを与えない小口** |
| 委託手数料 | **無料**（日本株の主要ネット証券は個人向け手数料ゼロ） |
| 市場インパクト | 実質ゼロ |

### 4.2 デフォルトコスト構造

| コスト要素 | 値 |
|------|-----|
| 委託手数料 | **0 bps** |
| 市場インパクト | **0 bps** |
| スプレッド（bid-ask の半分） | **大型=1 bp / 中型=2 bp / 中小型=3 bp**（流動性で切替） |
| スリッページ | 指値=0 / 成行=0.5〜2 bps |
| **合計片道コスト** | **1〜3 bps**（ユニバース次第） |
| 空売り貸株料 | **年 2%**（デフォルト、銘柄により 1〜4%） |
| 譲渡益税 | **20.315%**（日次リバランス戦略は毎年キックイン） |

```python
# 個人投資家前提のデフォルト
ONEWAY_COST_BPS = 2      # 片道 2 bps（中型株想定）
BORROW_RATE     = 0.02   # 空売り貸株料 年 2%（ショート側ウェイト × この値を差し引く）
TAX_RATE        = 0.20315
```

### 4.3 実装可能性の制約（バックテスト設計時に必ず考慮）

1. **銘柄数制約**: 数百銘柄の同時保有は最小単元株の問題で不可能
   - 1銘柄最小投資額 ≈ 20万円（単元株100株 × 平均株価2,000円）
   - 500万円運用 → 最大 ~25銘柄 / 3000万円運用 → 最大 ~150銘柄
   - **q=0.3 のような広い分散版は参考値にしかならない**。実行可能性評価では **q=0.05 相当の集中版も必ず併記**する
2. **執行タイミング**: 寄付後に複雑なシグナル計算→即手動発注は現実的でない
   - 実装可能パターン: **前日引け後シグナル → 翌日寄成 or 翌日引け成行**
   - 「寄付後にシグナルを見て数分以内に発注」前提の戦略は個人では機能しない
3. **税金**: 日次リバランスは毎年利益確定が発生し、税繰延べの恩恵なし
   - 長期保有戦略と比べて税効率が悪い点も評価に含める

### 4.4 結果報告の3段階

Sharpe・年率リターンは必ず以下 **3段階**で報告する:

```
1. グロス（コスト無し、比較可能性のため）
2. コスト差引後（取引コスト + 貸株料、実運用前のプリタックス収益）
3. 税引き後（譲渡益税 20.315% 控除後）
```

実装例:
```python
ONEWAY_COST_BPS = 2
BORROW_RATE     = 0.02
TAX_RATE        = 0.20315

gross_ann_ret  = ...
# 取引コスト = 日次入替率 × 片道コスト × 営業日数
daily_turnover = 0.6  # 例: q=0.3 のとき両サイド60%入替
cost_drag_ann  = daily_turnover * (ONEWAY_COST_BPS / 10000) * 245
borrow_drag_ann = short_weight * BORROW_RATE  # short_weight は -1 to 0 の範囲

net_ann_ret    = gross_ann_ret - cost_drag_ann - borrow_drag_ann
after_tax_ret  = net_ann_ret * (1 - TAX_RATE) if net_ann_ret > 0 else net_ann_ret
```

## 5. 合格基準（BACKTEST_PASS の目安）

| 指標 | 基準 | 備考 |
|------|------|------|
| 勝率 | ≥ 55% | ランダムの50%超 |
| 年率リターン | ≥ 5% | 手数料込み |
| シャープレシオ（年率） | ≥ 0.5 | 週次リターン × √52 |
| 最大ドローダウン | ≤ 20% | 許容ドローダウンは戦略ごとに設定 |
| トレード数 | ≥ 20件 | 統計的信頼性の最低ライン |

全項目でなくとも、**シャープ ≥ 0.5 かつ勝率 ≥ 55%** を最低条件とする。

## 6. 結果の解釈と次のステップ

### BACKTEST_PASS の場合
```
→ デモトレード（フォワードテスト）へ移行
→ docs/knowledges/strategies/ に戦略知見を記録
→ アイデアのステータスを BACKTEST_PASS → CANDIDATE に更新
```

### BACKTEST_FAIL の場合
```
失敗理由を特定して記録（以下のどれか）:
  A. 効果サイズが手数料を下回る
  B. アウトオブサンプルで消失（過学習）
  C. 特定期間のみ有効（相場環境依存）
  D. エントリーラグの問題（分析とバックテストのCAR設定ミス）
  E. 仮説の対称方向（ロング/ショート）を検証していなかった ← 今回の教訓

→ E の場合: 反対方向のバックテストを追加実施
→ それ以外: docs/knowledges/analysis/ に BACKTEST_FAIL の知見を記録して終了
```

## 8. 個人投資家で機能する戦略の構造条件

011 系 5 枝番（部分空間正則化PCAリードラグ）の検証（2026-04-11〜12）から得られたメタ知見。

### 条件: シグナルの寿命 > 執行ラグ

個人投資家は「前日夜にシグナル計算 → 翌朝寄成注文」（オプションA）という執行制約を持つ。この制約下で戦略が機能するには、**シグナルが執行までの時間を生き延びている**必要がある。

| 検証 | シグナル寿命 | 執行ラグ | 寿命 > ラグ? | 税後 Sharpe | 結果 |
|---|---|---|---|---:|---|
| 011-1 overnight→daytime | ~24時間 | ~24時間 | **寿命≈ラグ** | 0.19 | FAIL |
| 011-2 大型→中小型 | 数日 | 1日 | 寿命>ラグだが弱い | 0.47 | FAIL |
| 011-3 クラスタ間 | <1日 | 1日 | **寿命<ラグ** | -0.23 | FAIL |
| 011-4 米国→日本 | 翌日 | 3-4時間 | **寿命>>ラグ** | 0.99-1.58 | PASS |

### この知見の適用範囲

**この条件は 011 系（部分空間正則化PCAリードラグ）の検証で導出されたもの**。以下の前提に依存する:

- 手法: 低ランク線形予測器（結合相関行列の固有分解）
- 執行: オプションA（前日引け後シグナル → 翌日寄成 → 当日引け手仕舞い）
- ポジション: 日次デイトレード（オーバーナイト保有なし）
- 市場: 日本株セクターETF

**別のアプローチ（非線形モデル、異なる執行方法、異なる保有期間、異なる市場）では結論が変わる可能性がある**。例えば:
- 011-2（大→小）が非線形モデルやイベントドリブンなアプローチでは機能する可能性
- 週次ホールドではなく月次ホールドなら情報拡散の累積効果を捕捉できる可能性
- 個別銘柄レベルで銘柄選択の精度を上げれば Sharpe が改善する可能性

この知見を**全戦略に無条件適用して棄却するのは過剰**。新しいアイデアを評価するときの**初期スクリーニング基準**として使い、「寿命 < ラグ」のアイデアには追加の根拠を求める、という運用が適切。
